## 1. 진행 원칙과 흐름

- 기둥 질문은 주제를 여는 공통 질문이고, 가지 질문은 참여자의 실제 답변에 따라 골라 묻는 후속 질문입니다. 질문 전체를 순서대로 소진하지 않습니다.
- 한 칸에 후속 질문이 여러 개 있어도 한 번에 하나씩 묻고 답을 기다립니다.
- 세 기둥 모두 관련 경험이 있는지 확인하되, 직접 경험한 영역 1~2개와 최근 사례 한 건을 중심으로 깊게 듣습니다. 이미 답한 질문은 반복하지 않습니다.
- 세 영역 모두 직접 경험이 없다면 본인의 역할과 연결 지점만 확인하고 마무리합니다. 다른 담당자의 어려움을 대신 추측하도록 요구하지 않습니다.
- 제작자·판매자·운영자 역할을 미리 정하지 않습니다. 직접 한 일, 함께 한 일, 다른 사람에게 들은 이야기를 구분합니다.
- 어려움이 있다는 전제를 두지 않습니다. 잘 진행된 부분, 현재 방식으로 충분한 부분, 바꾸고 싶지 않은 방식도 기록합니다.
- 디지털 도구·온라인 판매·펀딩 경험을 전제하지 않습니다. 참여자가 실제로 사용하는 방식과 표현을 따릅니다.
- AI 사용 의향이나 특정 기능의 필요성을 먼저 묻지 않습니다. 기존 플랫폼의 여섯 체크리스트·Chat·Chip 등을 답변 틀로 제시하지 않습니다.
- 참여자가 도구를 언급하면 종류와 관계없이 실제 사용 사례·준비 과정·결과 확인 방식을 묻습니다. 연구 목적을 질문받으면 디지털·AI 지원 가능성도 검토하는 조사임을 정직하게 설명하되 기능 소개로 답변을 유도하지 않습니다.
- 구체적인 시간·횟수를 기억하지 못하면 대략의 범위나 미확인으로 남깁니다. 자료 열람은 참여자가 보여줄 수 있는 범위에서만 진행합니다.

권장 진행 시간은 약 40~50분이며 참여자의 여건에 맞춰 조정합니다.

| 순서 | 진행 내용 | 시간 가이드 |
| --- | --- | --- |
| 1 | 조사 소개·역할 파악 | 5분 |
| 2 | 최근 실제 사례와 업무 흐름 확인 | 8분 |
| 3 | 관련 기둥의 경험 탐색·가지 질문 | 20~25분 |
| 4 | 공통 심화·우선순위·마무리 | 7~12분 |

### 시작 안내 예시

> 오늘은 작품을 알리고 판매하거나 관련 업무를 처리하시는 경험을 듣고, 어떤 도움이 필요한지 알아보려 합니다. 직접 하셨던 일을 편하게 말씀해 주세요. 잘 진행된 일이나 특별히 불편하지 않은 부분도 듣고 싶습니다. 답하기 어려운 질문은 건너뛰실 수 있습니다.

진행자는 메모 목적을 설명하고, 녹음이 필요하면 시작 전에 동의를 받습니다. 자료를 볼 때는 고객 이름·연락처 등 공개하기 어려운 내용을 가리고 확인할 수 있도록 합니다. 자료 복사나 촬영은 별도로 동의한 범위에서만 합니다.

## 2. 공통 도입 질문 — 역할과 업무 분담

아래는 모든 참여자에게 묻는 도입 질문입니다. 이미 설명한 내용은 확인만 하고 넘어갑니다.

| ID | 질문 | 확인할 내용 |
| --- | --- | --- |
| I-01 | 명인님과 함께 어떤 일을 하고 계신지 소개해 주시겠어요? | 참여자가 스스로 설명하는 역할과 활동 맥락 |
| I-02 | 그중 본인이 직접 맡는 일은 무엇인가요? | 직접 경험할 수 있는 업무 범위 |
| I-03 | 그 일을 하실 때 다른 분들과는 어떻게 역할을 나누시나요? | 함께 일하는 사람, 업무 전달과 결정 관계 |

**역할을 더 확인할 필요가 있을 때의 가지 질문**

- 어떤 일이 생기면 보통 본인에게 오나요?
- 그 일에서 본인이 결정할 수 있는 부분은 어디까지인가요?
- 다른 분의 확인이나 도움이 필요한 부분은 무엇인가요?
- 지금 말씀하신 일은 직접 겪으신 일인가요, 다른 분에게 들으신 이야기인가요?

## 3. 공통 사례 질문 — 최근 한 건의 흐름

| ID | 질문 | 진행 메모 |
| --- | --- | --- |
| C-01 | 최근 작품을 알리거나 판매하는 일, 또는 그와 관련된 업무에 직접 참여하신 사례를 하나 말씀해 주시겠어요? | 참여자가 먼저 사례를 선택. 관련 사례가 없다면 최근 직접 맡은 일을 듣고 세 기둥과의 관련 여부 확인 |
| C-02 | 그 일은 어떻게 시작됐고, 어떤 순서로 진행됐나요? | 처음부터 마무리 또는 현재 진행 지점까지 시간 순서로 듣기 |
| C-03 | 그 과정에서 예상대로 진행된 부분은 무엇이었나요? 예상과 달랐던 부분도 있었나요? | 잘된 부분과 막힌 부분을 모두 확인. 특별한 문제가 없다는 답도 그대로 기록 |

**사례를 구체화하는 가지 질문**

- 그때 어떤 작품이나 일이었나요?
- 언제쯤 있었던 일인가요?
- 그 단계에서는 누가 무엇을 했나요?
- 그다음에는 어떻게 되었나요?
- 그때 실제로 주고받은 내용이나 사용한 자료를, 보여주실 수 있는 범위에서 함께 볼 수 있을까요?

같은 사례가 아래 기둥에 해당하면 그대로 이어갑니다. 새로운 사례를 매번 요구하지 않습니다.

가격 결정에 제작 관련 조건이 영향을 주었다면 그 조건의 의미와 확인 경로를 듣습니다. 세부 제작 공정이나 정확한 원가 계산을 설명하도록 요구하지 않습니다. 거래가 이어지지 않은 이유에 대한 참여자의 추정은 실제로 확인한 사실과 나눠 기록합니다.

| H-02 | 그 사례에서는 누구에게 어떤 방법으로 작품을 알리셨나요? | 선택한 사례를 이어가기. 참여자가 말한 대면·문서·온라인 등 실제 방식을 기준으로 질문 |

| H-B01 | 소개 글·사진·안내 자료 등을 준비함 | 어떤 자료를 준비하셨나요? 처음 준비해서 사용하기까지 어떤 과정을 거쳤나요? |
| H-B02 | 알릴 대상이나 전달 방법을 정함 | 그 대상이나 방법은 어떻게 정하셨나요? 결정할 때 무엇을 참고하셨나요? |
| H-B03 | 다른 사람에게 제작·수정을 부탁함 | 무엇을 전달해서 부탁하셨나요? 결과를 받은 뒤 어떤 확인이나 수정이 있었나요? |
| H-B04 | 알린 뒤 반응을 살펴봄 | 실제로 어떤 반응을 확인하셨나요? 확인하기 어려웠던 부분도 있었나요? |
| H-B05 | 같은 작품을 다시 알리거나 자료를 재사용함 | 다음번에는 기존 자료를 어떻게 사용하셨나요? 다시 준비한 내용은 무엇이었나요? |

“홍보가 어렵다”는 답변이 나오면 어느 단계의 어떤 일이었는지 먼저 확인합니다. 소개 자료 준비, 전달 방법 선택, 실제 반응 확인 중 특정 문제가 있다고 미리 정하거나, 글 작성 기능으로 곧바로 해결책을 좁히지 않습니다. 홍보 효과를 수치로 측정했을 것이라고 가정하지 않습니다.

## 6. 기둥 3 — 운영 과정

### 기둥 질문

| ID | 질문 | 진행 조건 |
| --- | --- | --- |
| O-01 | 최근 작품·문의·판매와 관련된 일을 처리하면서 필요한 정보는 어디서 확인하셨나요? | 실제 정보 확인 방식을 먼저 듣기. 기록이나 사용하는 시스템이 있을 것이라고 전제하지 않음 |

### 답변에 따른 가지 질문

| ID | 답변에서 나온 상황 | 가지 질문 |
| --- | --- | --- |
| O-B01 | 기록이나 목록을 남김 | 어떤 내용을 어디에 남기셨나요? 나중에 그 내용을 어떻게 확인하셨나요? |
| O-B02 | 정보를 다시 찾거나 옮겨 적음 | 최근에는 어떤 정보를 찾거나 옮기셨나요? 그때 어떤 순서로 처리하셨나요? |
| O-B03 | 일정·수량·주문 조건 등이 바뀜 | 바뀐 내용을 누가 어떻게 확인하고 전달했나요? 관련된 분들은 어떻게 알게 되었나요? |
| O-B04 | 누락·혼선·재작업을 경험함 | 그 일이 언제 어떻게 드러났나요? 알게 된 뒤에는 어떻게 처리하셨나요? |
| O-B05 | 현재 방식으로 잘 처리하고 있음 | 어떤 점이 본인 업무에 잘 맞나요? 그 방식이 도움이 된 최근 사례를 말씀해 주실 수 있나요? |

제작 일정이나 주문 가능 조건을 확인해야 한다면 업무 전달에 필요한 수준으로 듣습니다. 인터뷰 중 새로운 관리 시스템을 제안하거나 현재 방식을 비효율적이라고 평가하지 않습니다.

## 7. 공통 심화 가지 — 문제의 크기와 필요한 도움

세 기둥에서 구체적인 일이 나온 뒤, 아직 확인하지 못한 항목만 골라 묻습니다. 문제가 있었다는 답변이 없으면 억지로 고충을 만들지 않습니다.

| ID | 확인할 주제 | 가지 질문 |
| --- | --- | --- |
| D-01 | 반복성 | 비슷한 일이 최근에 또 있었나요? 있었다면 언제였나요? |
| D-02 | 수고·영향 | 그 일에 어느 정도 시간이 들었는지 기억나시나요? 다른 일이나 일정에는 어떤 영향이 있었나요? |
| D-03 | 현재 해결 방식 | 그때는 어떻게 처리하셨나요? 그 방법을 쓰게 된 이유는 무엇인가요? |
| D-04 | 남은 문제 | 처리한 뒤에도 남아 있던 일이 있었나요? 있었다면 무엇이었나요? |
| D-05 | 필요한 자료 | 그 일을 하려면 어떤 정보나 자료가 필요했나요? 누가 가지고 있었나요? |
| D-06 | 완료·품질 판단 | 어떤 상태가 되어야 그 일을 마쳤다고 보시나요? 결과가 맞는지는 어떻게 확인하시나요? |
| D-07 | 도움과 최종 판단의 경계 | 최근 다른 사람에게 도움을 받은 일이 있다면 어디까지 맡기셨나요? 본인이 직접 확인하거나 결정한 부분은 무엇이었나요? |

시간·횟수·영향은 실제 기억이나 근거가 있는 범위로 기록합니다. 정확한 수치가 없으면 대략의 범위·참여자 추정·미확인 중 무엇인지 구분합니다. D-07에서 도움을 받은 경험이 없다면 가상의 AI 사용 상황을 만들어 답하도록 요구하지 않습니다.

### 도구 사용을 자발적으로 언급했을 때

참여자가 AI를 포함한 도구나 외부 서비스를 먼저 언급한 경우에도 아래 실제 행동 중심 질문을 사용합니다.

- 최근 그 도구로 처리한 일을 하나 말씀해 주시겠어요?
- 사용하기 전에 어떤 준비를 하셨나요?
- 결과를 받은 뒤에는 무엇을 하셨나요?
- 결과를 어떻게 확인하거나 수정하셨나요?

이 답변만으로 앞으로도 사용할 의향이나 AI 기능 수요가 확인됐다고 기록하지 않습니다.

## 8. 마무리 질문

| ID | 질문 | 목적 |
| --- | --- | --- |
| W-01 | 오늘 이야기한 일 중 지금 가장 먼저 바꾸거나 부담을 줄이고 싶은 부분이 있나요? 있다면 무엇이고, 왜 그런가요? | 현재 우선순위 확인. 바꾸고 싶은 부분이 없다는 답도 허용 |
| W-02 | 제가 이해한 내용을 짧게 말씀드려도 될까요? [참여자의 표현으로 요약한 뒤] 다르게 이해했거나 빠뜨린 부분이 있나요? | 조사자의 해석을 확인하고 정정 받기 |
| W-03 | 아직 이야기하지 못했지만 이 일을 이해하려면 알아야 할 내용이 있을까요? | 기둥 밖에서 드러나는 관련 맥락 확인 |

조사 이후에는 여러 경험을 함께 검토해 지원할 문제를 좁힐 예정이라고 설명하고 마칩니다. 특정 기능의 제공이나 출시를 약속하지 않습니다.

## 9. 진행자가 주의할 유도 표현

| 피할 표현 | 대신 확인할 질문 |
| --- | --- |
| “AI가 홍보 글을 써주면 사용하시겠어요?” | “최근 소개 자료를 준비하실 때 어떤 과정을 거치셨나요?” |
| “판매보다 홍보가 더 어렵죠?” | “그 사례에서 예상과 달랐던 부분이 있었나요?” |
| “그 작업은 자동화하면 편해지겠네요?” | “그때는 어떻게 처리하셨고, 어떤 일이 남았나요?” |
| “ChatGPT를 검색에만 쓰시나요?” | 참여자가 도구를 언급했다면 “최근 어떤 일에 어떻게 사용하셨나요?” |

“많이 번거롭죠?”처럼 어려움의 강도를 암시하지 않습니다. 관찰한 행동과 참여자의 표현을 먼저 듣고, 해결책 제안은 인터뷰 이후 팀의 검토로 남깁니다.

## 10. 기록과 인터뷰 후 검토

### 사례별 최소 기록

| 기록 요소 | 기록 기준 |
| --- | --- |
| 참여자의 실제 역할 | 본인이 설명한 역할·담당 범위·함께 일하는 관계 |
| 구체적인 사건 | 어떤 일인지, 언제 있었는지, 시작·진행·결과 또는 현재 지점 |
| 자료와 실제 행동 | 어떤 자료를 누가 받아 무엇을 처리하고 어디로 전달했는지 |
| 어려움과 영향 | 참여자가 말한 막힘·수고·손실과 근거. 문제 없거나 잘된 사례도 보존 |
| 현재 해결 방식 | 실제 사용하는 사람·도구·기록 방식, 도움이 된 점과 남은 일 |
| 반복성과 우선순위 | 실제 반복 사례·대략의 빈도·본인이 우선 바꾸고 싶은 부분 |
| 필요한 결과와 판단 | 어떤 결과가 있어야 일을 마치는지, 누가 확인·결정하는지 |
| 근거의 성격 | 직접 경험·간접 전달·관찰·조사자 해석·미확인을 구분 |

말한 내용은 가능한 한 참여자의 표현으로 남기고, 관찰한 사실과 조사자의 해석을 나눕니다. 관련 경험이 없어 건너뛴 기둥을 “문제 없음”으로 처리하지 않습니다.

### 인터뷰 후 팀이 검토할 사항

아래는 참여자에게 읽어 주는 질문이 아니라 조사 이후 팀이 작성할 검토 항목입니다.

- 구체적인 어려움과 현재 해결 방식이 실제 사례로 확인됐는가?
- 그 일을 지원하는 데 필요한 입력 자료를 확보할 수 있는가?
- 제공할 결과물과 실제 사용처를 설명할 수 있는가?
- 사용자가 결과의 적절성을 확인·수정할 수 있는가? 실수의 영향과 사람이 맡을 판단은 무엇인가?
- 기존 방식과 비교해 어떤 수고를 줄일 수 있는가?
- 기본적인 기록·업무 전달 개선, 일반 자동화, AI 보조 중 검토할 접근은 무엇인가? 아직 판단할 수 없는 부분은 무엇인가?

이 단계에서는 지원 가설과 확인할 근거를 정리합니다. 기능 도입이나 기존 사용자 기능명세 변경은 별도 검토 사항이며, 인터뷰 몇 건의 의견을 전체 장년층의 수요로 일반화하지 않습니다.

### 작성 방식 참고

주제별 시작 질문과 후속 질문을 구분하고, 실제 경험을 중립적으로 탐색하며, 답변에 따라 질문 순서를 조정하는 진행 원칙은 [GOV.UK — Using in-depth interviews](https://www.gov.uk/service-manual/user-research/using-in-depth-interviews)를 참고했습니다. 위 질문과 분기는 이번 대상·조사 목적에 맞춘 초안입니다.
