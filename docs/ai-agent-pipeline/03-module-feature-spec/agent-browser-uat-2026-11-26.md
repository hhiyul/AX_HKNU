- 새 `docker-compose.uat.yml`, Compose 프로젝트 `ax-agent-uat`: 로컬 빌드한 React + nginx, `backend/main.py`, MongoDB 8. 프런트 `127.0.0.1:15173`, API `127.0.0.1:18091`에만 바인딩했다.

- 합성 계정 `browser-uat-20261126@example.com`, 프로젝트 `AG-P5 브라우저 검증 — 도자 머그`. 프로젝트 ID `6b07c1e4b7cd9686e73f19cb`.

## 남은 이슈와 미검증 범위

### Q-01 — 긴 답변의 품질·완결성 OPEN

실제 답변 `6b07d110db36e00f37b70dd3`에 구분자 `</|DELIM_Zenith|>`와 사용자에게 불필요한 영어 자기수정 문구가 노출되었으며 목록 연결도 어색했다. 60개 요청을 임의로 20개로 줄이겠다고 말한 뒤 나머지를 이어 출력했다. 원문은 runtime 증거에 보존했다.

별도의 500개 목록 요청에서 모델은 30개만 제공하겠다고 답했다. 23번까지 나온 시점에 중지하고 이어 생성을 눌렀을 때 24~30번으로 끝났다. 따라서 **부분 답변 보존·새 run 연결 성공**과 **원래 500개 요청의 완수**를 구분한다. 후자는 PASS가 아니다.

모델 출력·provider 응답·파서 중 어디에서 불필요한 문구가 섞였는지는 응답 원본 추적을 통한 추가 원인 분리가 필요하다. 문자열을 임의 삭제하는 후처리로 성공처럼 보이게 바꾸지 않았다. 다음 품질 검증에서는 긴 요청을 줄일 때의 명시적 안내, 사용자에게 노출할 출력만 전달되는지, continuation이 원래 작업의 남은 범위를 유지하는지 확인해야 한다.

### 이번에 실제 화면으로 닫지 않은 항목

- 여러 탭 동시 등록·revision 충돌, 응답 유실을 의도적으로 주입한 뒤 UI 복구, 날짜 미정 후보 취소, 항목 전환 중 늦게 도착한 응답. 관련 자동 테스트 통과와 화면 인수는 구분한다.
- 브랜드 공통 거래처·다른 계정 접근의 실제 다중 사용자 UI, 모바일 반응형·다른 브라우저·전체 접근성 평가.
- 대량 자료 페이지 탐색, PDF 입력의 AI 읽기, 실제 사진의 정밀 인식, 상대 날짜 해석 전반. 현재 지원 범위를 넘는 기능을 추가하지 않았다.
- 운영 환경 배포·이행·백업/복구·청구서 대조, 실제 사용자의 최종 인수.
- 기존 정책 `AG-OPEN-01`(기존 일정 변경 권한), `AG-OPEN-02`(반복 운영), `DOC-POL-01`(최종 완료 조건)은 그대로 OPEN. 원가 미입력은 대화·작성·저장·검토 전 다운로드를 막지 않았다.
