**2026-11-26 후속 보완:** [에이전트 기능 보완 명세](agent-capability-contracts-2026-11-26.md)는 최신 Figma와 현재 앱 소스를 대조해 자료·일정 조회, 일반 대화의 할 일 제안/확인 등록, 항목 맥락·파일·검토·이어서 생성의 미연결 경로를 구체화한다. 현재 일정 읽기와 사용자용 일정 API는 일부 존재한다. 이 문서의 D/J 목록을 모든 에이전트 기능·권한의 닫힘 판정으로 해석하지 않는다. GD-046~070과 첫 출시 범위는 유지한다.

## 1. 근거와 적용 우선순위

사용자 명시 결정 GD-046~070 → 이를 통합한 v0.3-R2의 적용 범위 → 최신 Figma의 확정 사항과 대체되지 않은 기존 계약 순으로 해석한다. Figma의 ‘설계’는 화면 기준, ‘제안’은 합의/구체화가 필요한 사항이다. 제안 전체를 제품 확정으로 승격하지 않는다. 사용자 동작이 달라지는 실제 충돌은 기록하고, 내부 필드 미정만으로 닫힌 Grill을 다시 열지 않는다.

참고 범위 0개는 ‘대화 이력도 0개’가 아니다. 사용자의 현재 요청·독립적인 말투/조건은 유지하며 제외 자료에서만 온 가격 등은 빼야 한다. 과거 메시지/요약에서 출처를 분리·검증할 수 없는 부분은 제외한다. 화면의 과거 답변은 보존하되 다음 모델 입력으로의 재사용 가능성과 구별한다.

선택 자료는 같은 항목의 후속 요청에 유지하고 다른 항목으로 자동 전파하지 않는다. 항목 재방문 복원 기간·후속 제외 변경 동기화·명시 제외 해제 UI는 D-01의 상세 설계다. 자체 시작 문서에 무관한 대화의 제외를 끼워 넣지 않는다. 선택한 외부 자료도 현재 권한·수명·제외에 어긋나면 읽지 않는다. 선택 후보에 보인다는 사실은 접근/입력 허용이 아니다.

## 5. 주요 상태와 실패 계약

1. **입력 준비:** 권한·수명·지정 파일 지원·제외를 검증한 뒤 현재 요청의 입력을 고정한다. 선택됐지만 읽지 못한 자료를 실제 사용으로 기록하지 않는다. 실행 도중 범위 변경·외부 검색 끄기는 기존 계약을 유지하며 다음 요청의 범위를 확실히 갱신한다.
2. **후보:** 생성 결과는 본문이 아니다. 적용은 고정한 항목의 편집안만 변경하고 별도 사용자 저장을 거친다. 사용자 편집·항목 이동·계정 변경·휴지통/복구가 발생하면 기존 기준을 다시 확인하며 오래된 응답으로 덮어쓰지 않는다.
3. **검토:** 규칙 검사 성공, AI 점검 성공, 사용자의 직접 확인, 문서 완료는 각각 다르다. 검사 후 문서가 바뀌면 옛 결과를 현재 완료 판정에 사용하지 않는다. AI 실패는 참고 점검 실패이며 기본 규칙 검사 성공으로도 표시하지 않는다.
4. **원본:** 현재 사실의 값 변경 확인은 영향 항목 재검토. 계획/과거 값 확인은 의미·시점과 함께 보존. 삭제/접근 실패만 확인한 경우 기존 완료를 보존하고 비교 불가 표시. 새 완료 판정에는 현재 필요한 근거를 다시 확인한다.
5. **등록:** 건별 성공/실패/미확인을 표시한다. 이미 성공한 할 일을 다시 만들지 않으며 원 등록이 미확인이면 조회 후 처리한다. 문서 완료 조건과 사용자 완료 요청이 있으면 등록 실패와 별개로 완료 가능하다.
6. **중단/계속:** 원 부분 답변과 중단 기록을 보존한다. AX 종료 및 이전 출력 차단 확인 → 사용자 ‘이어서 생성’ → 현재 범위 재검증 → 새 run에서 남은 내용 생성. 원격 종료 미확인은 GD-045처럼 표시하고 자동 재전송하지 않는다. 부분 답변 결합/중복 표시의 정확 방식은 D-05다.
7. **출력:** 현재 저장본의 일관된 버전·틀·이미지를 사용하고 미완료/재검토이면 검토 전으로 표시한다. 출력 때문에 문서/검토 상태를 바꾸지 않는다. 원본 접근 불가로 기존 완료를 유지하는 경우 현재 저장된 동일 완료본을 제공할 수 있다. 과거 완료본 선택 기능을 의미하지 않는다.

## 6. 남은 설계·공동 계약과 영향

**제품 원칙 FIXED**와 **상세 설계 OPEN**, **공동 제공 확인 OPEN**, **문서 정책 정합 OPEN**을 구분한다. 아래 OPEN은 미구현을 단정하는 표시가 아니라 이번 개정에서 증명하지 않은 계약이다. 기존 C/MC/B/E ID는 추적 연결이며 새 ID로 완료 상태를 지우지 않는다.

**DOC-POL-01 · OPEN:** GD-058은 핵심 원가 완료에 현재 견적/실제 비용 기록을 요구하고, GD-065는 견적 기록을 권장하되 미기록 자체가 작업의 blocker가 되지 않도록 완화했다. 실제 견적의 직접 기록 허용·작성/AI/저장/검토 전 다운로드 계속은 확정이다. **실제 근거 자체가 없는 핵심 원가의 최종 완료**까지 완화했는지는 결정 원문에서 단정하지 않았다. 문서/제품 owner가 그 한 가지 적용 관계를 정합해야 한다. GD-058을 임의 폐기하지 않으며 AI Pipeline에 견적 등록 강제나 모델 완료 판정 기능을 추가하지 않는다. AX-AC-070의 해당 완료 분기는 정책 정합 대기, 나머지 검증은 준비할 수 있다.

GD-046~070으로 결정한 입력·문서·등록 원칙은 다시 묻지 않는다. 다만 이 개정은 에이전트 기능 전체의 조회·쓰기 권한을 전수 종결한 기록이 아니다. [2026-11-26 보완 명세](agent-capability-contracts-2026-11-26.md)의 CAP-01~12에서 현재 경로와 부족한 계약을 구분하고, 기존 일정 변경 권한·반복 운영의 범위와 DOC-POL-01을 별도로 남긴다. D/J의 실제 제공·설계·시험은 여전히 필요하며, 확장 기능의 미결을 현재 승인된 AI 설계 전체의 일괄 중지 조건으로 확대하지 않는다.

## 7. 검증과 변경 범위

GD-046~070 각각의 요구/인수 대응은 [결정·변경 기록 2.2절](../02-user-feature-spec/ax-studio-mvp-decisions-v0.3.md)에 있다. AX-RQ-001~055와 AX-AC-001~077을 추적하며 사례는 모두 NOT_RUN이다. D/J 계약을 닫을 때 해당 AX-AC 및 기존 P5·CT·PC의 유효한 사례에 단위/통합/실제 서비스 검증을 연결한다. 옛 단일 대화·선택 텍스트 전용·원본 변경 경고만 기대값은 현재 인수에 사용하지 않는다.
