# P5 대화 컨텍스트·첨부·작업 이력 모듈 계약

**최신 제품 정정 GD-041·042:** 프로젝트마다 지속 대화 하나이며 삭제/새 대화 기능은 없습니다. AI는 CK에 관한 설명·제안은 할 수 있지만 CK를 변경할 수 있는 Artifact·도구·승인 경로는 만들지 않습니다. CK는 사용자 직접 수정만 허용하고 04 독립 문서 생성은 계속 제공합니다. 이전 다중 Chat·AI CK 적용 경로는 이 범위에서 대체합니다.

**이번 P5 구현 제외:** 사용자의 후속 요청에 따라 AI가 기존 04 문서 수정·삭제를 별도로 제안하거나 실행하는 도구·승인 경로는 구현하지 않습니다. 사용자의 직접 편집·삭제는 유지합니다. GD-035 자체는 기존 결정 이력으로 보존합니다.

기준: 2026-11-12 Q-P5-01~12와 후속 두 답변. 이 문서는 구현·시험 결과가 아니라 M-01·03·05~08의 현행 상세 계약입니다. 기존 모듈 명세 13절의 **AI만 압축, AI 100k, run당 최초+추가 1회, 64k 초과 무조건 중단, `old_ai_only` 및 해당 시험 기대값**은 이 계약으로 대체합니다. 그 외 권한·출처 필터·wire 일치·원격 종료 미확인·CAS 규칙은 유지합니다. 논리 필드와 이벤트 이름은 실제 DB/API 스키마를 확정하지 않습니다.

## 1. 책임과 경계

저장소 공통화는 첨부가 다른 Chat의 자동 검색 대상이 되거나 04 출처에 원문 사본을 추가하는 뜻이 아닙니다(GD-033·039). 파일 ID·경로·물리 스키마·권한 API·파일 생명주기와 Chat/프로젝트 삭제 시 물리 정리 방식은 공통 owner와 확인합니다. 04 문서의 1:N, revision, 최종 승인, 4형식 내보내기는 [04 명세](planning-output-module-spec.md)를 유지합니다.

## 2. 입력, 압축과 실제 모델 한도

1. 현재 권한·세션과 자료 제외를 검증하고 지시문, 도구 정의, 프로젝트/브랜드/CK, 활성 파일/Chip, 허용된 사용자·AI 대화 및 유효 요약, 도구 자료, 현재 요청을 실제 호출 순서와 역할로 구성합니다. 원문 전문은 사용자가 열 수 있도록 보존하되 압축 뒤 모델에 전문이 동시에 전달된다고 주장하지 않습니다. 제공 불가 자료·미정과 0을 구분합니다.
2. 실제 사용할 모델과 최종 wire를 기준으로 전체 **입력** 토큰을 계수합니다. 지시문·도구 정의와 framing을 포함하고 출력 예약은 합산하지 않습니다. 같은 입력 digest로 발송하며 변경·도구 결과·권한 변경 시 다시 구성·계수합니다. 계수 실패는 추정치로 성공 처리하지 않습니다. 출력 8,000 및 안전 여유 8,000은 별도로 확보하며 실제 모델/계정의 검증된 입력 및 전체 컨텍스트 한도를 확인합니다.
3. 입력이 **64,000 이상**이면 오래된 사용자 및 AI 발화를 함께 요약합니다. 종전 캡슐 4,000토큰 및 최근 AI 원문 16,000토큰은 목표로 유지합니다. 최근 사용자 원문 보존 범위와 완전 메시지 경계의 정확한 분할은 EXACT_OPEN이며, 현재 질문이나 진행 중 도구 프로토콜을 오래된 발화로 가장하지 않습니다. 오래된 대화가 없으면 압축 호출을 만들지 않습니다.
4. 각 정상 압축 단계는 하나의 유효 후보와 실제 재계수로 성립하며, 최대 **3단계**입니다. 각 단계의 호출 실패·거절·불완전·유효성 실패 또는 압축이 실질적으로 부족한 경우 그 단계에서 별도의 추가 압축 호출을 최대 **1회** 허용합니다. 캡슐 4k는 목표이지 그 수치 초과만으로 실패하는 하드 상한이 아닙니다. 부족 판정의 정량 기준은 EXACT_OPEN입니다. 한 run의 압축 호출 최대 6회이며 숨은 HTTP 재시도·분할 호출로 늘리지 않습니다. 유효하고 충분한 후보의 전체 입력이 여전히 64k 이상이면 실패 재시도가 아니라 다음 정상 단계로 진행합니다. 재접속·도구 재호출에서 소비 횟수를 초기화하지 않습니다.
5. 후보는 적용 대상 대화 범위·순서·역할·출처와 연결해 검증합니다. 사용자의 결정·정정, AI 제안, 거부·미정·시점·출처를 구분하며 요약이 사용자 승인이나 업무 저장이 되지 않습니다. 형식 검증만으로 의미가 완전 보존됐다고 주장하지 않습니다. 기존 유효 캡슐은 저장 확인 전 보존하며 CAS 충돌·저장 결과 미확인은 멈춥니다. 압축 요청도 실제 모델의 한도를 각각 검증합니다.
6. 세 단계가 완료돼도 64k 이상이거나 압축할 오래된 대화가 없으면 **초과를 사용자에게 알리고**, 실제 모델 한도와 출력·여유를 충족할 때 계속합니다. 64k는 차단 하드 상한이 아닙니다. 실제 한도 초과·계수 실패는 진행하지 않고 자료 조정 등 가능한 다음 행동을 안내합니다. 단계 실패 후 추가 호출까지 실패한 경우에는 유효 후보 없이 진행하지 않고 실패를 알립니다. 원문·프로젝트·첨부를 몰래 잘라 보내지 않습니다.

전송 후 timeout 등 원격 결과 미확인은 확정 실패와 구별합니다. 미확인 호출을 확정 실패로 가장해 자동 재전송하지 않습니다. 로컬 실행 종료 후에는 오류 코드·원격 결과 미확인을 실행 메타데이터에 남기고 로컬 잠금을 자동 해제하여 다음 사용자 요청을 허용합니다. 서버 재시작 시 진행 중이던 실행도 미확인으로 기록하고 자동 해제합니다. 이는 원래 응답 복구나 원격 취소를 보장하지 않습니다. 업무 쓰기의 미확인 결과와 승인·재전송 경계는 별도이며, 구체 retryable 분류·deadline과 다중 프로세스 복구는 EXACT_OPEN입니다.

## 3. 출처, 첨부 및 외부 도구

- 사용자·AI 발화와 요약의 출처 의존성을 추적합니다. 제거한 자료에서만 유래한 정보는 다음 run의 원문·이력·요약·도구 입력으로 자동 재유입하지 않습니다(D-UF-084). 출처가 섞인 요약은 허용 여부를 검증하고 필요한 경우 허용 원문으로 재구성합니다. 출처를 분리하거나 검증할 수 없다면 해당 파생 내용을 안전한 것으로 간주하지 않습니다. 사용자가 명시적으로 채택한 기획 가정은 별도 결정으로 유지합니다.
- 현재 Chat 업로드는 `.txt`·`.md` 두 **형식**만 지원합니다. 개수·크기 제한은 별도 계약이며 2개 제한을 뜻하지 않습니다. UTF-8·CP949 모두 지원하고 손상/미지원/모호한 디코딩을 성공으로 표시하지 않습니다. 자동 인코딩 판별과 양쪽 유효 시 선택 방식은 EXACT_OPEN입니다. 실제 파일 참조, 세션·프로젝트 소속, 상태·실제 사용 범위를 분리해 기록합니다.
- 프로젝트/브랜드/CK의 허용 상태를 기본 맥락에 제공한 뒤 정보가 부족할 때 에이전트가 필요한 프로젝트 읽기·웹 검색 도구를 선택할 수 있습니다. 웹은 기존 검색 허용/끄기, 외부 전송 최소화와 개인정보 경계(D-UF-062·067)를 준수합니다. 자료가 충돌하면 출처·상태·시점과 불확실성을 설명하고 필요한 판단을 묻습니다. 사용자의 명시적 승인 없이 CK·문서를 쓰거나 삭제하지 않습니다.

## 4. UI·이력과 실패

실제로 발생한 압축의 시작·진행·완료/실패와 64k 초과 진행 사실을 보여줍니다. 압축된 내용 자체는 열람/다운로드 인터페이스로 제공하지 않으며 원문 대화는 기존 이력에서 열 수 있습니다. GD-043·044에 따라 모델 입력 계수·한도·출력 예약·안전 여유·압축 기준과 마지막 답변 호출 및 이번 요청 전체의 입력/출력 사용량을 표시합니다. 전체는 압축·생성·별도 웹 검색 모델 호출의 Provider 보고값을 포함하고, 각 유형의 합계·보고 건수와 진행/미확인을 분리합니다. 입력 계수 API·비모델 도구·이전 요청은 합산하지 않습니다. 모의 값은 구분하고 API 비용은 표시하지 않습니다. 계수는 압축과 도구 이후 재계수하며 이벤트 재생 시 같은 상태로 복원합니다. 작업 단계와 실제로 확인된 중간 결과 및 전달된 답변은 같은 Chat 재방문에서도 확인 가능해야 하며, 미확인 성공·모델 내부 추론·압축 내용·비밀키를 진행 기록으로 노출하지 않습니다. 이벤트는 실행·순서·중복을 구분해 재연결 시 재생성 없이 복원하고 세션 간 노출을 막습니다. 중단/권한 상실/원격 결과 미확인은 기존 규칙을 유지합니다. 제품 통합의 물리 이벤트 스키마·보존 기간은 후속입니다.
