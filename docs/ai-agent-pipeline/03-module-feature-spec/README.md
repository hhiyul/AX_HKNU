# 모듈 기능명세

**2026-11-25 현재:** [사용자 정본 v0.3-R2](../02-user-feature-spec/ax-studio-user-feature-spec-v0.3.md)와 [AI Pipeline 개정 계약](ai-pipeline-contract-revision-2026-11-25.md)이 GD-046~070·최신 Figma의 현재 기준입니다. 개정 계약에서 경로별 입력·모듈 책임·상태, 기존 대체 범위와 내부 설계 D-01~07·공동 제공 J-01~05·문서 정책 DOC-POL-01을 구분합니다. 아래 기존 모듈 상세는 대체되지 않은 범위의 재사용 근거입니다. [인수 추적표](../02-user-feature-spec/ax-studio-mvp-acceptance-v0.3.md)는 55개 요구·77개 사례이며 실행은 NOT_RUN입니다. 논리 계약 작성으로 실제 제공·상세 설계·구현·인수 완료를 주장하지 않습니다.

**2026-11-26 구현 전 보완:** [에이전트 기능 보완 명세](agent-capability-contracts-2026-11-26.md)는 Figma·현재 앱의 CAP-01~12 차이, 자료/일정 조회와 확인 등록의 논리 계약, 공동 owner 제공물, ACAP-01~18 인수 계획을 정리합니다. 현재 일정 읽기는 일부 존재하며 일반 대화의 할 일 제안 연결은 별도로 필요합니다. 기존 일정 변경 권한을 자동 추가하지 않으며 코드·Grill·HandOff는 변경하지 않았습니다. 실행 인수는 NOT_RUN입니다.

[구현 Phase 계획](agent-implementation-phases-2026-11-26.md)은 AG-P0~6의 작업 순서·사용자 확인 시나리오·완료 조건·공동 계약 의존성과 검증 방법을 정리합니다. 후속 [AG-P0~5 구현·검증 기록](agent-implementation-progress-2026-11-26.md)에 실제 코드 연결, 백엔드 465개·프런트 3개 테스트, 공개 API/저장 계약, 남은 UAT·정책을 기록했습니다. 화면 자동 확인은 도구 연결 오류로 미완료이며 실제 UAT·배포는 수행하지 않았습니다.

## 과거 모듈 단계의 상태와 자료

사용자 기능명세를 구현할 모듈의 책임·상호작용·실제 실행 계약을 정의하는 계층입니다.

**현재 상태: 2026-11-06 M-01/06 상세 계약·발송 전 검증 보완 / 공통 API·일부 어댑터 OPEN / 구현·테스트 NOT_RUN.** 사용자 기능명세 v0.2의 D-UF-109로 MVP 대화·압축 모델은 OpenAI `gpt-6-luna`로 지정됐습니다. Python 3.11과 팀원 API를 호출하는 Python 어댑터 경계는 이번 사용자 확인입니다. 자료 획득→허용 컨텍스트→Responses payload·파싱·압축/예산, 자산 바이트·계수/발송 일치·실패 상태와 시험 기대값을 구체화했습니다. 제품 보류와 공동 계약은 필요한 경로별로 먼저 확인합니다.

- [04 기획 산출물 모듈 명세](planning-output-module-spec.md): 03 라우팅과 04 실행·문서·출력 owner 계약.
- [03·04 구현 준비 계약과 blocker](implementation-readiness-contracts.md): 내부 포트 설계, 현재 소스와의 차이, 공동 owner 제공물·시험 계획.
- [OpenAI 백엔드 송수신 구현 계획](openai-backend-implementation-plan.md): 체리픽 후 기준선, DB 없는 단위시험과 opt-in 실연결 시험, 실제 제품 통합 전 차이.
- [P5 현행 컨텍스트·첨부·작업 이력 모듈 계약](p5-context-module-contract.md): Q-P5-01~12의 압축·도구·표시·저장과 반례.
- [P5 채팅·컨텍스트·에이전트 구현 계획과 질문지](p5-chat-context-implementation-plan.md): P5-1~5의 구현·인수, 64k 압축·표시, 스트리밍, TXT/MD 초기 범위와 제품 질문.

## 실제 모듈 명세에 연결할 내용

- 근거 사용자 기능 UF ID·정리 쟁점 U/C ID·기존 결정 D ID·미정 OPEN-UF.
- 모듈 책임과 경계, 실제 입력·출력·인터페이스·상태·저장 방식.
- 오류·동시성·실행 제약과 사용자 결과의 연결.
- 구현 검증 기준과 팀원 담당 시스템과의 미정 계약.

사용자 기능의 완료, 모듈 구현 가능성, 구현 완료, 실서비스 검증은 별개입니다. 모듈의 세부 계약이 사용자 결과를 바꾸면 사용자 기능·공통 계약에서 먼저 확인합니다.
