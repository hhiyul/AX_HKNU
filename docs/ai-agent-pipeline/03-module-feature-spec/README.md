# 모듈 기능명세

사용자 기능명세를 구현할 모듈의 책임·상호작용·실제 실행 계약을 정의하는 계층입니다.

**현재 상태: 2026-11-06 M-01/06 상세 계약·발송 전 검증 보완 / 공통 API·일부 어댑터 OPEN / 구현·테스트 NOT_RUN.** 사용자 기능명세 v0.2의 D-UF-109로 MVP 대화·압축 모델은 OpenAI `gpt-6-luna`로 지정됐습니다. Python 3.11과 팀원 API를 호출하는 Python 어댑터 경계는 이번 사용자 확인입니다. 자료 획득→허용 컨텍스트→Responses payload·파싱·압축/예산, 자산 바이트·계수/발송 일치·실패 상태와 시험 기대값을 구체화했습니다. 제품 보류와 공동 계약은 필요한 경로별로 먼저 확인합니다.

## 이 계층에서 다룰 주제

| 주제 | 후속 설계할 내용 |
| --- | --- |
| 에이전트 역할 | 실제 책임 분담·입출력·다른 구성요소와의 경계 |
| 하네스 구성 | 컨텍스트·실행·도구·검증·저장·관찰을 지원할 구성요소와 연결 |
| 프로젝트 섹션별 컨텍스트 관리 | 섹션별 조회·조합·갱신·출처/버전·권한/제외, 비압축 prefix와 과거 AI만의 압축. [현행 상세 계약](ai-pipeline-module-feature-spec-v0.1.md#13-m-0106-상세-구현-계약)을 따르며 옛 요약 논의로 자료 prefix를 압축하지 않음 |
| 에이전트 루프 | 실행 시작·반복·도구 결과 반영·종료·실패·중단·복구의 실제 계약 |

여섯 체크리스트를 여섯 에이전트로 대응시키거나 특정 프레임워크를 선택한 것이 아닙니다. 사용자 동작·결과를 구현 기본값으로 대신 정하지 않으며, 이미 합의한 재조회·버전·보류·재시도·종료 제약은 설계 입력으로 유지합니다.

## 실제 모듈 명세에 연결할 내용

- 근거 사용자 기능 UF ID·정리 쟁점 U/C ID·기존 결정 D ID·미정 OPEN-UF.
- 모듈 책임과 경계, 실제 입력·출력·인터페이스·상태·저장 방식.
- 오류·동시성·실행 제약과 사용자 결과의 연결.
- 구현 검증 기준과 팀원 담당 시스템과의 미정 계약.

사용자 기능의 완료, 모듈 구현 가능성, 구현 완료, 실서비스 검증은 별개입니다. 모듈의 세부 계약이 사용자 결과를 바꾸면 사용자 기능·공통 계약에서 먼저 확인합니다.
