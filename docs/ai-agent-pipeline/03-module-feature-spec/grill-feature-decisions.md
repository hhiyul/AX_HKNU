GD는 이 Grill의 결정 추적 번호입니다. 질문 ID인 GQ, 사용자 정본의 D-UF, 공동 C·물리 MC 번호와 구별합니다. 이 표의 채택은 구현·시험·실서비스 검증의 완료를 뜻하지 않습니다.

GD-022에서는 시스템 형식 오류의 재요청 부담을 줄이는 대신 추가 모델 호출·대기가 생길 수 있는 대가를 채택했습니다. 정상 예에서는 현재 출력의 검증 오류를 보정한 뒤 재검증을 통과한 제안만 전달합니다. 반례로 같은 오류가 다시 나오거나 진전이 없으면 무한 수정하지 않고 기존 실패 안내로 종료합니다. 응답이 왔는지 모르는 통신 실패나 저장 결과 미확인을 보정 대상으로 삼지 않으며, 형식 통과를 사실 검증·실제 저장 완료로 만들지 않습니다.

GD-023에서는 일시 혼잡의 재요청 부담을 줄이는 편의와 같은 요청의 대기가 길어질 수 있는 대가를 채택했습니다. 정상 예에서는 계약상 생성 미접수가 확인된 일시 반려만 활성 요청 안에서 제한적으로 다시 시도합니다. 반례로 응답이 오지 않거나 오류 코드만 있는 경우를 미실행으로 간주해 같은 생성을 자동 재전송하지 않습니다. 확인 수단이 없는 실제 어댑터에는 이 예외를 적용할 수 없으며, 미접수 확인/오류 분류와 재시도 한도는 아직 제공·검증됐다고 주장하지 않습니다.

기존 합의 적용 확인: 자동 참고한 추가 기록에도 정본 G-11의 실제 읽은 범위·중요한 누락/판단 영향·출처/시점/한계 안내를 적용합니다. 이는 새 선택이 아니므로 별도 GD를 만들거나 같은 원칙을 재투표하지 않습니다.

### 응답 완료 · GQ-06-02/C-03: 한 기획자의 여러 프로젝트 AI 작업 병행

상태는 **GD-018로 B안 제품 방향 채택 / 실제 병렬 제공 조건 공동 확인 대기**입니다. 아래는 GD-017의 한 명 이용을 전제로 제시한 질문 당시 비교안입니다. G-25·D-UF-104의 같은 Chat 단일 실행을 유지하며 서로 다른 프로젝트 Chat의 병렬 실행은 GD-018을 따릅니다. 기획자 전체 하나씩 제한 A안은 미채택입니다. 영향 모듈은 M-05·08, 실제 실행 제공 조건은 C-03입니다.

합성 상황: 기획자가 A 프로젝트 Chat에서 사례 조사·비교를 요청했고 답변이 진행 중입니다. 같은 앱 실행을 유지한 채 자신이 이용 가능한 B 프로젝트의 전용 Chat으로 이동해 B 가격안 검토도 요청하려 합니다. A/B는 각각 고정된 별도 저장 대상을 유지합니다. 사용자 중단·앱 종료·중단 작업 복구 상황은 아닙니다.

| --- | --- | --- |

두 안 모두 큐잉·예약·종료 후 자동 전송·자동 작업 전환을 추가하지 않습니다. B로 이동했다는 이유만으로 A를 자동 취소하거나 A의 저장 대상을 B로 변경하지 않습니다. 제한 대상은 새 AI 답변 실행이며, 저장 미확인의 자동 결과 조회를 답변 생성과 합쳐 기존 다른 Chat/항목 작업 허용을 막지 않습니다. 실제 이용 한도·서버의 실행/종료 확인·여러 탭의 중복 제어는 C-03/MC 후속입니다. 이번에는 정확한 병행 개수·타임아웃·API·락 구조를 정하지 않습니다.

### 응답 완료 · GQ-07/C-01: 진행 중인 AI 작업과 프로젝트 삭제

### 다음 질문 · GQ-03-05: 서비스 실행 종료·Provider 종료 미확인과 다음 질문

상태는 **질문 제시·미응답 / 기존 중단·전송 경로**입니다. G-25·D-UF-104의 같은 Chat 단일 활성 실행/종료 후 직접 전송과 UF-AI-05 EX-02·ST-02·06의 중단 확인 범위를 연결합니다. 중단 요청 접수를 실제 종료로 간주하는 안은 제시하지 않습니다. 이번에는 서비스 자체의 실행 종료가 확인된 뒤에도 Provider 종료 확인을 다음 질문 전송의 필수 조건으로 둘지 확인합니다. 영향 모듈은 M-05·06·07·08이며 실제 종료 증거·전달은 C-03/MC 후속입니다.

합성 상황: 사용자가 현재 답변의 중단을 요청했습니다. AX 서버는 해당 답변 실행의 종료를 확인했고, 기존 답변 생성 루프의 추가 모델/도구 호출과 늦은 출력의 본문·제안 반영을 차단했습니다. 중단 요청 접수 시점의 부분 답변은 GD-010에 따라 고정됐습니다. 하지만 이미 보낸 외부 Provider 호출이 실제로 끝났는지는 확인하지 못했습니다. 프로젝트/Chat 접근은 허용되며 사용자가 새로운 질문을 작성했습니다.

| 대안 | 사용자 결과 | 대가·범위 |
| --- | --- | --- |
| A · AX 실행 종료 확인 후 새 질문 허용 | 서비스 답변 실행 종료와 본문 반영 차단이 확인되면 사용자가 새 질문을 직접 전송할 수 있게 함. Provider 종료는 미확인으로 구별해 안내 | 원격 확인 지연 때문에 대화를 계속 막지 않지만, 이전 외부 호출이 아직 처리 중일 가능성은 남음. 중단 접수만으로는 전송을 허용하지 않음 |
| B · Provider 종료 확인까지 전송 보류 | AX 실행이 끝나도 외부 Provider 종료가 확인되기 전에는 같은 Chat에서 입력 작성만 허용하고 새 전송을 막음 | 원격 처리까지 겹치지 않도록 기다리지만 실제 확인 수단이 없거나 늦으면 같은 Chat이 오래 잠길 수 있음. 자동 예약/전송은 하지 않음 |

두 안 모두 현재 AX 답변 실행의 종료/본문 반영 차단이 확인되지 않았다면 기존 같은 Chat의 추가 전송 제한을 유지합니다. Provider 취소/종료를 확인 없이 완료로 표시하지 않으며, 늦은 결과로 중단 답변을 추가·교체하거나 새 답변의 근거로 자동 반입하지 않습니다. 새 질문 허용은 원 요청의 자동 재전송·종료 작업 복구·미확인 저장 요청의 재쓰기 허가가 아닙니다. 저장 미확인은 기존 자동 결과 조회와 미반영 종료 확인 후 UI 재승인 조건을 유지합니다. 이 조회와 확인된 실행/쓰기 상태의 갱신은 중단 답변의 본문 추가와 구별합니다. 다른 프로젝트 Chat의 병렬 실행·사용자 편집 보존·미전송 내용 자동 전송 제외도 유지합니다. A안이 채택되면 G-25의 단일 활성 실행 종료 기준을 AX의 확인된 답변 실행 종료로 구체화하되 Provider 원격 결과 상태는 별도로 유지해야 합니다. 실제 종료/차단 증거·늦은 결과 격리·새 실행 접수·표시 형식은 C-03/MC 후속입니다.
