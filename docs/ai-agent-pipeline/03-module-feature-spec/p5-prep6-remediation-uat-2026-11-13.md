# P6 전 P5 기능 보완과 UAT — 2026-11-13

## 범위

사용자 요청으로 팀 공통 백엔드와의 계약 대조·통합은 보류하고 P5의 독립 합성 SQLite 경로를 보완했다. 기존 사용자의 대화나 공통 MongoDB는 사용하지 않았다. 실제 OpenAI 요청은 `gpt-6-luna`, 공개 검색어와 합성 데이터만 사용했다. 키·요약·요청 본문을 남기지 않은 [비민감 계측 trace](p5-prep6-remediation-uat-trace-2026-11-13.jsonl)를 보존한다.

## 결과

| 결과 미확인 | 생성·압축·웹 검색에서 원격 결과가 미확인이면 `outcome_unknown`을 표시하고 같은 대화의 새 실행을 보류한다. 모의 전송 오류·검색 오류와 재시작으로 확인했다. 원격 결과 확인 및 관리자 복구 경로는 아직 없다. 실제 타임아웃은 유발하지 않았다. |

| 03 추가 기록 | 프로젝트별 한 기록, 단일 UI 승인, revision 충돌 및 편집안 보존을 합성 시험했다. 브라우저에서 revision 1을 저장했고 실제 모델이 내용을 읽고 CK와 구분했다. 실제 모델은 채팅 저장 요청에 저장 없이 검토안만 만들었다. |
| 03 기획 내보내기 | 저장된 여섯 CK 내용·상태와 존재하는 추가 기록을 MD/TXT로 출력한다. 브라우저 버튼으로 받은 파일을 UTF-8로 열어 여섯 항목과 한글 기록을 확인했다. 필수 항목 조회 불완전 시 전체 출력을 보류하며 04 문서 4형식 출력과 별개다. |
| 첨부 원문·제외 | TXT/MD 원본 다운로드와 참고 제외 후 비활성 원문의 다운로드 차단을 합성 시험했다. 두 파일과 혼합 캡슐에서 한 파일을 제외해 파생 답변·요약의 자동 재유입을 막는 합성 시험을 수행했다. |
| 실제 첨부 읽기 | 최초 실제 실행은 두 파일이 입력에 있었는데 모델이 프로젝트 읽기 도구로 파일을 찾지 못해 읽을 수 없다고 답해 FAIL이었다. 이후 첨부가 이미 읽힌 입력임을 설명하고 해당 도구가 요청에 포함된 활성 첨부를 조회하도록 수정했다. 새 합성 프로젝트에서 실제 모델이 두 파일을 읽었고, 하나를 제외한 후에는 나머지만 입력·답변에 포함했다. 재검증 시 모델은 추가 읽기 도구 없이 첨부를 읽었으므로 도구 재조회 경로 자체는 모의 시험이다. |

전체 합성 `tests_unit` **86개 통과**. 실제 모델 호출 **18회**, 입력 계수 **21회**, 확인된 토큰 사용량 합은 입력 330,310·출력 1,829·합계 **332,139토큰**이다. 여기에는 최초 첨부 읽기 실패, 최종 검색 재검증과 압축 대상 없는 64k 초과 시험도 포함된다. 청구 금액은 확인하지 않았다.

04의 AI 주도 기존 문서 수정·삭제 경로 및 CK에 대한 AI 변경 경로는 추가하지 않았다. 팀 인증·파일 저장소·원자성·복구·다중 프로세스, 실제 프로젝트로의 이행, 다단계 압축 실호출과 운영 품질은 별도다.
