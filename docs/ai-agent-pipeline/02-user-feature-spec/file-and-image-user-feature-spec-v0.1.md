# AI Chat 파일 첨부·이미지 분석 사용자 기능명세 v0.1

작성일: 2026-11-03 · 연결: UF-AI-03 / R-04·05 / U-07·08 / C-01·03 / OPEN-UF-04·12

**상태: 사용자 기능 초안 / D-UF-081~088의 파일·이미지 사용자 기능 합의 / D-UF-089는 기존 확인 자료 재사용 원칙의 적용 확인 / 구체적 지원 조건·한도·보존·권한은 공동 확인.** 이 문서는 구현 완료나 실제 모델의 처리 품질을 증명하지 않습니다. 기존 [사용자 기능명세](ai-pipeline-user-feature-spec-v0.1.md)와 저장·검색·프로젝트 관계의 합의를 유지합니다.

**2026-11-12 현행 범위:** Q-P5-05~07에 따라 Chat 첨부는 txt·md 두 형식이고 UTF-8·CP949를 지원합니다. 파일 개수는 미정입니다. Word·이미지 업로드/분석 관련 아래 기록은 D-UF-081·082·085의 역사이며 현재 Chat에서 제공하지 않습니다. 이 제한은 프로젝트 사진 관리와 04 문서 TXT/MD/DOCX/PDF export를 변경하지 않습니다. 첨부 원문과 04 산출물은 같은 프로젝트 파일 저장소를 활용하되 Chat별 접근 격리와 04 소유·출처 원본 사본 없음은 유지합니다. 디코딩 판별·모호성 및 물리 저장/보존·접근은 후속입니다. [현행 상세](../03-module-feature-spec/p5-context-module-contract.md).

## 1. 사용자 목적과 결정 상태

사용자는 기획 문서·제품 사진·포장 시안·견적 캡처를 일일이 다시 설명하지 않고 AI Chat의 참고 자료로 제공하여, 현재 펀딩 기획에 필요한 설명·검토·편집 가능한 제안을 얻습니다. 파일 업로드, 실제 내용 분석, 체크리스트 평가, 기획 저장·확정은 서로 다른 결과입니다.

| 구분 | 현재 기준 |
| --- | --- |
| 현행 | AI Chat 업로드는 txt·md 두 형식, UTF-8·CP949 지원(Q-P5-05·06). 과거 여섯 형식 D-UF-081은 Chat 지원 범위에서 대체 |
| 과거 결정·현재 Chat 미지원 | 이미지의 보이는 내용·읽을 수 있는 문자를 해석하고 사용자 요청에 맞는 기획 제안까지 연결. 관찰·추론·미정을 구분하며 사진만으로 실물 규격·원가·성능을 확정하지 않음(FILE-01 A / D-UF-082) |
| 이번에 확정 | 첨부 파일은 사용자가 제거할 때까지 해당 Chat의 활성 참고 자료로 유지하고 목록을 표시. 제거하면 이후 활성 파일 참조에서 제외하며 원문 삭제와 구분(FILE-02 A / D-UF-083) |
| 이번에 확정 | 이력은 남기되 제거한 파일에서만 유래한 과거 정보는 자동 재사용하지 않음. 사용자가 현재 기획에 명시적으로 채택했거나 저장한 결정은 유지(FILE-02-HISTORY A / D-UF-084) |
| 과거 결정·현재 Chat 미지원 | Word 문서의 요청에 필요한 본문·표·삽입 이미지를 함께 분석 대상으로 지원하고 내용 간 연결을 검토. 실제 확인 범위·누락·영향을 구분하며 완전/무제한 처리와는 구분(FILE-03-A A / D-UF-085) |
| 이번에 확정 | 파일만 Chat 메시지로 전송하면 실제 확인 내용의 짧은 요약·다음 행동 제안. 사용자가 방향을 선택·변경(FS-01 A / D-UF-086) |
| 이번에 확정 | 일부 자료를 읽지 못하면 가능한 부분 검토와 실제 참고 범위·누락 영향·보류 판단 안내. 자료 보완 또는 범위를 좁힌 진행 선택(FS-02 A / D-UF-087) |
| 이번에 확정 | Chat의 첨부·근거 표시에서 실제 분석에 사용한 원문을 열거나 다운로드할 경로 제공. 파일 형식·실제 접근/제공 범위 안내(FS-03 A / D-UF-088) |
| 기존 원칙 적용 확인 | 과거 실제 확인 자료는 출처·당시 확인 시점·현재 한계와 함께 재사용하고 최신/원문 확인이 필요한 판단은 보류. FS-04 A / D-UF-089이며 독립 신규 기능으로 분류하지 않음 |
| 기존 보장 유지 | 파일명 등록을 실제 내용 검토로 표시하지 않음. 최신 사용자 결정·편집안 존중, 명시적 UI 저장·확정, 기존 서버 검증·저장 보류 유지 |
| 아래의 초안 제안 | 첨부→요청→분석→기획 활용의 사용자 흐름과 문서 분석 결과 구성. 미정 정책을 확정된 동작으로 읽지 않음 |
| 공동 미정 | 구체적 지원 조건·개수/용량/처리 한도, 원문 제공·보존·삭제·권한 |

첨부 파일의 활성 참조 지속·제거는 FILE-02 A / D-UF-083, 제거한 파일의 과거 정보 자동 재사용 제외는 FILE-02-HISTORY A / D-UF-084로 별도 합의했습니다. 파일은 프로젝트 소유 관계를 만들거나 저장 프로젝트를 바꾸지 않습니다. 프로젝트 사진 관리 화면의 지원 형식은 이번 Chat 업로드 결정으로 변경하지 않습니다.

## 2. 과거 허용 파일 목록 — Q-P5-05로 Chat 지원 범위 대체

아래 표는 D-UF-081의 기록입니다. 현재 허용은 txt와 md뿐이며 Word와 이미지는 Chat에서 거부합니다.

| 분류 | 허용 확장자 | 활용 예시 | 구분할 지원 범위 |
| --- | --- | --- | --- |
| 텍스트 문서 | `.txt` | 상품 설명·인터뷰 메모·견적 항목 | 실제 읽힌 내용과 읽지 못한 부분. 인코딩·문서 길이 등의 제공 범위는 공동 확인 |
| Word 문서 | `.docx` | 펀딩 기획서·제안서 | 요청에 필요한 본문·표·삽입 이미지를 함께 분석 대상으로 지원(D-UF-085). 실제 읽힌 범위·누락·영향을 구분하며 모든 내부 요소의 완전한 처리를 보장하지 않음 |
| Markdown 문서 | `.md` | 기획 초안·구조화된 메모 | 문서 내용과 링크 대상·외부 이미지는 구분. 첨부만으로 외부 검색·조회 허용을 얻지 않음 |
| 이미지 | `.png`, `.jpeg`, `.jpg` | 제품 사진·포장 시안·문구/견적 캡처 | 보이는 내용·읽을 수 있는 문자와 불명확한 부분을 구분. JPEG의 `.jpeg`·`.jpg`는 모두 허용 |

그 밖의 확장자는 Chat 업로드 대상으로 허용하지 않고 지원 형식을 안내합니다. 프로토타입의 WebP 입력·파일 2개·각 2MB는 현행 제품 계약이 아닙니다. 허용 확장자여도 손상·잠금·읽기 불가 등으로 실제 내용을 처리하지 못할 수 있으며 이를 분석 성공으로 안내하지 않습니다. 정확한 지원 조건·한도와 형식 검증 방법은 아직 정하지 않았습니다.

## 3. 대표 사용자 흐름 초안

아래 Word·이미지 예시는 과거 형식 기준의 역사적 예시입니다. 현재 Chat에는 txt/md에 해당하는 흐름만 적용합니다.

| 단계 | 사용자의 목적·행동 | 사용자에게 제공할 결과·선택 | 결정 상태 |
| --- | --- | --- | --- |
| 1. 자료 제공 | 프로젝트 전용 Chat에 허용 파일을 첨부 | 첨부한 파일을 식별하고 지원 여부·실제 접수 결과 확인. 파일 선택·드래그 앤 드롭의 구체적 UX는 후속 검토 | 확장자 제한 확정 / UX 초안 |
| 2. 요청 전달 | 원하는 작업을 설명하거나 질문 없이 파일만 전송 | 명시한 요청에 맞춰 검토. 파일만 전송하면 실제 확인 내용의 짧은 요약·다음 행동을 제안하고 방향 변경 가능 | FS-01 A / D-UF-086 확정 / 구체적 표시 UX 후속 |
| 3. 분석 결과 확인 | 문서 내용·사진이 어떻게 활용됐는지 확인 | Word 본문·표·삽입 이미지를 요청에 맞게 함께 검토. 일부 자료를 읽지 못해도 가능한 부분 검토와 실제 참고 범위·누락 영향·보류 판단 안내 | 분석 대상·FS-02 A / D-UF-087 확정 / 구체적 표시 UX 후속 |
| 3-1. 원문 대조 | AI가 읽은 수량·문구·조건 등을 직접 확인 | 실제 분석에 사용한 원문을 열기/다운로드할 경로 제공. 다른 파일을 원문으로 대체하지 않으며 이용 불가 시 확인 성공으로 표시하지 않음 | FS-03 A / D-UF-088 확정 / 구체적 제공·보존·권한은 공동 계약 |
| 4. 기획 발전 | 추가 질문·사용자 정정·필요한 제안 선택 | 최신 사용자 결정을 작업 기준으로 유지. 새 AI 제안은 별도 후보로 두고 기존 미저장 편집안을 자동 덮어쓰지 않음 | 기존 합의 유지 |
| 4-1. 자료를 계속 참고하거나 제외 | 같은 Chat의 다음 질문에서 첨부 자료를 참고하거나 목록에서 제거 | 제거 전까지 활성 참고 자료로 유지하고 현재 목록 확인. 제거 후 활성 파일 참조·파일에서만 유래한 과거 정보의 자동 재사용 제외. 이력·사용자 채택/저장 결정은 유지하고 원문 삭제와 구분 | FILE-02·FILE-02-HISTORY A / D-UF-083·084 확정 |
| 5. 종료 또는 저장 | 설명만 얻고 종료하거나 원하는 변경을 편집·선택 | 미저장 상태로 Chat을 이어갈 수 있음. 실제 기획 반영은 UI의 명시적 초안/확정 선택·최종 반영과 기존 검증·보류·결과 확인을 따름 | 기존 합의 유지 |

첨부만으로 여섯 체크리스트를 모두 완료 평가하거나 저장하지 않습니다. 기존의 명시적 재검토가 필요한 경로를 파일 분석으로 우회하지 않습니다. 같은 Chat을 이어갈 때 활성 참고 자료의 기준은 제거 전까지 유지됩니다. 활성 참조 유지는 매 응답에서 모든 파일을 다시 읽거나 전부 처리했다는 뜻이 아니며 실제 참고 범위·한계는 계속 구분합니다. 원문 보존·재방문에서의 실제 이용 가능 범위는 공동 계약으로 남깁니다.

## 4. 분석 결과의 사용자 의미

### 4.1 문서를 참고한 설명·제안 — Word 분석 대상 합의 / 응답 구성 초안

문서를 단순히 보관하는 기능에 그치지 않고, 실제 읽힌 범위에서 사용자의 질문에 답하고 기획의 설명·미정·충돌·개선안을 정리하는 흐름을 제안합니다. Word 문서는 요청에 필요한 본문·표·삽입 이미지를 함께 분석 대상으로 지원하고 내용 간 연결을 검토합니다(FILE-03-A A / D-UF-085). 문서에 적힌 가설이나 견적은 해당 자료의 진술로 다루며 실제 구매 반응·최종 원가·제작 가능성이 검증됐다는 뜻으로 바꾸지 않습니다. 모든 내부 요소의 완전한 처리·무제한 분석 보장은 아닙니다.

예를 들어 상품 설명 `.md`와 기획서 `.docx`의 고객·구성이 다르면 차이를 설명하고 선택·수정할 안을 제시할 수 있습니다. 어느 파일을 우선할지 불명확할 때 오래된 문서가 최신 사용자 결정을 자동 대체하지 않습니다. 전체 문서를 읽지 못했다면 전체 일관성 검토가 끝났다고 표시하지 않습니다.

### 4.2 이미지를 해석한 기획 제안 — FILE-01 A / D-UF-082

AI는 이미지의 보이는 대상·구성·표현과 읽을 수 있는 문자를 참고해 요청에 필요한 해석·기획 제안을 제공합니다. 이미지에서 확인한 내용, 그에 근거한 추론·가정, 추가로 알아야 할 내용을 구분합니다. 관련 체크리스트의 제안으로 연결할 수 있지만, 이미지 분석 결과만으로 전체 구체화 완료·사용자 확정을 대신하지 않습니다.

| 상황 | 제공할 사용자 결과 | 판단의 한계 |
| --- | --- | --- |
| 제품 사진으로 선물 구성을 고민 | 보이는 구성·표현을 설명하고 고객 목적에 맞는 구성·표현 개선 가설 제시 | 실제 치수·재질·내구성·고객 반응은 사진만으로 확정하지 않음 |
| 포장 시안에서 문구·표현을 검토 | 읽을 수 있는 문구와 배치·표현을 근거로 전달력·기획 정합성의 개선안 제시 | 흐릿하거나 가려진 문구는 추정한 확정 원문으로 표시하지 않음 |
| 견적 캡처로 가격 기획을 검토 | 읽을 수 있는 수치·조건을 구분해 가능한 계산과 누락 비용·영향 설명 | 읽지 못한 금액·수량·조건은 0이나 임의 값으로 채우지 않으며 필요한 총원가·최종 이익 판단 보류 |

한 이미지를 첨부했다고 모든 시각 요소·문자를 빠짐없이 확인했다는 뜻은 아닙니다. 요청에 필요한 부분이 확인되지 않았다면 그 한계를 설명하고 해당 판단을 단정하지 않습니다. 실제 처리 품질·지원 해상도 등은 별도의 제공 범위 확인이 필요합니다.

### 4.3 일부 자료를 읽지 못한 요청의 부분 검토 — FS-02 A / D-UF-087

파일명만 등록했거나 일부 내용을 읽지 못했는데 전체 검토 성공으로 안내하지 않는 기존 보장은 유지합니다. 문서 표를 읽지 못했거나 이미지 문자가 불명확한 경우 실제 활용 범위와 결과의 한계를 구분해야 합니다.

실제 읽힌 자료로 가능한 부분 검토·제안을 제공하고 **실제 참고 범위·읽지 못한 자료/내용·누락 영향·그 자료가 필요한 보류 판단**을 구분해 안내합니다. 사용자는 필요한 자료를 다시 제공하거나 범위를 좁혀 이어갈 수 있습니다(FS-02 A / D-UF-087). 부분 결과를 전체 비교·기획 완료로 표시하거나 중요한 누락 금액을 임의 값·0으로 채우지 않습니다.

기존 기획·미저장 편집안·저장 상태는 자동 변경하지 않습니다. 활성 참조 제거는 FILE-02 A, 제거 파일 정보 취급은 FILE-02-HISTORY A를 따릅니다. 실제 기술 복구·자동 재처리·재시도 횟수와 원문 보존/제공은 이 결정에서 확정하지 않으며 기존 Projection 조회 실패·평가 보류·명시적 재시도는 유지합니다.

### 4.4 질문 없이 파일만 보낸 첫 도움 — FS-01 A / D-UF-086

사용자가 질문 없이 파일만 Chat 메시지로 전송하면 실제 확인한 내용의 짧은 요약과 현재 프로젝트에 맞는 소수의 다음 행동을 제안합니다. 사용자는 방향을 선택·변경할 수 있습니다. 단순히 파일을 선택한 순간과 메시지로 전송한 행동은 구분합니다.

읽지 못한 내용은 요약하지 않으며 일부 처리 실패가 있으면 4.3절을 함께 적용합니다. 파일 전송을 여섯 체크리스트 전체 평가·명시적 재검토·저장 선택으로 확대하지 않습니다. 기존 UI 저장·서버 검증·보류 규칙을 유지합니다.

### 4.5 실제 분석에 사용한 원문 확인 — FS-03 A / D-UF-088

Chat의 첨부·근거 표시에서 실제 분석에 사용한 원문을 열거나 다운로드할 경로를 제공합니다. 파일 형식·실제 제공 범위에 맞춰 확인 방식을 안내하며 새로운 수정본이나 다른 파일을 과거 분석에 사용한 원문인 것처럼 제공하지 않습니다.

원문을 이용할 수 없다면 이용 불가를 알리고 열기/다운로드 성공으로 표시하지 않습니다. 원문 확인만으로 AI 재분석·검색·기획 저장을 실행하지 않으며 기존 저장 상태·편집안 보호·참조 제거/과거 정보 취급을 유지합니다. 정확한 보존 기간·원문 제공 조건·권한·뷰어/전달 방식은 공동 계약·후속 설계로 연결합니다.

### 4.6 원문 일시 조회 실패의 기존 원칙 적용 — FS-04 A / D-UF-089

과거 실제 확인 내용은 출처·당시 확인 시점·현재 원문 대조 불가의 한계와 함께 재사용합니다. 최신/원문 확인이 필요한 판단은 보류하며 다시 읽었거나 현재 사실을 확인했다고 표시하지 않습니다. 참조 제거·삭제·권한 상실과 기존 Projection 재조회·저장 보류의 경계는 유지합니다.

이는 기존 확인 자료 재사용·부분 검토 원칙의 적용 확인입니다. 사용자 지적에 따라 같은 원칙을 기술적 실패 예외로 반복 질문하지 않으며 보존·재시도·컨텍스트 구성은 공동 계약·모듈 설계로 연결합니다.

## 5. 저장·다른 자료와의 관계

- 분석 답변·편집용 제안·실제 저장 내용은 구분합니다. 파일 분석이나 제안 가져오기만으로 DRAFT·DECIDED를 변경하지 않습니다. 기존 편집안 보호·선택 범위 반영·UI 최종 선택·서버 검증·저장 보류를 유지합니다.
- 첨부 파일과 프로젝트 Chip은 모두 참고 자료가 될 수 있지만, 파일 첨부가 Chip의 소유/참조 관계나 파일의 장기 보존 정책을 대신 결정하지 않습니다.
- 검색 사용은 D-UF-062·067을 따릅니다. 파일 첨부·Chat 내부 분석은 웹 검색 허용이나 원문·내부 금액·고유명 전체를 검색 입력으로 내보낼 허용을 뜻하지 않습니다.
- 파일 내용과 프로젝트 정보가 다를 때 최신 사용자 결정을 존중하고 차이·가정을 드러냅니다. 자료의 사실 확인, 현재 기획 가설, 실제 저장 내용은 구분합니다.

**상황:** 제품 사진·포장 시안·견적 캡처를 올렸을 때 사용자는 내용을 옮겨 적는 도움과 기획을 발전시키는 도움 중 어디까지 기대할 수 있는가?

| 대안 | 사용자 결과 | 트레이드오프 |

### FILE-02 첨부 파일의 참조 지속·제거 — A 채택 / D-UF-083

**상황:** 제품 사진과 견적서를 보내 한 차례 답변을 받은 뒤, 다음 메시지에서 “수량을 절반으로 줄이면?”이라고 질문합니다. 파일을 다시 첨부하지 않아도 같은 자료를 참고할 것인가?

| 대안 | 사용자 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 사용자가 제거할 때까지 해당 Chat의 활성 참고 자료로 유지하고 목록 표시 | 연속 기획에 편리하지만 오래된 자료·활성 목록 관리와 제거 후 정보 취급의 의미를 명확히 해야 함 |
| B · 미채택 | 첨부한 요청에만 기본 사용하고 이후 다시 사용할 때 사용자가 자료를 선택 | 요청별 사용 범위가 명확하지만 이어지는 대화에서 재선택 부담이 생김 |

사용자가 A를 채택했습니다. 첨부 파일은 제거할 때까지 해당 Chat의 활성 참고 자료이며 현재 목록을 표시합니다. 제거하면 이후 활성 목록·새 파일 참조에서 제외합니다. 이 동작은 원문 삭제가 아니고 과거 대화·분석 결과를 일괄 삭제하는 동작도 아닙니다. 기존 기획·편집안·저장 상태는 자동 변경하지 않습니다.

활성 참조는 매 응답의 전체 재분석·원문 영구 보존을 보장하지 않습니다. 실제 읽기·참고 범위와 원문 보존/삭제·권한의 미정은 유지합니다. 제거한 파일의 과거 정보 자동 재사용은 아래 FILE-02-HISTORY A로 제외합니다.

### FILE-02-HISTORY 제거한 파일의 과거 정보 재사용 — A 채택 / D-UF-084

**상황:** 견적서를 참고해 단가 3,500원이라는 설명을 받은 뒤 오래된 자료라서 활성 목록에서 제거했습니다. 이후 “최소 판매가격을 다시 봐 줘”라고 요청할 때, 과거 답변·추출 요약에 남은 그 단가를 자동으로 다시 써도 되는가?

| 대안 | 사용자 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 과거 이력은 남기되 제거한 파일에서만 유래한 정보를 이후 답변의 근거로 자동 재사용하지 않음. 사용자가 현재 기획에 명시적으로 채택했거나 저장한 결정은 유지 | 제거 의도가 이후 답변에도 이어지지만 필요한 정보는 다른 유효 자료·사용자 설명으로 보완해야 할 수 있음 |
| B · 미채택 | 원문을 새로 참고하지 않되 제거 전에 실제 확인한 내용은 과거 자료임을 밝히고 확인 시점·한계와 함께 재사용 | 대화 연속성은 높지만 제거한 파일의 정보가 이후 답변에도 계속 영향을 줄 수 있음 |

사용자가 A를 채택했습니다. 과거 답변·추출 요약·미채택 제안에 남은 해당 파일에서만 유래한 정보도 이후 답변·기획 제안·평가의 근거로 자동 재사용하지 않습니다. AI가 한 번 제안했다는 사실만으로 사용자의 채택으로 보지 않습니다. 사용자가 현재 기획에 명시적으로 채택·저장한 값은 현재 기획 가정으로 유지하되 원본 파일의 최신 사실이 확인됐다는 뜻으로 바꾸지 않습니다.

예를 들어 견적서의 단가 3,500원을 AI가 설명했을 뿐이라면 파일 제거 후 그 값을 자동 계산 근거로 쓰지 않습니다. 사용자가 “이번 기획은 단가 3,500원으로 진행하자”고 명시적으로 채택했거나 그 내용으로 저장했다면 해당 결정은 유지합니다. 그 외 유효 자료로 판단할 수 없는 중요한 비용은 임의 값·0으로 채우지 않고 기존 비용 미정·판단 보류 원칙을 따릅니다.

두 안 모두 기존 이력을 보존하고 원문을 새 활성 참조로 되살리지 않으며, 기존 기획·미저장 편집안·저장 상태를 자동 변경하지 않는 전제입니다. 원문 삭제·보존 기간·구현상 컨텍스트 제외 방식은 이 질문에서 정하지 않습니다.

### FILE-03 지원 조건·처리 한계 — 사용자·공동 확인

Word 문서의 본문·표·삽입 이미지는 FILE-03-A A안으로 함께 분석 대상에 포함합니다. 파일만 보낸 첫 도움과 일부 자료를 읽지 못한 경우의 부분 검토는 FS-01·02 A안으로 합의했습니다. 파일별/요청별 용량·개수·문서 길이·이미지 품질의 제공 한도와 잠긴/손상된 파일 등 구체적 지원 조건은 아직 미정입니다. 실제 읽힌 범위·누락·영향을 안내하며 데모 값을 그대로 채택하지 않습니다.

#### FILE-03-A Word 문서의 분석 범위 — A 채택 / D-UF-085

**상황:** 펀딩 기획서 한 파일에 본문의 상품 설명, 표의 수량·원가, 삽입 이미지의 포장 시안이 함께 있습니다. 사용자가 “이 기획을 검토해 줘”라고 요청하면 어디까지 분석 대상으로 지원할 것인가?

| 대안 | 사용자 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 요청에 필요한 본문·표·삽입 이미지를 함께 분석 대상으로 지원하고 내용 간 연결을 검토 | 파일을 나눠 다시 제공하는 부담이 줄고 문서 맥락을 함께 볼 수 있지만 실제 확인 범위·처리하지 못한 부분의 안내가 중요해짐 |

사용자가 A를 채택했습니다. Word 파일의 요청에 필요한 본문·표·삽입 이미지를 함께 분석 대상으로 지원합니다. 기본 지원 범위를 본문·표로 제한해 삽입 이미지의 별도 재첨부를 항상 요구하지 않습니다. 실제 읽은 범위·누락·영향을 알리고 읽지 못한 내용이 필요한 판단은 단정하지 않는 기존 기준을 유지합니다.

모든 내부 요소의 완전한 처리·무제한 분석 보장은 아닙니다. 정확한 크기·개수·길이·품질 한도, 잠금/손상 등 지원 조건, 실제 추출·이미지 처리 기법은 이번 결정에서 확정하지 않습니다. 분석만으로 체크리스트 완료·기획 저장/확정이 되지 않습니다.

원문·분석 결과의 재방문·보존 기간·접근 권한·삭제 후 영향은 C-01·03 및 U-08과 공동 확인합니다. 활성 참조에서 빼는 기능을 원본 영구 삭제·모든 파생 기록 소거 보장으로 표시하지 않습니다. 지원 한도와 보존을 임의 값으로 채우지 않습니다.

## 7. 사용자 검토 기준

확정 요구의 검토 사례는 본문 AC-202~215에 연결합니다. 다음은 사용자 결과의 정합성 검토 기준이며 구현 통과 기록이 아닙니다. FS-04 A는 기존 원칙 적용 확인으로 기록하고 별도 신규 기능 사례를 늘리지 않습니다. 공동 계약의 미정은 별도로 추적합니다.

- 문서와 이미지를 제공한 사용자가 실제 처리한 범위·읽지 못한 부분·제안의 근거를 이해할 수 있는가?
- 활성 파일 목록·제거 후 새 파일 참조/과거 파일 정보의 자동 재사용 제외와 이력·사용자 채택/저장 결정 유지를 구분해 이해할 수 있는가?
- 실제 처리하지 못한 문서 내부 요소·흐릿한 사진 등에서 한계·누락 영향·다음 행동이 분명한가?
- 분석 결과를 수정·선택해 저장하거나, 저장 없이 설명만 얻고 종료하는 기존 흐름을 그대로 이용할 수 있는가?

### 7.1 다음 사용자 시나리오 검토

[사용자 시나리오 기록](file-and-image-user-scenarios.md)의 FS-01~03은 A 채택이고 FS-04 A는 기존 원칙 적용 확인입니다. 제공 조건·보존·권한의 공동 확인과 FS-CHECK-01의 기존 합의 연결 점검을 유지합니다. 이후 다른 사용자 목적별 기능의 합의·현재 쟁점은 [정리·완료 계획](user-feature-closure-plan.md)에서 추적합니다.

## 8. 후속 모듈 설계 경계

업로드 API·저장소·파일 판별, 텍스트 추출/문자 인식 라이브러리, 이미지 변환·모델 선택, 분할·요약·컨텍스트 조립, 도구 순서·재시도·비용 집행은 이 문서에서 정하지 않습니다. 사용자 결과와 지원 약속을 먼저 정한 뒤 기존 모듈 이관 대장의 M-01·05·06·08 등과 연결합니다. 원문 보존·삭제·제공 한도처럼 사용자 결과를 바꾸는 약속 자체는 모듈 설계로 넘겨 임의 확정하지 않습니다.
