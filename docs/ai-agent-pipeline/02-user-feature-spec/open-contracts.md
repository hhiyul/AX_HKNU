# AI 파이프라인 사용자 기능명세: 미정 계약

연결 문서: [사용자 기능명세 v0.1](ai-pipeline-user-feature-spec-v0.1.md) · 상태: **OPEN / 합의 대기**

이 문서는 기능 초안을 구현 가능한 계약으로 구체화할 때 필요한 쟁점을 관리합니다. 아직 없는 값·스키마·상태 전이·권한을 임의로 확정하지 않습니다. 각 항목의 합의 완료 조건은 합의 결과를 검토하기 위한 기준이며, 그 결과 자체가 아닙니다.

## OPEN-UF-01 시스템 기능·권한·업무 분담 연결

- **현재 기준:** 전체 백엔드와 프로젝트 구성·브랜드 생성은 팀원 담당, AI 채팅 파이프라인·하네스는 이 세션의 명세 범위입니다. 상위 시스템 기능명세는 아직 연결되지 않았습니다.
- **미정:** 사용자·계정·역할과 자원 접근 권한, 시스템 기능 ID, UI·백엔드·AI 기능별 책임과 실제 저장 권한의 담당 계약.
- **합의 완료 조건:** 사용자 기능을 시스템 기능에 추적할 수 있고, 누가 조회·실행·저장을 검증하는지 공동으로 식별할 수 있어야 합니다.

## OPEN-UF-02 6개 체크리스트의 세부 평가와 완료 조건

- **현재 기준:** 6개 항목의 개념과 독립적인 내용·저장 상태는 확인됐습니다. 평가 결과가 저장 상태를 자동 변경하지 않습니다.
- **미정:** 항목별 세부 질문·필수 입력·누락 판단·평가 근거·완료 조건, 내부 평가 결과의 표현, 확정 요청 시 필요한 검증 조건.
- **합의 완료 조건:** 같은 자료에서 무엇을 확인할 수 있고 무엇이 부족한지 평가·설명할 기준과 대표 반례가 있어야 합니다. 내부 평가와 사용자 결정 상태를 구분해야 합니다.

## OPEN-UF-03 컨텍스트 범위

- **현재 기준:** 독립 Chat과 프로젝트 연결 Chat이 있습니다. 필요한 프로젝트·브랜드·기획 항목을 조회해 참고하고 저장 상태와 새 제안을 구분합니다.
- **미정:** 한 대화의 연결 프로젝트 수·변경 가능 시점, 항목의 수동 선택과 AI 선택 범위, 브랜드·사진 자동 포함, 최근 대화·요약·이전 도구 결과의 포함·제외, 참조 해제 후 기존 대화에 남은 정보의 취급, 전송 범위 안내, 참조 시점과 버전.
- **합의 완료 조건:** 사용자 선택과 실제 모델 입력의 관계를 설명할 수 있어야 합니다. 연결 해제·권한 변경·자료 삭제 이후 무엇을 더 이상 사용할 수 없는지 정해야 합니다.

## OPEN-UF-04 첨부 처리·제한·참조 범위

- **현재 기준:** Chat과 프로젝트 사진의 첨부 기능을 추적하며, 파일 이름 등록과 실제 내용 처리를 구분합니다.
- **미정:** 허용 형식·용량·개수, 텍스트 추출·이미지 전달 방식, 처리 실패·일부 읽기 안내, 이번 메시지와 이후 메시지의 참조 범위, 원문 저장·삭제와 접근 권한.
- **합의 완료 조건:** 첨부 성공·내용 처리 성공·모델 참조 여부를 구분하고, 제외·실패·다시 열기 시의 사용자 결과를 정의해야 합니다. 데모의 2개·2MB를 기본값으로 확정하지 않습니다.

## OPEN-UF-05 웹 검색의 실행 조건·입력·근거

- **현재 기준:** 사용자가 검색어를 입력하고 결과를 선택하는 기능이 있습니다. 검색·선택만으로 체크리스트가 저장되지 않습니다.
- **미정:** 검색 도구·Provider, 검색 요청에 포함할 정보, 자동 검색의 허용 여부와 범위, 검색 횟수·결과 수·재사용, 출처·기준 시각·요약·인용과 비용 표시, 조회 실패·접근 불가 자료 처리.
- **합의 완료 조건:** 사용자가 실제 검색 여부와 참고한 자료를 알 수 있고, 자료가 뒷받침하는 주장과 AI·사용자 가설을 구분할 수 있어야 합니다.

## OPEN-UF-06 변경 제안·사용자 편집·반영 의도

- **현재 기준:** AI는 대상 항목과 편집 가능한 내용을 제안합니다. 사용자는 내용을 수정하거나 항목을 제외하고 초안 저장 또는 확정을 선택합니다.
- **미정:** 제안의 항목·내용·근거·기준 버전 구조, 여러 후보·여러 메시지의 제안 관리, 기존 내용과의 비교, 한 요청에서 항목별 다른 저장 의도를 허용할지, 저장/확정 선택을 전달할 UI와 요청 계약.
- **합의 완료 조건:** 사용자에게 표시한 대상·사용자 수정 내용·저장 의도가 서버가 검증하고 적용하는 내용과 일치해야 합니다. 모델의 응답·도구 요청이 사용자 선택을 대신하지 않아야 합니다.

## OPEN-UF-07 상태 전이·재편집·연관 항목 영향

- **현재 기준:** 저장 상태는 `UNSET / DRAFT / DECIDED`입니다. Figma에서 초안 저장 `UNSET / DECIDED → DRAFT`, 확정 `UNSET / DRAFT → DECIDED`를 확인했습니다. 대화·평가·제안만으로 상태가 바뀌지 않습니다.
- **미정:** DRAFT 재저장, DECIDED 수정·재확정, 항목 비우기·초기화, 한 항목의 변경이 다른 항목에 미치는 영향, 재검토 표시·유효성·승인 정책.
- **합의 완료 조건:** 사용자 동작별 허용 전이·거부 조건을 빈칸 없이 정의하고, 기존 결정을 새 정보만으로 조용히 덮어쓰지 않도록 해야 합니다. `UNSET`의 내용 표현이나 별도 재검토 상태도 임의로 추가하지 않습니다.

## OPEN-UF-08 여러 항목 저장·버전 충돌·부분 처리

- **현재 기준:** 사용자가 선택한 항목에만 반영하고, 서버가 권한·대상·버전을 검증합니다.
- **미정:** 버전의 단위, 여러 항목의 원자적 반영 또는 부분 처리, 저장 중 다른 편집·요청과의 충돌, 충돌 후 비교·재조회·재선택·재확인 방식.
- **합의 완료 조건:** 일부 항목만 반영되거나 충돌한 경우의 결과를 사용자에게 정확히 알릴 수 있어야 합니다. 전체 성공·전체 취소·부분 성공 중 어느 정책인지 명시하고 해당 반례를 검토해야 합니다.

## OPEN-UF-09 저장 결과 확인·응답 유실·중복 방지

- **현재 기준:** 저장 완료는 서버가 확인한 결과에 근거합니다. 응답 유실을 성공 또는 미반영으로 단정하지 않습니다.
- **미정:** 저장 요청의 식별·중복 방지, 결과 확인 수단, 재접속 후 조회 범위, 반복 클릭·시간 초과·결과 미확인 시의 다음 행동과 재반영 방지.
- **합의 완료 조건:** 서버 반영 후 응답만 사라지는 경우에도 같은 변경을 조용히 두 번 적용하지 않고 결과를 확인할 수 있어야 합니다. 요청 필드명·키·영수증 형식은 모듈·백엔드 계약에서 정합니다.

## OPEN-UF-10 실행·취소·재시도·재접속

- **현재 기준:** 사용자는 진행·종료·실패·취소 결과를 구분하고, 화면 이동·재접속만으로 새 유료 요청을 발생시키지 않습니다.
- **미정:** 실행 상태와 종료 조건, 추가 사용자 입력 대기, 동시 요청 범위, 취소 가능 시점과 완료 판단, 자동 재시도 허용 조건, 도구 결과의 재사용, 재시작 복구.
- **합의 완료 조건:** 요청 접수 전 실패, 도구 실행 중 취소, 모델 응답 후 취소, 재접속과 재전송을 구분하는 사용자 결과가 있어야 합니다. 내부 반복·도구 호출의 제한값은 별도로 정해야 합니다.

## OPEN-UF-11 실제 모델·인증·사용량·비용·제한

- **현재 기준:** 데모의 설정 저장·연결 테스트를 실제 Provider 연결 성공으로 취급하지 않습니다. 알 수 없는 사용량·비용을 0으로 표시하지 않습니다.
- **미정:** 지원 모델·Provider, 인증정보의 소유·보관·전달, 실행에 적용할 모델 설정의 시점, 모델별 도구·첨부 지원, 생성·검색 비용과 사용량의 기준, 허용 시간·횟수·금액 및 제한 도달 시 동작.
- **합의 완료 조건:** 설정 화면과 실제 실행의 관계, 사용량·비용의 확인 여부·추정 여부를 설명할 수 있어야 합니다. 프로토타입 모델 목록·가격·시도 한도·세션 TTL을 그대로 채택하지 않습니다.

## OPEN-UF-12 이력·초안·제안·내부 평가의 저장과 복구

- **현재 기준:** 대화, 내부 평가, 미저장 제안, 사용자 저장 초안, 확정 내용은 구분합니다. 현재 HTML에서는 미전송 텍스트가 새로고침 후 소실됐습니다.
- **미정:** 메시지·도구 결과·미전송 입력·첨부·사용자 수정 제안·내부 평가·실행 기록의 저장 여부, 보존 기간, 복원 범위, 이력 생략·요약·정정과 이전 형식 오류 처리.
- **합의 완료 조건:** 어떤 사용자 작업이 화면 이동·새로고침·재접속·삭제 뒤에도 복구되는지 알릴 수 있어야 합니다. 내부 평가 기록을 보존하는 것과 업무 체크리스트를 갱신하는 것을 구분해야 합니다.

## OPEN-UF-13 공통 관리·삭제·내보내기와 참조 처리

- **현재 기준:** 브랜드·프로젝트 관리와 전체 백엔드는 팀원 담당 범위입니다. Chat은 해당 자원과 연결되고 저장된 기획 내용을 다시 조회합니다.
- **미정:** 대화 이름·삭제·복원 정책, 프로젝트·브랜드·파일 삭제가 이력·실행·제안·체크리스트 참조에 미치는 영향, 내보내기에 포함할 내용·상태·근거·버전의 범위.
- **합의 완료 조건:** 실제 공통 기능과 AI 흐름의 경계를 연결해야 합니다. 옛 PLAN 데이터 중심의 내보내기·삭제 처리를 새 기획 모델의 동작으로 간주하지 않습니다.

## OPEN-UF-14 사용자 표시·피드백·응답 전달

- **현재 기준:** 대화·평가·제안·저장 결과와 현재 저장 상태를 구분해 사용자가 이해할 수 있어야 합니다.
- **미정:** 체크리스트의 표시 위치와 상세도, 제안 편집·비교·항목 선택 UI, 상태·오류·부분 처리 문구, 진행·완료 표시 시점, 스트리밍·조회 등 응답 전달 방식과 표시 갱신.
- **합의 완료 조건:** 사용자에게 보이는 성공 표시와 서버 저장 결과가 일치해야 합니다. 내부 API·도구 스키마를 알아야만 핵심 흐름을 사용할 수 있는 화면으로 만들지 않습니다.

## OPEN-UF-15 도구 목록과 계산·자료 검토 계약

- **현재 기준:** 필요한 조회·검색·계산 등의 검토 결과는 대화·평가·제안에 사용합니다. 모델의 도구 요청만으로 사용자 저장/확정 권한이 생기지 않습니다.
- **미정:** 실제 도구 목록과 입력·출력·실행 권한, 내부 평가에서의 도구 선택 조건, 계산의 입력·단위·산식·반올림·미확인 값 처리, 도구 실패·제한 시 검토 계속 여부와 결과 검증.
- **합의 완료 조건:** 대표 사용자 질문을 어떤 자료·도구로 검토하고, 실패하거나 자료가 부족할 때 무엇을 말할 수 있는지 정해야 합니다. PLAN-02의 옛 계산 필드와 상수를 새 도구 계약으로 자동 승계하지 않습니다.

## 합의 결과를 반영하는 방법

1. 사용자·AI 명세 담당·공통 백엔드 담당 사이에서 해당 사용자 결과와 반례를 검토합니다. 화면 계약은 실제 UI 담당과 연결합니다.
