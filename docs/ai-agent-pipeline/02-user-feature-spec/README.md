# 사용자 기능명세

펀딩을 준비하는 사용자가 무엇을 요청하고 어떤 결과를 얻는지 정의합니다. AI 파이프라인을 중심으로 Chat, 항목별 평가·제안, 사용자 선택 후 저장·확정의 흐름을 다룹니다.

**현재 상태: v0.1 초안 / 사용자 검토 중 · 일부 계약 결정 / 상위 시스템 기능명세 연결 대기.** 사용자의 명시적인 요청에 따라 현재 분석과 확인된 제품 기준을 근거로 먼저 작성했으며, 팀원의 시스템 기능명세가 준비되면 대조·연결합니다.

핵심 흐름은 `Chat → 관련 항목 평가·제안 → 사용자 수정·항목 선택 → 초안 저장 또는 확정 선택 → 서버 검증 → 내용·상태 갱신`입니다.

2026-10-30 결정 D-UF-001에 따라 프로젝트 연결 Chat의 체크리스트 저장 대상은 해당 프로젝트 하나로 고정합니다. 다른 프로젝트 작업은 새 Chat에서 시작합니다. D-UF-002에 따라 독립 Chat에서도 같은 대화에서 프로젝트를 최초 한 번 첨부하듯 연결하고 해당 프로젝트의 Projection 정보를 불러올 수 있습니다.

D-UF-003에 따라 연결 전 제안은 프로젝트의 Projection 정보를 바탕으로 재검토한 뒤 사용자가 내용·항목을 확인하고 저장·확정을 선택합니다. 재검토만으로 저장하지 않습니다. D-UF-004에 따라 프로젝트 연결 시 Projection은 불러오되 재검토는 자동 실행하지 않고 사용자가 명시적으로 요청할 때 실행합니다. 저장 시도만으로 재검토를 자동 실행하지도 않습니다.

D-UF-005에 따라 명시적인 재검토 요청에서 대상이 요청·문맥상 명확하면 추가 확인 없이 실행하고, 모호할 때만 질문으로 대상을 확인합니다. 최신 제안이나 전체 제안을 임의로 선택하지 않습니다.

D-UF-006에 따라 명시적인 재검토 요청의 대상이 정해지면, 재검토 시작 직전에 Projection을 다시 조회하고 그 결과를 재검토 자료로 사용합니다. 연결 당시 조회만으로 대신하지 않습니다.

D-UF-007에 따라 시작 직전 조회한 프로젝트 자료로 재검토를 완료하고 완료 시 변경 여부를 확인합니다. 변경이 확인된 해당 제안은 이전 정보 기반 결과로 표시해 저장을 보류하고 사용자의 명시적인 재요청을 받습니다. 기존 저장 내용·상태는 유지하며 변경만으로 자동 중단·재실행하지 않습니다.

D-UF-008에 따라 제안별 실제 입력·조회한 참조 자료 묶음과 그 버전으로 변경을 판정하고, 저장 대상 항목 버전도 별도로 검증합니다. Projection 전체를 AI에 전달했다면 전체 자료 묶음을 참조 범위에 포함하며 모델의 사후 설명으로 범위를 줄이지 않습니다.

D-UF-009에 따라 각 체크리스트의 내용·상태를 하나의 버전 묶음으로 관리하되, 내부에는 실제 사용자 문제를 해결할 하위 필드·질문·평가 기준을 둡니다. 버전 단위와 문제 분석 단위를 구분하며, 세부 필드 후보는 별도 검토안으로 관리합니다.

D-UF-010에 따라 고객 접점·판매 경로 가설을 CK-02 고객 선정의 하위 필드로 포함해 저장·평가 대상으로 관리합니다. D-UF-011에 따라 구매 상황별 고객 가설 안에서 구매자·사용자, 목적·상황, 접점·판매 경로와 접근 근거를 연결하고 같은 가설의 요소들이 서로 맞는지와 부족한 부분을 살펴봅니다. 버전·저장 상태는 CK-02 단위로 유지하며, 가설 개수·실제 저장 구조·필수 입력·충족·완료 기준은 미정입니다.

D-UF-012에 따라 고객 가설의 구체화 평가와 실제 검증을 분리합니다. 펀딩 준비 사용자에게 아직 없는 실측값·실제 고객 반응을 가설 구체화 완료의 필수 조건으로 요구하지 않으며, 가설·추정·미정과 확보한 근거를 구분합니다. 내부 평가가 자동 저장·확정이나 실제 검증 성공을 뜻하지는 않습니다.

D-UF-013에 따라 가설 구체화 완료에는 접점 후보와 해당 고객을 그 경로에서 만날 수 있다고 보는 이유가 필수입니다. 이유는 가설 수준이어도 되며 실제 접근 실적·반응은 비필수입니다. 이 요건을 Chat 진행·초안 저장 조건으로 자동 적용하지 않으며, 충족만으로 전체 완료·자동 저장·확정으로 취급하지 않습니다.

D-UF-014에 따라 참여·구매 목적도 필수로 두고 구체적인 계기·시점은 제안에 영향을 줄 때만 추가 확인합니다. 모든 가설에 특정 행사·날짜를 요구하거나 모르는 값을 임의로 채우지 않습니다. 나머지 정보의 필수 수준·전체 완료 판정은 미정입니다.

D-UF-015에 따라 사용 관계도 제안에 영향을 줄 때만 추가 확인하고, 그렇지 않으면 미정으로 남길 수 있습니다. 응원 목적만으로 사용자가 없다고 추정하지 않으며, 미정과 사용자 없음을 구분합니다. 대상 집단의 구체화 등 나머지 필수 정보·전체 완료 판정은 미정입니다.

나머지 세부 하위 필드·필수 수준·허용 미정·전체 충족 및 완료 판정, 접점·연결 이유의 구체적인 표현·품질 판단, 재검토 요청의 UX·의도 및 대상 식별의 세부 기준, 확인 질문의 응답·대기·취소, Projection의 필드·재검토 외 갱신·모델 입력 범위, 체크리스트 외 자료 묶음의 경계·버전 형식·참조 추적, 재조회 실패 시 복구·변경 확인 실패 시 처리, 완료 후 저장까지의 근거 재검증·충돌, 연결 전 이력·내부 평가의 모델 입력 취급 및 다른 프로젝트의 읽기 전용 참조는 아직 미정입니다.

확인된 제품 기준, 검토할 기능 초안, 미정 계약을 구분합니다. PLAN-01·PLAN-02는 폐기되었으며 사용자 기능으로 재도입하지 않습니다. 새 문서가 추가되어도 기존 분석 자료는 관찰 기록으로 유지합니다.

## 기능별로 정리할 내용

- 근거가 되는 시스템 기능명세의 문서 경로와 기능명 또는 기능 ID
- 기능을 사용하는 사용자와 달성하려는 목적
- 시작 조건과 사용자가 제공하는 입력
- 사용자가 거치는 흐름과 확인할 수 있는 진행 상태
- 최종 결과물과 완료 기준
- 사용자 관점의 실패, 중단, 재시도 조건
- 상위 명세와 추가로 확인해야 할 미정 사항

에이전트 내부 구현보다 사용자에게 보이는 동작을 먼저 정리합니다. 시스템 기능명세가 없는 부분은 미정으로 표시합니다.
