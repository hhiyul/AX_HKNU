# 사용자 기능명세

펀딩을 준비하는 사용자가 무엇을 요청하고 어떤 결과를 얻는지 정의합니다. AI 파이프라인을 중심으로 Chat, 항목별 평가·제안, 사용자 선택 후 저장·확정의 흐름을 다룹니다.

**현재 상태: v0.1 초안 / 사용자 검토 중 · 일부 계약 결정 / 상위 시스템 기능명세 연결 대기.** 사용자의 명시적인 요청에 따라 현재 분석과 확인된 제품 기준을 근거로 먼저 작성했으며, 팀원의 시스템 기능명세가 준비되면 대조·연결합니다.

핵심 흐름은 `Chat → 관련 항목 평가·제안 → 사용자 수정·항목 선택 → 초안 저장 또는 확정 선택 → 서버 검증 → 내용·상태 갱신`입니다.

2026-10-30 결정 D-UF-001에 따라 프로젝트 연결 Chat의 체크리스트 저장 대상은 해당 프로젝트 하나로 고정합니다. 다른 프로젝트 작업은 새 Chat에서 시작합니다. D-UF-002에 따라 독립 Chat에서도 같은 대화에서 프로젝트를 최초 한 번 첨부하듯 연결하고 해당 프로젝트의 Projection 정보를 불러올 수 있습니다.

D-UF-003에 따라 연결 전 제안은 프로젝트의 Projection 정보를 바탕으로 재검토한 뒤 사용자가 내용·항목을 확인하고 저장·확정을 선택합니다. 재검토만으로 저장하지 않습니다. D-UF-004에 따라 프로젝트 연결 시 Projection은 불러오되 재검토는 자동 실행하지 않고 사용자가 명시적으로 요청할 때 실행합니다. 저장 시도만으로 재검토를 자동 실행하지도 않습니다.

D-UF-005에 따라 명시적인 재검토 요청에서 대상이 요청·문맥상 명확하면 추가 확인 없이 실행하고, 모호할 때만 질문으로 대상을 확인합니다. 최신 제안이나 전체 제안을 임의로 선택하지 않습니다.

D-UF-006에 따라 명시적인 재검토 요청의 대상이 정해지면, 재검토 시작 직전에 Projection을 다시 조회하고 그 결과를 재검토 자료로 사용합니다. 연결 당시 조회만으로 대신하지 않습니다.

D-UF-007에 따라 시작 직전 조회한 프로젝트 자료로 재검토를 완료하고 완료 시 변경 여부를 확인합니다. 변경이 확인된 해당 제안은 이전 정보 기반 결과로 표시해 저장을 보류하고 사용자의 명시적인 재요청을 받습니다. 기존 저장 내용·상태는 유지하며 변경만으로 자동 중단·재실행하지 않습니다.

D-UF-008에 따라 제안별 실제 입력·조회한 참조 자료 묶음과 그 버전으로 변경을 판정하고, 저장 대상 항목 버전도 별도로 검증합니다. Projection 전체를 AI에 전달했다면 전체 자료 묶음을 참조 범위에 포함하며 모델의 사후 설명으로 범위를 줄이지 않습니다.

D-UF-009에 따라 각 체크리스트의 내용·상태를 하나의 버전 묶음으로 관리하되, 내부에는 실제 사용자 문제를 해결할 하위 필드·질문·평가 기준을 둡니다. 버전 단위와 문제 분석 단위를 구분하며, 세부 필드 후보는 별도 검토안으로 관리합니다.

D-UF-010에 따라 고객 접점·판매 경로 가설을 CK-02 고객 선정의 하위 필드로 포함해 저장·평가 대상으로 관리합니다. D-UF-011에 따라 구매 상황별 고객 가설 안에서 구매자·사용자, 목적·상황, 접점·판매 경로와 접근 근거를 연결하고 같은 가설의 요소들이 서로 맞는지와 부족한 부분을 살펴봅니다. 버전·저장 상태는 CK-02 단위로 유지하며, 가설 개수·실제 저장 구조·필수 입력·충족·완료 기준은 미정입니다.

D-UF-012에 따라 고객 가설의 구체화 평가와 실제 검증을 분리합니다. 펀딩 준비 사용자에게 아직 없는 실측값·실제 고객 반응을 가설 구체화 완료의 필수 조건으로 요구하지 않으며, 가설·추정·미정과 확보한 근거를 구분합니다. 내부 평가가 자동 저장·확정이나 실제 검증 성공을 뜻하지는 않습니다.

D-UF-013에 따라 가설 구체화 완료에는 접점 후보와 해당 고객을 그 경로에서 만날 수 있다고 보는 이유가 필수입니다. 이유는 가설 수준이어도 되며 실제 접근 실적·반응은 비필수입니다. 이 요건을 Chat 진행·초안 저장 조건으로 자동 적용하지 않으며, 충족만으로 전체 완료·자동 저장·확정으로 취급하지 않습니다.

D-UF-014에 따라 참여·구매 목적도 필수로 두고 구체적인 계기·시점은 제안에 영향을 줄 때만 추가 확인합니다. 모든 가설에 특정 행사·날짜를 요구하거나 모르는 값을 임의로 채우지 않습니다. 나머지 정보의 필수 수준·전체 완료 판정은 미정입니다.

D-UF-015에 따라 사용 관계도 제안에 영향을 줄 때만 추가 확인하고, 그렇지 않으면 미정으로 남길 수 있습니다. 응원 목적만으로 사용자가 없다고 추정하지 않으며, 미정과 사용자 없음을 구분합니다.

D-UF-016에 따라 대상을 구별할 특성·관계는 가설 구체화 완료에 필수입니다. 관심·행동·역할·창작자와의 관계 등은 설명 방식의 예시이며 모두 작성할 필요는 없습니다. 연령·성별·직업 등은 제안에 영향을 줄 때만 추가 확인하며, 이미 대화에서 파악한 내용을 반복 질문하거나 정형 페르소나를 일괄 요구하지 않습니다. 필수 기준은 사용자 직접 입력 목록이 아니며, 나머지 필수 정보·전체 완료 판정은 미정입니다.

D-UF-017에 따라 중요한 정보가 미정이면 조건별 제안을 제공하고 해당 고객 가설 전체의 구체화 완료는 보류합니다. 구체화된 부분과 남은 미정 사항·영향을 설명하며 Chat과 부분 제안은 계속합니다. 같은 미정 질문을 표현만 바꿔 반복하지 않고, 내부 완료 보류를 저장 상태 변경이나 다른 체크리스트의 보류로 자동 확대하지 않습니다. 중요성 판단은 D-UF-018을 따르며 보류 해제·재평가·상황 변화 후 재질문·기록의 세부 기준은 미정입니다.

D-UF-018에 따라 조건부 확인 정보는 추천 대상·접점·구성·핵심 메시지·실행 조건 등 핵심 선택이 달라질 때만 중요하게 봅니다. AI는 어떤 선택이 어떻게 달라지는지 설명해야 하며, 단순한 말투·표현·개인화 차이만으로 추가 확인이나 완료 보류를 요구하지 않습니다. 기존 대상·목적·접점의 필수 요건과 반복 질문 방지 기준은 유지합니다. 재질문 조건은 D-UF-019를 따르며 설명의 세부 품질·경계 사례와 재평가의 시점·조건 등은 미정입니다.

D-UF-019에 따라 같은 미정 사항의 재질문은 사용자가 그 사항을 다시 다루도록 요청했거나 관련 상황의 실질적인 변화로 질문의 필요성·영향이 달라졌을 때만 이유를 설명하고 수행합니다. 시간 경과·대화 진행·미정 값의 존재만으로 반복하지 않고, 이미 답을 확인할 수 있으면 활용합니다. 여전히 모르면 조건별 제안과 Chat을 이어가며 재질문 자체로 평가 보류를 해제하거나 저장·확정하지 않습니다. 새 정보에 따른 관련 평가 갱신은 D-UF-020을 따르며 상황 변화·사용자 요청의 세부 식별·설명 품질과 나머지 재평가 계기·범위·기록·복구 등은 미정입니다.

D-UF-020에 따라 진행 중인 Chat에서 새 정보를 받으면 그 정보의 영향을 받는 기준과 남은 보류 사유를 같은 응답에서 갱신합니다. 별도의 평가 요청을 필수로 요구하지 않고 해소된 사유와 남은 사유를 구분합니다. 평가 갱신만으로 저장된 내용·상태를 바꾸지 않으며, 연결 전 제안의 프로젝트 기반 재검토는 기존 명시적 요청 원칙을 유지합니다. 기본 안내·상세 제공은 D-UF-021을 따르며 전체 완료·보류 해제의 세부 충족 조건과 다른 재평가 계기·범위·실패 처리, 정확한 표시 형식·기록·복구는 미정입니다.

D-UF-021에 따라 평가 갱신의 기본 응답은 변경된 평가와 남은 보류 사유를 짧게 안내하고, 상세 기준별 결과는 사용자 요청 시 제공합니다. 짧은 안내에도 전체 구체화 완료의 보류 여부와 남은 사유가 드러나야 합니다. 전체 기준별 평가표를 매번 기본 표시하거나 상세 제공을 저장·확정으로 취급하지 않습니다. 정확한 길이·문구·위치·형식과 상세 요청의 UX·범위, 결과의 기준 시점·최신성 안내·기록·복구는 미정입니다. 표시 원칙의 상세 결정은 OPEN-UF-14에서 관리합니다.

D-UF-022에 따라 고객 선정의 전체 구체화 완료 판정에는 실제 진행 대상으로 정한 가설만 포함합니다. 진행 대상이 여러 개면 모두 평가하며, 미선택 비교 후보의 미정 자체는 전체 완료를 막지 않습니다. 진행 대상에 영향을 주는 공통 정보·중요한 미정은 계속 평가합니다. 대상 지정은 D-UF-023을 따르며 변경의 세부 규칙과 실제 저장 구조·전체 완료의 세부 충분조건은 미정입니다. 범위 결정만으로 후보를 삭제하거나 저장 내용·상태를 바꾸지 않습니다.

D-UF-023에 따라 사용자의 진행 의사와 대상·범위가 명확하면 추가 확인 없이 평가 범위에 반영하고 모호할 때만 확인합니다. 단순한 긍정·AI 추천·최근 언급만으로 진행 선택을 대신하지 않습니다. 반영한 대상을 짧게 안내하며 진행 대상 지정과 저장·확정은 구분합니다. 이전 진행 가설의 취급은 D-UF-024를 따르며 의도·대상 식별의 세부 기준·UX, 추가·대체의 나머지 규칙과 실제 선택 정보의 기록·복구는 미정입니다.

D-UF-024에 따라 진행 대상에서 빠진 이전 가설은 현재 작업의 비교 후보로 남겨 다시 검토·선택할 수 있게 합니다. 비교 후보의 미정 자체는 전체 완료를 막지 않으며 대상 변경·후보 유지·재선택만으로 저장된 내용·상태를 바꾸지 않습니다. 재선택 시 전체 재평가는 D-UF-025를 따르며 참조 자료의 갱신·조회와 실제 후보 표시·정리·별도 삭제·보관 기간·영속 기록·복구는 미정입니다.

D-UF-025에 따라 이전 가설을 재선택하면 현재 대화·참조 자료로 해당 가설의 전체 기준과 남은 보류 사유를 같은 응답에서 다시 평가합니다. 별도 평가 요청을 필수로 요구하지 않고 과거 판정의 승계나 변경 부분만의 평가로 대체하지 않습니다. 기존 필수 수준·미정 허용과 짧은 안내·요청 시 상세 제공, 저장·확정 선택 및 서버 검증은 유지합니다. 프로젝트 연결 Chat의 재조회 시점은 D-UF-026을 따르며 정확한 필드·조회 범위·모델 입력과 그 밖의 갱신·실패·미완료·자료 변경 처리는 미정입니다.

D-UF-026에 따라 프로젝트 연결 Chat의 재선택 평가는 대상·범위가 명확해진 뒤 실제 평가 시작 직전에 같은 프로젝트의 Projection을 다시 조회하고 그 자료로 전체 기준·남은 보류 사유를 평가합니다. 연결 당시나 확인 질문 전 자료로 대신하지 않으며 조회·평가만으로 저장된 내용·상태를 바꾸지 않습니다. 독립 Chat의 프로젝트 연결을 필수화하지 않습니다. 재조회 실패의 기본 처리는 D-UF-027을 따르며 재시도·평가 재개, 정확한 필드·모델 입력과 자료 변경의 세부 처리는 미정입니다. 조회 시점의 상세 결정은 OPEN-UF-03에서 관리합니다.

D-UF-027에 따라 재선택 평가의 Projection 재조회가 실패하면 해당 평가를 보류하고 재시도를 안내하되 Chat과 부분 제안은 계속할 수 있습니다. 이전 자료로 평가 완료를 대신하지 않고 이용 가능한 자료·확인 한계를 구분하며 실패·보류·부분 제안만으로 저장된 내용·상태를 바꾸지 않습니다. 보류 후 재시도 실행은 D-UF-028을 따르며 요청의 세부 식별·UX와 성공 후 평가 재개·동시 요청·기록·복구는 미정입니다. 실패 처리의 상세 결정은 OPEN-UF-10에서 관리합니다.

D-UF-028에 따라 보류 안내 후에는 사용자가 명시적으로 재시도를 요청할 때만 실패한 Projection 조회를 다시 시도합니다. 재시도 안내·연결 회복·시간 경과·다른 대화만으로 자동 재시도하지 않으며 요청·재조회만으로 저장된 내용·상태를 바꾸지 않습니다. 성공 후 동일하고 명확한 대상의 재개는 D-UF-029를 따르며 요청의 세부 식별·UX와 대상 변경·동시 요청·기록·복구는 미정입니다.

D-UF-029에 따라 재시도 조회가 성공하고 보류했던 평가 대상이 그대로이며 명확하면 추가 확인 없이 같은 응답에서 새 자료로 해당 가설의 전체 기준·남은 보류 사유를 재평가합니다. 과거 판정을 승계하거나 일부 기준만 평가하지 않으며 기존 짧은 안내·요청 시 상세 제공과 저장·확정 선택·서버 검증을 유지합니다. 진행 대상에서 빠진 가설의 보류 평가는 D-UF-030을 따르며 그 밖의 변경·불명확 시 처리와 세부 식별·동시 요청·실패·자료 변경·기록·복구는 미정입니다.

D-UF-030에 따라 진행 대상에서 빠진 가설의 보류 평가는 종료하고 가설은 비교 후보로 유지합니다. 다시 선택하면 종료된 보류 평가를 재개하는 대신 현재 자료로 새로 평가하며 D-UF-025·026을 따릅니다. 종료·재선택·새 평가만으로 저장된 내용·상태를 변경하지 않습니다.

나머지 세부 하위 필드·필수 수준·허용 미정·전체 충족 및 완료 판정, 접점·연결 이유의 구체적인 표현·품질 판단, 재검토 요청의 UX·의도 및 대상 식별의 세부 기준, 확인 질문의 응답·대기·취소, Projection의 필드·재검토 외 갱신·모델 입력 범위, 체크리스트 외 자료 묶음의 경계·버전 형식·참조 추적, 재조회 실패 시 복구·변경 확인 실패 시 처리, 완료 후 저장까지의 근거 재검증·충돌, 연결 전 이력·내부 평가의 모델 입력 취급 및 다른 프로젝트의 읽기 전용 참조는 아직 미정입니다.

확인된 제품 기준, 검토할 기능 초안, 미정 계약을 구분합니다. PLAN-01·PLAN-02는 폐기되었으며 사용자 기능으로 재도입하지 않습니다. 새 문서가 추가되어도 기존 분석 자료는 관찰 기록으로 유지합니다.

## 기능별로 정리할 내용

- 근거가 되는 시스템 기능명세의 문서 경로와 기능명 또는 기능 ID
- 기능을 사용하는 사용자와 달성하려는 목적
- 시작 조건과 사용자가 제공하는 입력
- 사용자가 거치는 흐름과 확인할 수 있는 진행 상태
- 최종 결과물과 완료 기준
- 사용자 관점의 실패, 중단, 재시도 조건
- 상위 명세와 추가로 확인해야 할 미정 사항

에이전트 내부 구현보다 사용자에게 보이는 동작을 먼저 정리합니다. 시스템 기능명세가 없는 부분은 미정으로 표시합니다.
