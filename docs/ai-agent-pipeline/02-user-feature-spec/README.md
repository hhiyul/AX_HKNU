# 사용자 기능명세

펀딩을 준비하는 사용자가 AI Chat에 무엇을 요청하고 어떤 결과를 얻으며 무엇을 선택·저장하는지 정의합니다.

**현재 상태: v0.1 초안 / P0 사용자 기능 Grill 재개 / 일부 계약 결정 / 사용자 기능 미완료 / 상위 시스템 연결 대기.** 2026-11-02 사용자 요청으로 대표 흐름부터 검토를 재개했습니다. 기존 합의는 유지하고, 사용자 기능의 남은 쟁점을 먼저 정리하며 모듈 설계는 뒤로 미룹니다.

## 현재 먼저 정리할 범위

| 우선순위 | 사용자 기능에서 남은 일 |
| --- | --- |
| P0 | 대표 흐름, 여섯 항목의 목적·필수 정보·허용 미정·결과·완료 기준, 제안 수정·선택·저장·확정·재편집, 항목 간 영향 |
| P1 | 대표 실패·취소·충돌·결과 미확인, 파일·웹·프로젝트 자료 활용, 이력·복구·삭제·내보내기·설정 |
| 공동 확인 | 권한·공통 데이터와 팀원 기능, 가격·원가의 사업 기준, 서비스 지원·이용 제한·보존 보장 |
| 후속 모듈 | Projection·모델 입력·버전·실행 상태·도구·저장·전달의 실제 구조와 구현 계약 |

우선순위는 문서 검토 순서이며 사용자에게 여섯 항목의 작성 순서를 강제하는 것이 아닙니다. 기술 용어가 들어가도 사용자 결과를 바꾸는 의미는 사용자 기능·공통 계약에서 먼저 정합니다.

## 기존 합의와 미정의 취급

D-UF-001~055는 모두 유효합니다. 프로젝트 저장 대상 고정·최초 연결·명시적 재검토, 고객·목적·접점의 가설과 필수 수준·미정 취급, 평가 갱신·진행 대상·재선택, 이미 정한 재조회·버전·보류·재시도·종료 원칙을 유지합니다. D-UF-031~033은 막연한 고민의 첫 도움, 구체안의 제안, 프로젝트 생성·같은 Chat 복귀의 흐름입니다. D-UF-034는 내부 미완료와 사용자 명시적 확정의 분리, D-UF-035~037과 D-UF-039는 CK-01·03·04·06의 일부 필수 수준, D-UF-038은 비용 미정 시 계산 응답 범위, D-UF-040은 선택한 변경 범위 반영, D-UF-041은 저장·확정의 사용자 명시적 UI 선택 필수 원칙입니다. D-UF-042는 확정 내용의 수정안을 UI에서 명시적으로 재확정하면 중간 초안 없이 검증·반영하는 경로입니다. D-UF-043은 체크리스트별로 초안·확정을 UI에서 명시적으로 선택한 뒤 함께 반영할 수 있다는 결정입니다. D-UF-044는 검증을 통과하고 저장 보류가 없는 항목만 부분 반영하고 항목별 결과·미반영 사유를 구분해 안내하는 원칙입니다. D-UF-045는 실제 영향이 확인된 다른 항목의 영향·이유·다음 검토를 변경 결과와 함께 짧게 안내하며 다른 항목의 저장 내용·상태는 자동 변경하지 않는 원칙입니다. D-UF-046은 미저장 편집안을 유지하고 새 AI 제안을 별도 후보로 비교한 뒤 필요한 부분만 명시적으로 가져오는 원칙입니다. D-UF-047은 CK-05의 판매 단위에 적용할 기획용 가격·범위를 필수로 두되 최종 판매가 확정은 요구하지 않고 기존 비용 미정·판단 보류를 유지하는 결정입니다. D-UF-048은 중요한 비용 미정 시 CK-05 전체 구체화 완료를 보류하되 설명 가능한 기획용 추정·범위를 허용하고 실제 견적·실측값은 강제하지 않는 결정입니다. D-UF-049는 판매가격·구성·제작 규모·진행 여부에 미치는 영향으로 비용의 중요성을 판단하고 AI가 구체적인 영향·이유를 설명하는 결정입니다. D-UF-050은 CK-06 핵심 구성품의 제작·조달 방식 가설을 필수로 두고 업체 확정·계약·실제 제작 검증은 요구하지 않는 결정입니다. D-UF-051은 현재 자료·사용자 설명에서 확인된 제작 방식·규모·일정의 명백한 충돌에 대해 CK-06 전체 구체화 완료를 보류하고 이유·조정 대안을 제시하되 실제 제작 검증은 강제하지 않는 결정입니다. D-UF-052는 CK-01 상품 선정 이유를 비교·추천·범위 조정에 영향을 줄 때만 확인하되 CK-03의 고객 참여·구매 이유 필수 원칙은 유지하는 결정입니다. D-UF-053은 판매 대상·범위의 충분한 식별·일관성과 중요한 선택 미정·충돌 없음을 CK-01 전체 구체화 완료 기준으로 합의한 결정이며 최종 규격·옵션·가격 확정은 요구하지 않습니다. 다른 항목의 완료·저장 상태 및 전체 사용자 기능 완료와는 구분합니다. D-UF-054는 실제 진행 고객 가설 모두의 기존 요건·대상/목적/접점 연결·일관성과 중요한 미정/충돌 없음을 CK-02 전체 구체화 완료 기준으로 합의하고 첫 접근·판매 실험 계획은 후속 제안으로 구분한 결정입니다. 기존 조회·평가 보류·저장 분리는 유지합니다. D-UF-055는 CK-03~06의 실제 진행안만 전체 완료 평가에 포함하되 공통 영향 정보는 유지하는 결정입니다. 각 항목의 전체 완료 충분조건을 모두 정한 것은 아니며 현재 P0 진척과 종료 작업은 정리·완료 계획 9절에서 점검합니다. 세부 내용을 본문에서 줄인 것은 폐기나 재선택이 아닙니다.

**D-UF-041의 최종 채택은 B안입니다.** Chat에서 내용·반영 범위를 준비할 수 있지만 명확한 저장·확정 요청도 별도 UI 선택을 대신하지 않습니다. 초안인지 확정인지는 반드시 사용자가 명시적으로 선택하며 AI가 대신 정하지 않습니다.

기존 미정 원문은 계층이 섞여 있으므로 정리·완료 계획에서 사용자·공통·모듈 부분을 나눠 읽습니다. 모든 OPEN-UF와 기술 미정이 사라져야 사용자 기능이 완료되는 것은 아니며, 이번 정리로 어떤 OPEN 항목 전체를 완료 처리하지도 않습니다.

시스템 기능명세가 준비되면 상위 추적 관계를 연결합니다. 현행 UF ID는 문서 식별자이며 API·DB·도구 이름이 아닙니다. 실제 모듈 구성·에이전트 수·프레임워크·실행 한도는 아직 확정하지 않습니다.
