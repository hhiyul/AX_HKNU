# 사용자 기능명세

펀딩을 준비하는 사용자가 AI Chat에 무엇을 요청하고 어떤 결과를 얻으며 무엇을 선택·저장하는지 정의합니다.

**현재 상태: v0.1 초안 / P0 사용자 기능 Grill 재개 / 일부 계약 결정 / 사용자 기능 미완료 / 상위 시스템 연결 대기.** 2026-11-02 사용자 요청으로 대표 흐름부터 검토를 재개했습니다. 기존 합의는 유지하고, 사용자 기능의 남은 쟁점을 먼저 정리하며 모듈 설계는 뒤로 미룹니다. 2026-11-03 사용자 정정에 따라 기존 합의 적용과 새로운 사용자 선택을 구분합니다. 파일·이미지의 D-UF-081~088은 보존하고 FS-04 A는 D-UF-089의 기존 원칙 적용 확인으로 기록합니다. EXPORT-01 A / D-UF-090으로 기본 내보내기 범위를 합의했습니다. RESUME-01 A / D-UF-091은 브라우저 인메모리로 합의했습니다. 실행이 유지되는 화면 이동·복귀 범위이며 새로고침·탭 종료 후 복원은 보장하지 않습니다. HISTORY-01 A / D-UF-092는 경량화해 저장 이력을 편집 가능한 문서로 열고 직접 수정하는 범위로 합의했습니다. 별도 전후 비교 UI는 제공 범위에서 제외합니다.

## 현재 먼저 정리할 범위

2026-11-03 사용자 요청으로 파일·이미지 첨부의 사용자 기능을 별도 검토합니다. 기존 P1 자료 확장 중 사용자가 지정한 현재 작업이며 아래의 기존 P0 보류·공동 확인은 유지합니다. 파일의 참조 지속·제거를 프로젝트 Chip 정책으로 대신 확정하지 않습니다.

| 우선순위 | 사용자 기능에서 남은 일 |
| --- | --- |
| P0 | 웹 검색·프로젝트 컨텍스트 Chip의 실행/참조/표시 계약, 대표 흐름, 여섯 항목의 필수 정보·허용 미정·완료 기준, 제안 수정·선택·저장·재편집·항목 간 영향 |
| P1 | 대표 실패·취소·충돌·결과 미확인의 상세 흐름, 파일 등 나머지 자료 확장, 이력·복구·삭제·내보내기·설정. 웹 검색·프로젝트 Chip의 기본 사용자 계약은 P0에서 다룸 |
| 공동 확인 | 권한·공통 데이터와 팀원 기능, 가격·원가의 사업 기준, 서비스 지원·이용 제한·보존 보장 |
| 후속 모듈 | Projection·모델 입력·버전·실행 상태·도구·저장·전달의 실제 구조와 구현 계약 |

우선순위는 문서 검토 순서이며 사용자에게 여섯 항목의 작성 순서를 강제하지 않습니다. 사용자 결과를 바꾸는 의미는 사용자 기능·공동 계약에서 먼저 정합니다. 2026-11-02 사용자 추가 지시에 따른 현재 작업 순서는 웹 검색·프로젝트 컨텍스트 Chip의 사용자 계약(U-07의 P0 부분) → 재저장·제안 가져오기·연관 검토의 잔여 흐름(U-03~05) → CK-03~06 완료 기준(U-02) → 자료 사용을 포함한 대표 흐름 연결 검토(U-01)입니다. 세부 수정은 정리·완료 계획 8·9절과 현재 P0 질문지를 따릅니다. 프로젝트 섹션별 컨텍스트 관리의 내부 구성은 모듈 기능명세 M-01에서 다룹니다.

## 기존 합의와 미정의 취급

D-UF-001~080의 원문·근거를 보존합니다. 현행 적용은 D-UF-063·064의 참조 분리·프로젝트 선행/1:1과 부분 대체 범위를 우선하며 나머지 합의는 유지합니다. 프로젝트 저장 대상 고정·최초 연결·명시적 재검토, 고객·목적·접점의 가설과 필수 수준·미정 취급, 평가 갱신·진행 대상·재선택, 이미 정한 재조회·버전·보류·재시도·종료 원칙을 유지합니다. D-UF-031·032는 첫 도움·구체안 제안이며 D-UF-033의 독립 Chat 생성/복귀 경로는 D-UF-064로 대체됐습니다. D-UF-034는 내부 미완료와 사용자 명시적 확정의 분리, D-UF-035~037과 D-UF-039는 CK-01·03·04·06의 일부 필수 수준, D-UF-038은 비용 미정 시 계산 응답 범위, D-UF-040은 선택한 변경 범위 반영, D-UF-041은 저장·확정의 사용자 명시적 UI 선택 필수 원칙입니다. D-UF-042는 확정 내용의 수정안을 UI에서 명시적으로 재확정하면 중간 초안 없이 검증·반영하는 경로입니다. D-UF-043은 체크리스트별로 초안·확정을 UI에서 명시적으로 선택한 뒤 함께 반영할 수 있다는 결정입니다. D-UF-044는 검증을 통과하고 저장 보류가 없는 항목만 부분 반영하고 항목별 결과·미반영 사유를 구분해 안내하는 원칙입니다. D-UF-045는 실제 영향이 확인된 다른 항목의 영향·이유·다음 검토를 변경 결과와 함께 짧게 안내하며 다른 항목의 저장 내용·상태는 자동 변경하지 않는 원칙입니다. D-UF-046은 미저장 편집안을 유지하고 새 AI 제안을 별도 후보로 비교한 뒤 필요한 부분만 명시적으로 가져오는 원칙입니다. D-UF-047은 CK-05의 판매 단위에 적용할 기획용 가격·범위를 필수로 두되 최종 판매가 확정은 요구하지 않고 기존 비용 미정·판단 보류를 유지하는 결정입니다. D-UF-048은 중요한 비용 미정 시 CK-05 전체 구체화 완료를 보류하되 설명 가능한 기획용 추정·범위를 허용하고 실제 견적·실측값은 강제하지 않는 결정입니다. D-UF-049는 판매가격·구성·제작 규모·진행 여부에 미치는 영향으로 비용의 중요성을 판단하고 AI가 구체적인 영향·이유를 설명하는 결정입니다. D-UF-050은 CK-06 핵심 구성품의 제작·조달 방식 가설을 필수로 두고 업체 확정·계약·실제 제작 검증은 요구하지 않는 결정입니다. D-UF-051은 현재 자료·사용자 설명에서 확인된 제작 방식·규모·일정의 명백한 충돌에 대해 CK-06 전체 구체화 완료를 보류하고 이유·조정 대안을 제시하되 실제 제작 검증은 강제하지 않는 결정입니다. D-UF-052는 CK-01 상품 선정 이유를 비교·추천·범위 조정에 영향을 줄 때만 확인하되 CK-03의 고객 참여·구매 이유 필수 원칙은 유지하는 결정입니다. D-UF-053은 판매 대상·범위의 충분한 식별·일관성과 중요한 선택 미정·충돌 없음을 CK-01 전체 구체화 완료 기준으로 합의한 결정이며 최종 규격·옵션·가격 확정은 요구하지 않습니다. 다른 항목의 완료·저장 상태 및 전체 사용자 기능 완료와는 구분합니다. D-UF-054는 실제 진행 고객 가설 모두의 기존 요건·대상/목적/접점 연결·일관성과 중요한 미정/충돌 없음을 CK-02 전체 구체화 완료 기준으로 합의하고 첫 접근·판매 실험 계획은 후속 제안으로 구분한 결정입니다. 기존 조회·평가 보류·저장 분리는 유지합니다. D-UF-055는 CK-03~06의 실제 진행안만 전체 완료 평가에 포함하되 공통 영향 정보는 유지하는 결정입니다. 각 항목의 전체 완료 충분조건을 모두 정한 것은 아니며 현재 P0 진척과 종료 작업은 정리·완료 계획 9절에서 점검합니다. D-UF-056은 가져오기 대상이 명확하면 그대로 적용하고 모호하면 반영을 보류한 채 먼저 확인하며 대상 확인과 실제 저장·확정을 구분하는 결정입니다. D-UF-057은 실제 영향은 즉시 안내하되 연관된 저장 기획의 후속 검토는 명시적 사용자 요청 후 시작하고 일반 대화·기존 내부 평가 갱신·부분 제안과 실제 저장 경계는 유지하는 결정입니다. D-UF-058은 현재 초안의 선택한 변경 범위만 갱신하고 서버 확인 후 DRAFT를 유지하며 기존 UI 선택·검증·저장 보류 규칙을 유지하는 결정입니다. D-UF-059은 변경 영향 중심의 기본 후속 검토 범위를 필수 영향 안내 UX 강화 조건과 함께 채택하고, 요청 시 항목 전체 검토·검토 범위/남은 사항의 명시·저장 경계 유지를 정한 결정입니다. D-UF-060은 Q-LATEST-01 B안인 최신 결정의 변경 요약·사용자 편집안 반영 선택, D-UF-061은 Q-LATEST-02 A안인 저장 종류 유지·갱신된 내용에 대한 사용자 최종 반영 단추를 정했습니다. 실제 저장 흐름에서 별도 중간 적용·종류 재선택을 필수로 요구하지 않습니다. D-UF-062는 WEB-01 A안인 Chat의 명시적 검색 허용 후 필요한 검색의 AI 실행·사용자 이후 끄기·검색 상태 표시를 정했습니다. 검색 입력의 기본 범위는 후속 D-UF-067을 따르고 결과 선택·근거 표시는 후속 D-UF-068을 따르고 제한과 구체적인 표시 UX 등은 계속 미정이며 Chip 실제 참고/누락 안내와 부분 제안은 후속 D-UF-069를 따릅니다. D-UF-063은 CHIP-01 A안인 프로젝트 Chip의 참조 첨부·저장 연결 분리와 다른 프로젝트 참조를, D-UF-064는 프로젝트 생성 선행·프로젝트와 AI Chat 1:1을 정했습니다. 독립 Chat 사후 연결과 Chat에서 생성 후 복귀 경로는 D-UF-064로 대체하며 기존 원문은 보존합니다. D-UF-065는 CHIP-02 A안인 제거 전까지 Chat의 활성 참조 유지·제거 후 이후 활성 참조 제외를 정했습니다. 과거 B 정보 재사용은 후속 D-UF-066을 따르며 기존 A 결정·저장 내용과 실제 참조 버전 검증은 유지합니다. D-UF-066은 과거 이력을 유지하면서 제거한 B 고유 정보의 자동 재사용은 제외하고 A에 저장했거나 명시적으로 채택한 결정은 유지하도록 정했습니다. D-UF-067은 WEB-02 A안인 일반화된 특성과 사용자가 검색 사용을 명시한 내용만 기본 검색 입력에 포함하는 결정을 정했습니다. 내부 참고·A 저장/채택을 외부 전송 허용으로 간주하지 않습니다. D-UF-068은 WEB-03 A안인 필요한 검색 결과의 AI 선택과 핵심 주장별 출처·확인 범위·한계 표시, 사용자 자료 제외·추가 검토 요청을 정했습니다. 검색 근거와 기획 가설·현재 사용자 결정·실제 저장은 구분합니다. D-UF-069는 CHIP-03 A안인 실제 참고 범위·누락 영향 안내와 가능한 부분 제안 지속, 읽지 못한 자료가 필요한 판단 보류를 정했습니다. 기존 Projection 조회 실패·명시적 재시도 규칙은 유지합니다. D-UF-070은 WEB-04 A안인 허용 범위 내 AI 보완 검색과 진전 없음/한도 도달 시 중단, 확인 내용·남은 한계·보류 판단 안내를 정했습니다. 기존 검색 허용/끄기·입력 범위·Projection 명시적 재시도·저장 경계는 유지합니다. D-UF-071은 WEB-05 A안인 검색 끄기 후 도착한 결과의 현재 답변 새 근거 제외와 기존 자료 기반 답변·보류 판단 안내, 실제 검색 취소와의 구분을 정했습니다. D-UF-072는 WEB-06 A안인 검색 끄기 전 확인 자료의 출처·확인 시점·한계와 함께 재사용, 최신 확인이 필요한 판단 보류를 정했습니다. 새 검색 금지·늦은 결과 제외·자료 제외/권한·기획/저장 경계는 유지합니다. D-UF-073은 WEB-07 A안인 해당 Chat에서 재허용 전까지 자료 제외 유지·사용자 명시 적용 범위 우선·기존 기획/저장 상태 자동 변경 금지를 정했습니다. 웹 검색·Chip 기본 동작의 합의와 잔여 공동/후속 계약을 구분하고 D-UF-074는 SAVE-01 A안인 한 항목 전체 비우기 후 내용 없음/UNSET 복귀·최종 선택 전 확정 해제 영향 안내·다른 항목 자동 변경 금지를 정했습니다. 기존 권한/대상/버전 검증·저장 보류·서버 확인은 유지합니다. D-UF-075는 SAVE-02 A안인 저장 결과 미확인 안내·자동 결과 확인·확인된 결과 또는 미확인 안내를 정했습니다. 같은 변경의 자동 재전송과 기존 기획/편집/저장 상태의 임의 변경은 하지 않습니다. 2026-11-03 사용자 지시로 이후 검토는 대표 사용자 흐름의 목적·요청·보이는 결과·선택에 한정하고 실행 세부는 모듈 설계로 미룹니다. 새 세부 Grill 질문은 추가하지 않습니다. 요약 생략과 명시적인 후속 대체를 구분합니다. D-UF-076~080은 대표 흐름 질문 5문항의 A 채택으로 연결된 기획 대안과 CK-03~06 전체 완료 기준을 정했습니다. 기존 부분 가져오기 보류는 해소하지 않으며 실제 프로젝트 평가/저장 완료나 전체 P0 완료를 뜻하지 않습니다.

**D-UF-041의 최종 채택은 B안입니다.** Chat에서 내용·반영 범위를 준비할 수 있지만 명확한 저장·확정 요청도 별도 UI 선택을 대신하지 않습니다. 초안인지 확정인지는 반드시 사용자가 명시적으로 선택하며 AI가 대신 정하지 않습니다.

기존 미정 원문은 계층이 섞여 있으므로 정리·완료 계획에서 사용자·공통·모듈 부분을 나눠 읽습니다. 모든 OPEN-UF와 기술 미정이 사라져야 사용자 기능이 완료되는 것은 아니며, 이번 정리로 어떤 OPEN 항목 전체를 완료 처리하지도 않습니다.

시스템 기능명세가 준비되면 상위 추적 관계를 연결합니다. 현행 UF ID는 문서 식별자이며 API·DB·도구 이름이 아닙니다. 실제 모듈 구성·에이전트 수·프레임워크·실행 한도는 아직 확정하지 않습니다.
