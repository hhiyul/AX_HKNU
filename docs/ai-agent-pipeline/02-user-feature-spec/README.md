# 사용자 기능명세

펀딩을 준비하는 사용자가 AI Chat에 무엇을 요청하고 어떤 결과를 얻으며 무엇을 선택·저장하는지 정의합니다.

**현재 상태: v0.1 초안 / P0 사용자 기능 Grill 재개 / 일부 계약 결정 / 사용자 기능 미완료 / 상위 시스템 연결 대기.** 2026-11-02 사용자 요청으로 대표 흐름부터 검토를 재개했습니다. 기존 합의는 유지하고, 사용자 기능의 남은 쟁점을 먼저 정리하며 모듈 설계는 뒤로 미룹니다.

## 현재 먼저 정리할 범위

| 우선순위 | 사용자 기능에서 남은 일 |
| --- | --- |
| P0 | 대표 흐름, 여섯 항목의 목적·필수 정보·허용 미정·결과·완료 기준, 제안 수정·선택·저장·확정·재편집, 항목 간 영향 |
| P1 | 대표 실패·취소·충돌·결과 미확인, 파일·웹·프로젝트 자료 활용, 이력·복구·삭제·내보내기·설정 |
| 공동 확인 | 권한·공통 데이터와 팀원 기능, 가격·원가의 사업 기준, 서비스 지원·이용 제한·보존 보장 |
| 후속 모듈 | Projection·모델 입력·버전·실행 상태·도구·저장·전달의 실제 구조와 구현 계약 |

우선순위는 문서 검토 순서이며 사용자에게 여섯 항목의 작성 순서를 강제하는 것이 아닙니다. 기술 용어가 들어가도 사용자 결과를 바꾸는 의미는 사용자 기능·공통 계약에서 먼저 정합니다.

## 기존 합의와 미정의 취급

D-UF-001~037은 모두 유효합니다. 프로젝트 저장 대상 고정·최초 연결·명시적 재검토, 고객·목적·접점의 가설과 필수 수준·미정 취급, 평가 갱신·진행 대상·재선택, 이미 정한 재조회·버전·보류·재시도·종료 원칙을 유지합니다. D-UF-031~033은 막연한 고민의 첫 도움, 구체안의 제안, 프로젝트 생성·같은 Chat 복귀의 흐름입니다. D-UF-034는 내부 미완료와 사용자 명시적 확정의 분리, D-UF-035~037은 CK-01 판매 범위·CK-03 고객 목적과 선택 이유·CK-04 한 판매 단위의 핵심 구성·수량의 필수 수준입니다. 세부 내용을 본문에서 줄인 것은 폐기나 재선택이 아닙니다.

기존 미정 원문은 계층이 섞여 있으므로 정리·완료 계획에서 사용자·공통·모듈 부분을 나눠 읽습니다. 모든 OPEN-UF와 기술 미정이 사라져야 사용자 기능이 완료되는 것은 아니며, 이번 정리로 어떤 OPEN 항목 전체를 완료 처리하지도 않습니다.

시스템 기능명세가 준비되면 상위 추적 관계를 연결합니다. 현행 UF ID는 문서 식별자이며 API·DB·도구 이름이 아닙니다. 실제 모듈 구성·에이전트 수·프레임워크·실행 한도는 아직 확정하지 않습니다.
