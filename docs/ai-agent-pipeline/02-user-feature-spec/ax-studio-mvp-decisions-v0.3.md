## 5. 기준선 동결 전에 처리할 세 묶음

새 질문을 자동으로 재개하지 않는다. 먼저 담당 코드·상위 명세와 정합하고, 사용자 행동을 바꾸는 선택만 묶어서 묻는다. 모듈 설계로 넘길 수 있는 수치·스키마는 제품 질문으로 늘리지 않는다.

| ID | 현재 불일치 | 현재 안전한 기준 | 닫는 조건·시점 |
| --- | --- | --- | --- |
| OPEN-MVP-01 | 옛 CK 명세의 UNSET/DRAFT/DECIDED와 통합 코드의 SKIPPED/WRITTEN | AI 직접 변경 금지·직접 편집·기존 값 보존. WRITTEN을 사용자 확정으로 추정하지 않음. 새 문서의 검토 상태로 치환하지 않음 | CK 담당 상위 사용자 명세 확인 후 기존 CK 상태 UI·이전 정책 결정. G-U에서 처리 결과 기록 |
| OPEN-MVP-02 | 추가 기록은 프로젝트당 논리 문서 하나였으나 코드에는 여러 record가 있음 | 모든 기존 제목·본문·연결 보존, 강제 병합·삭제 없음. 할 일이나 CK로 자동 변환하지 않음 | 기존 기록을 어떻게 열고 새 기록을 어디에 누적하는지 사용자 흐름을 정합. G-U |
| OPEN-MVP-03 | HTML의 전체 백업·v1~v3 가져오기·기존 정산/달력 주장이 실제 코드와 다름 | 기존 저장 데이터 보존과 신규 문서·일정 통합은 P0. 검증할 파일 없는 구버전 호환을 약속하지 않음. 상세 정산 제외 | 가져오기 대상/샘플·원본 소유자 확인 후 백업 UI의 P0/P1 범위를 한 번에 결정. 대상이 없으면 지원하지 않는 범위를 명시해 G-U 종료 |

G-U 통과 전 이 세 항목은 미결 또는 명시적 범위 제외로 기록되어야 한다. 사용자 명세에 미결이 있다는 이유로 전체 대화를 재질문하지 않는다. 변경은 해당 요구·시나리오·인수 조건·후속 설계의 영향 범위에만 적용한다.

## 6. 변경 관리

변경 기록은 변경 이유, 근거, 영향을 받는 AX-RQ/AX-AC, 폐기·대체한 이전 결정, 검토 상태를 함께 남긴다. 기준선 확정 뒤 발견한 코드 제약을 제품 요구의 자동 변경으로 처리하지 않는다. HandOff는 당시 이관 스냅샷으로 보존하며 소급 수정하지 않는다.
