## 1. 이번 검토의 기준

사용자는 대화·내부 평가·저장 흐름 외에도 웹 검색 MCP와 프로젝트 컨텍스트의 Chip 형식 드래그 앤 드롭에 P0 논의가 남았다고 정정했습니다. 기존 U-07의 웹 검색·프로젝트 컨텍스트 부분을 P0 우선 검토 대상으로 다룹니다. 파일 형식·용량 등의 나머지 자료 확장과 세부 구현까지 모두 P0로 올리는 것은 아닙니다.

프로젝트 Chip은 드래그 앤 드롭하는 참조 자료로 다루고 저장 프로젝트의 명시적 연결과 구분합니다(D-UF-063). 프로젝트를 먼저 준비한 1:1 전용 Chat에서 다른 프로젝트 Chip을 참고할 수 있습니다(D-UF-064). 활성 유지·제거는 D-UF-065로 정했고 과거 이력 유지·제거 B 정보 자동 재사용 제외·A 결정 보존은 D-UF-066을 따릅니다. 기본 검색 입력 범위는 D-UF-067을 따르며 검색 결과 선택·근거 표시와 자료 제외/추가 검토 요청은 D-UF-068을 따르며 Chip 실제 참고/누락 안내와 부분 제안/필요 판단 보류는 D-UF-069를 따릅니다. 보완 검색·진전 없음/한도 도달 시 중단과 결과 안내는 D-UF-070을 따릅니다. 검색 끄기 후 도착 결과의 현재 답변 제외·실제 취소 구분은 D-UF-071을 따릅니다. 끄기 전 확인 자료 재사용·최신 확인 필요 판단 보류는 D-UF-072를 따릅니다. 자료 제외의 Chat 지속·명시 범위 우선은 D-UF-073을 따릅니다. 기본 동작 합의 후 구체적인 한도/권한·참조 표시/복구 등은 잔여 OPEN으로 추적하고 다음 질문은 [저장·재편집 SAVE-02](save-and-edit-grill.md)로 이동합니다. 프로토타입 관찰은 UI-21의 카드·첨부/드래그 코드와 UI-22의 모의 수동 검색 근거이며 실제 MCP 연동·완성된 Chip UX의 증거가 아닙니다.

D-UF-001~073의 원문·이유·변경 이력을 보존합니다. 현행은 D-UF-063·064의 프로젝트 선행·1:1·참조 Chip 분리를 우선 적용하고 기존 독립 Chat 전제는 명시된 범위에서 대체합니다. 다른 접근 가능한 프로젝트의 읽기 전용 Chip 참조는 허용됐으며 저장 대상·조회/참조/대상 버전·명시적 재검토·최종 UI 반영·저장 보류의 나머지 제약은 유지합니다.

## 4. WEB-01 — 웹 검색을 언제 실행할 수 있는가 (A 채택 / D-UF-062)

**상황:** 사용자가 프로젝트 컨텍스트를 참고하며 ‘이 구성을 2만원에 팔아도 괜찮을까?’라고 묻습니다. 현재 자료만으로 기획 조언을 할 수도 있지만 AI는 유사 상품·펀딩 사례를 검색하면 판단을 보강할 수 있다고 봅니다. 사용자가 이번 메시지에서 웹 검색을 명시적으로 요청하지 않았을 때 어떤 동작을 기본으로 할지 정합니다.

| 대안 | 사용자 흐름 | 장점·트레이드오프 |
| --- | --- | --- |
| A — Chat에서 검색을 허용한 뒤 필요 시 AI 실행 (채택 / D-UF-062) | 검색 사용 여부를 Chat에서 명시적으로 선택. 허용 전에는 필요성을 안내하고, 허용 후에는 요청을 해결하는 데 필요한 검색을 AI가 실행. 현재 허용 상태를 알 수 있고 이후 사용을 끌 수 있게 함 | 한번 허용한 뒤 반복 요청 부담을 줄이며 검색 사용을 제어할 수 있음. 처음 허용하는 조작과 허용 범위를 이해하는 UX가 필요함 |
| B — 매번 명시적인 검색 요청 후 실행 (미채택) | AI는 검색의 필요성을 제안하고 사용자가 자연어 또는 UI로 그 검색을 요청하면 실행 | 검색마다 의도가 분명함. 대신 외부 확인이 자주 필요한 대화에서 요청 단계가 반복될 수 있음 |
| C — 기본 허용 상태에서 필요 시 AI 실행 (미채택) | 별도 사전 허용 없이 요청에 필요한 검색을 AI가 실행하며, 검색 사용 상태와 실제 실행을 알리고 사용자가 이후 검색을 끌 수 있게 함 | 처음부터 자연스럽게 도구를 활용할 수 있음. 사용자는 일반 질문이 외부 검색으로 이어질 수 있음을 미리 이해할 수 있어야 함 |

**선택 이유:** 사용자는 A를 채택했습니다. Chat에서 검색 사용을 선택한 뒤 에이전트가 필요한 검색을 판단하므로 사용자 제어와 도구 활용을 함께 제공할 수 있습니다. 매 응답 검색·무제한 반복을 의무화하거나 허용하지 않습니다. 구체적인 횟수·비용·시간 기준은 서비스 계약과 후속 질문에서 정합니다.

**유지할 경계:** 어떤 안이든 실제 검색 여부·사용한 근거·처리 한계를 알 수 있어야 하고 검색·결과 선택만으로 체크리스트를 저장하지 않습니다. 검색을 허용했다고 모든 프로젝트 정보를 검색 입력에 사용할 권한이 생기는 것으로 해석하지 않습니다. 그 정보 범위는 WEB-02에서 정합니다. 프로젝트 연결만으로 기존 제안 재검토를 자동 실행하거나 사용자의 현재 결정을 바꾸는 권한도 추가하지 않습니다.

**최종 선택:** 2026-11-02 사용자 지시로 A를 D-UF-062에 기록했습니다. 해당 Chat의 명시적 허용 뒤 AI가 필요한 검색을 실행하고 사용자가 이후 끌 수 있게 합니다. 끈 뒤 새로운 자동 검색은 시작하지 않으며 진행 중 검색의 중단·과거 결과 재사용과 정확한 UX는 후속 계약입니다.

## 5. CHIP-01 — 프로젝트 Chip은 참조 자료·저장 연결과 분리 (A 채택 / D-UF-063)

**당시 질문과 전제 변경:** 독립 Chat의 첫 프로젝트 Chip이 참조와 최초 연결 중 무엇을 뜻하는지 질문했습니다. 사용자는 A의 참조/저장 연결 분리를 채택하면서 프로젝트 생성 선행·프로젝트와 AI Chat의 1:1 관계·다른 프로젝트 Chip 참조를 추가로 명시했습니다. 독립 Chat 상황은 현행 진입 경로에서 D-UF-064로 대체합니다.

| 당시 대안 | 최종 선택과 의미 | 트레이드오프 기록 |
| --- | --- | --- |
| A — 참조 첨부와 저장 프로젝트 최초 연결 구분 | 채택 / D-UF-063. 참조 Chip과 명시적 저장 프로젝트 연결을 구분. 최초 연결은 프로젝트 선택·전용 Chat 진입에서 표현하며 독립 Chat을 새로 허용하지 않음 | 참고할 자료와 실제 작업 대상을 명확히 나눔. 소유 프로젝트와 참조 프로젝트의 표시가 필요함 |
| B — 첫 Chip 첨부가 참조와 최초 연결을 함께 선택 | 미채택. Chip 첨부를 소유·저장 프로젝트의 연결/변경으로 취급하지 않음 | 조작은 줄일 수 있지만 참조 첨부가 저장 대상 고정으로 이어지는 문제가 있음 |

**현행 흐름:** 프로젝트를 먼저 생성하거나 기존 프로젝트를 선택 → Chip과 별개로 저장 프로젝트를 명시적으로 연결 → 그 프로젝트의 전용 Chat을 시작·재방문 → 다른 프로젝트를 Chip으로 참고합니다. A 프로젝트의 Chat에 B Chip을 넣어도 소유·저장 대상은 A입니다. B에서 실제 작업하려면 B의 전용 Chat으로 이동하고 동일 프로젝트에 Chat을 중복 생성하지 않습니다.

**유지할 경계:** 프로젝트/참조 권한과 실제 조회·모델 참조 여부를 구분하고 실제 A/B 참조 묶음·저장 대상 버전을 검증합니다. Chip은 저장·확정·검색 허용이나 명시적 재검토 요청을 대신하지 않습니다. 내부 프로젝트 섹션별 컨텍스트 관리는 M-01에서 후속 설계하며, 정확한 진입 UI·실제 1:1 자원 생성 시점·보존/복구는 공동·모듈 계약입니다.

## 6. CHIP-02 — 추가 참조 Chip의 지속·제거 의미 (A 채택 / D-UF-065)

**상황:** A 프로젝트의 전용 Chat에서 B 프로젝트 Chip을 첨부해 고객 가설을 비교했습니다. 다음 메시지에 사용자가 ‘그럼 가격은 어떻게 잡을까?’라고 묻고 B를 다시 첨부하지 않았습니다. B를 계속 활성 참조로 사용할지, 이번 메시지에만 사용하는지 정합니다. 이번 질문은 추가 참조 B의 범위이며 소유 프로젝트 A의 연결·기본 컨텍스트와 구분합니다.

| 대안 | 사용자 흐름 | 트레이드오프 |
| --- | --- | --- |
| A — Chat에서 유지하고 사용자가 제거하면 활성 참조 해제 (채택 / D-UF-065) | 전송에 포함한 B Chip을 이후 요청에도 활성 참조로 유지하고 현재 참조 목록에 표시. 사용자가 제거하면 이후 요청에서 B를 새로 조회·활성 첨부로 포함하지 않음 | 연속된 기획 대화에서 반복 첨부를 줄임. 현재 어떤 프로젝트를 계속 참고하는지 눈에 보여야 하며 사용자가 필요 없어진 참조를 제거할 수 있어야 함 |
| B — 전송한 메시지에만 활성 참조로 사용 (미채택) | B를 첨부한 메시지에만 활성 참조로 사용하고 다음 메시지는 다시 첨부하지 않으면 B를 새로 조회·활성 첨부로 포함하지 않음. 해당 메시지에서 무엇을 썼는지 확인 가능 | 요청별 참조 범위가 분명함. 같은 자료로 이어서 질문할 때 반복 첨부가 필요할 수 있음 |

**제거의 채택 범위:** 전송 전 Chip을 제거하면 해당 전송의 활성 참조 선택에서 제외합니다. 사용한 뒤 제거하면 이후 활성 참조를 해제하며 A의 소유 연결·저장 대상이나 A/B 원본·저장된 기획·과거 대화/결과를 삭제·초기화하지 않습니다. 제거가 이미 수행한 조회를 되돌리거나 과거 자료가 포함된 모든 입력·기록을 지웠다는 뜻은 아닙니다. 과거 이력 유지·제거 B 고유 정보 자동 재사용 제외·A 저장/명시 채택 결정 유지는 D-UF-066을 따릅니다.

**남겨둘 다음 쟁점:** 과거 B 고유 정보 자동 재사용 제외와 A 결정 유지는 D-UF-066으로 정했습니다. 재선택·권한 변경·원본 삭제의 최신성, 실제 참조/채택 구분·표시·보존/복구의 세부 계약은 남습니다. 이력 표시와 실제 새 답변의 참고 범위를 구분하고 실제 필터링·요약·재구성은 M-01에서 후속 설계합니다.

**최종 선택:** 사용자가 A를 채택했습니다(D-UF-065). B Chip은 제거할 때까지 Chat의 활성 참조로 유지하고 제거 후 이후 활성 참조에서 제외합니다. 소유 프로젝트 1:1·고정 저장 대상·명시적 최종 저장·검색 허용과 실제 참조/대상 버전 검증을 유지하며, 이미 B를 실제 참조한 제안의 검증 범위를 제거 때문에 줄이지 않습니다.

## 7. CHIP-02-HISTORY — 제거한 B 정보가 과거 대화에 남아 있을 때 (A 채택 / D-UF-066)

**상황:** A Chat에서 B Chip을 참고한 응답에 ‘B의 포장비는 2,000원’이라는 내용이 남아 있습니다. 사용자는 B Chip을 제거한 뒤 ‘A의 가격을 다시 추천해 줘’라고 요청합니다. B를 새로 조회하거나 활성 Chip으로 다시 넣지 않는 것은 D-UF-065로 정했습니다. 남은 질문은 AI가 과거 응답·요약에 있는 B 고유 정보를 다시 근거로 써도 되는지입니다.

| 대안 | 사용자에게 보이는 의미·흐름 | 트레이드오프 |
| --- | --- | --- |
| A — 과거 이력은 볼 수 있게 두고 B 고유 정보의 자동 재사용 제외 (채택 / D-UF-066) | B를 직접 근거로 삼은 과거 정보·요약을 이후 답변의 자동 참고 자료로 다시 사용하지 않음. B 자료 자체를 다시 참고하려면 사용자가 Chip을 다시 선택. 과거 대화를 삭제하거나 A의 현재 결정을 되돌리지 않음 | 제거 후 B의 영향 범위가 명확해짐. B 자료로 다시 비교하려면 재선택이 필요하고, 이력 표시와 실제 모델 참고를 구분하는 UX가 필요함 |
| B — 새 조회만 중단하고 과거 대화 정보는 계속 재사용 (미채택) | 활성 B Chip·새 조회는 제외하되 과거 대화/요약에 있던 B 정보를 후속 답변에서 참고할 수 있음. 과거 정보라는 출처·기준을 구분하고 현재 원본을 재확인한 것으로 표시하지 않음 | 대화의 연속성을 유지함. 대신 Chip을 제거한 뒤에도 B 정보가 답변에 영향을 줄 수 있음을 사용자가 알아야 함 |

**두 안의 공통 경계:** A 프로젝트에 이미 저장했거나 사용자가 명시적으로 채택한 내용은 Chip 제거만으로 삭제·초기화하지 않습니다. 예를 들어 사용자가 B 사례를 참고해 ‘A의 포장비도 기획상 2,000원으로 두자’고 선택했다면 그 A의 현재 결정은 유지하고, B의 현재 실제 비용이 확인됐다는 뜻과 구분합니다. 질문 대상은 B 자료 자체의 자동 재사용이며 사용자의 현재 A 결정을 취소하는 정책이 아닙니다. 실제 A 저장에는 기존 변경 요약·최종 UI 선택·서버 검증·저장 보류를 유지합니다.

**다음 단계와 모듈 경계:** 권한 변경·자료 삭제·다시 선택했을 때의 최신성, 혼합된 이력/요약의 출처 구분·구체적인 표시·보존/복구는 후속 계약입니다. 선택한 사용자 계약에 따른 입력 필터링·요약·재구성·검증은 M-01에서 설계하며 이번 질문으로 실제 삭제·마이그레이션·도구 실행을 하지 않습니다.

**최종 선택:** 사용자가 A를 채택했습니다(D-UF-066). 과거 이력은 유지하고 제거한 B의 고유 정보는 이후 답변에 자동 재사용하지 않습니다. A에 저장했거나 사용자가 명시적으로 채택한 결정은 유지하며 미채택 AI 제안·요약과 구분합니다. 검색어 작성·중간 요약으로 같은 B 정보를 자동 재사용하거나 과거 제안의 실제 참조 검증을 줄이지 않습니다. 정확한 입력 구성은 사용자 계약을 입력으로 M-01에서 설계합니다.

## 8. WEB-02 — 외부 검색 입력에 사용할 프로젝트 정보의 기본 범위 (A 채택 / D-UF-067)

**상황:** 현재 A 프로젝트에는 머그컵 선물 세트라는 상품 유형과 미공개 상품명·제조 원가가 있고 사용자가 다시 선택해 활성화한 B Chip에는 공급처명·견적 자료가 있습니다. 사용자가 유사 펀딩 사례를 요청했습니다. WEB-01 A에 따라 검색은 허용돼 있지만 어떤 내용을 검색어·필터 등 외부 검색 입력으로 보낼 수 있는지는 아직 정하지 않았습니다. Chat 안에서 참고할 수 있는 정보와 검색 도구에 전달할 정보의 범위를 구분합니다.

| 대안 | 자동 검색 입력의 기본 범위 | 트레이드오프 |
| --- | --- | --- |
| A — 일반화된 특성과 검색 사용을 명시한 내용 중심 (채택 / D-UF-067) | 상품 종류·용도 등 필요한 일반 특성으로 검색어를 구성. 예: ‘머그컵 선물 세트 펀딩 사례’. 사용자가 검색에 쓰도록 명시한 내용 외에 미공개 고유명·내부 원가·공급처/견적·문서 원문은 기본 자동 포함에서 제외. 추가 범위가 필요하면 그 필요성과 대상을 안내 | 반복 검색마다 검토하지 않고 일반 사례를 찾기 쉬움. 정확한 상품/업체·세부 조건 검색에는 사용자가 추가로 검색 사용 범위를 정해야 할 수 있음 |
| B — 사용자가 미리 전송을 허용한 자료 범위에서 고유 정보도 활용 (미채택) | 사용자가 프로젝트별 검색 전송 가능 자료 범위를 선택하면 AI가 그 안에서 필요한 정확한 명칭·수치·원문 내용을 검색 입력에 사용. 검색 실행 허용과 전송 가능 자료 선택을 구분하고 선택 범위를 알 수 있게 표시 | 구체적인 비교·자료 검색의 정확도를 높일 수 있음. 대신 최초 자료 범위 설정이 필요하고 내부 참고 허용과 외부 검색 입력 허용의 차이가 명확해야 함 |

**두 안에서 유지할 조건:** 현재 권한과 소유/활성 참조 범위를 지키고 제거한 B 고유 정보를 과거 대화에서 끌어와 검색 입력으로 재사용하지 않습니다(D-UF-066). A의 결정으로 보존된 정보도 외부 검색 입력 허용과는 별개입니다. 검색 허용만으로 대화·프로젝트·문서 전문을 통째로 자동 전송하지 않습니다. 어떤 안도 매 검색마다 실행 승인을 다시 받는 방식으로 WEB-01 A를 되돌리지 않습니다. 검색이 실행되거나 결과가 채택돼도 저장·확정은 기존 사용자 UI 선택·서버 검증·저장 보류를 따릅니다.

**후속 경계:** 일반화·검색 사용을 명시한 정보의 구체적인 식별, 추가 전송 범위 설정·표시와 변경/해제, 실제 검색 MCP에 전달되는 입력 형식·검증·기록은 후속 사용자·공동·모듈 계약입니다. 프로젝트 섹션별 필드·필터·Provider·도구 스키마를 이 질문에서 설계하지 않습니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-067). 기본 검색 입력에는 필요한 일반화된 특성과 사용자가 검색 사용을 명시한 내용만 포함합니다. 일반 사례 검색에는 고유명·내부 원문 없이 필요한 검색어를 만들 수 있고 허용 후 AI 검색을 이어갈 수 있습니다. 정확한 명칭·세부 자료가 필요하면 필요성과 대상을 알리고 사용자의 검색 사용 명시 범위 안에서만 사용합니다. 내부 참고·A 저장/채택을 전송 허용으로 간주하거나 허용된 매 검색마다 실행 승인을 반복하지 않습니다. B안은 채택하지 않았으며 WEB-03은 별도 미정 질문으로 이어갑니다.

## 9. WEB-03 — 검색 결과를 누가 골라 쓰고 근거를 어떻게 보여줄 것인가 (A 채택 / D-UF-068)

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-068). 필요한 검색 결과는 AI가 선택하고 핵심 주장에 출처·확인 범위·한계를 연결해 보여줍니다. 사용자는 자료 제외·추가 검토를 요청할 수 있습니다. 매번 자료를 먼저 골라야 하는 부담을 줄이되 선택 근거와 실제 확인 범위를 검토할 수 있어야 합니다. 검색 목록 노출을 원문 확인으로 과장하거나 검색 근거 선택을 A의 기획 채택·편집안 덮어쓰기·저장으로 취급하지 않습니다. B안은 채택하지 않았으며 다음 CHIP-03은 별도 미정 질문입니다.

## 10. CHIP-03 — Chip 첨부와 실제 참고 범위가 다를 때의 안내·부분 답변 (A 채택 / D-UF-069)

**상황:** A 프로젝트의 Chat에서 사용자가 B 프로젝트 Chip을 첨부하고 ‘B와 비교해서 A의 고객 접점을 추천해 줘’라고 요청했습니다. A 자료는 읽었지만 B는 권한 변경 또는 조회 실패로 내용을 읽지 못했습니다. Chip이 화면에 있다는 이유로 B를 참고했다고 말할 수 없고 B 비교 결론도 뒷받침할 수 없습니다. 실패·실제 미사용을 알리는 공통 경계를 유지하면서, A만으로 가능한 도움을 바로 이어갈지 먼저 참조 범위를 다시 확인할지 정합니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-069). 실제 참고 범위와 누락 영향을 기본 응답에 안내하고 가능한 부분 제안을 이어가되 읽지 못한 자료가 필요한 판단은 보류합니다. 일부 참조 실패로 가능한 도움까지 중단하지 않으면서 요청한 비교를 완료했다고 오해하지 않게 합니다. 기존 Projection 조회 실패·명시적 재시도·평가 보류와 저장 규칙은 유지합니다. B안은 채택하지 않았고 다음 WEB-04는 별도 미정 질문입니다.

## 11. WEB-04 — 검색 근거가 부족할 때의 보완 검색·부분 답변 (A 채택 / D-UF-070)

**상황:** 검색을 허용한 사용자가 A 상품의 유사 펀딩 사례를 요청했지만 첫 검색의 결과는 홍보 글뿐이거나 원문을 읽지 못해 구성·가격 비교를 뒷받침할 근거가 부족합니다. Chat의 검색 허용·이후 끄기(D-UF-062), 입력 정보 범위(D-UF-067), AI 결과 선택·근거/확인 범위/한계 표시(D-UF-068)는 이미 정했습니다. 이번에는 근거 부족 이후 AI가 다른 검색어·자료로 필요한 보완 검색을 이어갈지, 부족을 알리고 추가 검색 요청을 기다릴지 정합니다.

| --- | --- | --- |

**후속 경계:** 정확한 검색 횟수·비용·시간 한도와 표시·한도 도달 UX는 공동 서비스 계약에서 정합니다. 검색어/자료 경로 선택·진전 판단·실제 MCP 오류/재시도·루프 중단 구현은 M-06·03·05·08 후속 설계입니다. 과거 결과 재사용·검색 끄기 때 이미 진행 중인 작업 처리·권한 변화와 구체적인 실패 복구 UX도 남습니다. 이번 질문의 채택만으로 웹 검색·Chip 사용자 계약 전체가 완료되는 것은 아닙니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-070). 허용된 범위에서 AI가 보완 검색하되 진전이 없거나 한도에 도달하면 멈추고 확인한 내용·남은 한계·보류 판단을 안내합니다. 재요청 부담을 줄이면서 진전 없는 반복·결과 과장을 막고 검색 허용/끄기·입력 정보 범위·Projection 명시적 재시도·저장 경계를 유지합니다. B안은 채택하지 않았고 정확한 한도·내부 중단 구현은 후속 계약입니다. 검색 끄기 후 진행 중 결과의 사용은 WEB-05의 별도 미정 질문으로 이어갑니다.

## 12. WEB-05 — 검색 끄기 후 도착한 진행 중 결과를 현재 답변에 쓸 것인가 (A 채택 / D-UF-071)

| 대안 | 사용자에게 보이는 흐름 | 트레이드오프 |
| --- | --- | --- |
| A — 끄기 후 도착한 결과는 현재 답변의 새 근거에서 제외 (채택 / D-UF-071) | 새 자동 검색을 시작하지 않고 뒤늦게 도착한 결과도 현재 답변의 새 근거로 추가하지 않음. 검색을 꺼서 해당 결과를 사용하지 않았다는 사실·현재 확인 범위와 필요한 보류 판단을 짧게 안내하고 사용 가능한 기존 자료로 답변 | 끄기 이후 검색 결과가 답변에 추가되지 않아 제어의 의미가 명확함. 대신 이미 시작된 검색에서 유용한 결과가 와도 현재 답변에 활용하지 못할 수 있음 |
| B — 새 검색은 막고 이미 시작한 검색 결과는 현재 답변에 사용 (미채택) | 새 자동 검색은 시작하지 않되 끄기 전에 시작한 검색에서 도착한 결과는 현재 답변에 사용. 이전에 시작한 검색 결과라는 사실과 실제 사용 근거·확인 범위·한계를 안내 | 진행한 검색의 결과를 활용해 답변을 완성하기 쉬움. 대신 검색을 껐는데도 새 결과가 반영될 수 있다는 의미를 사용자가 이해해야 함 |

**두 안의 공통 경계:** 검색 끄기 뒤 새로운 자동 검색·보완 검색을 시작하지 않습니다. 전체 Chat 답변 취소·이미 완료된 검색/사용량의 되돌림·이력/현재 결정/편집안/저장 내용의 자동 삭제를 끄기와 동일시하지 않습니다. 실제로 현재 답변에 사용한 자료·확인 범위·한계와 필요한 보류 판단은 정직하게 안내합니다. 끄기 전에 이미 확인·사용한 자료와 과거 결과의 향후 재사용 범위는 별도 계약이며 이번 질문으로 소급 삭제하거나 모두 허용하지 않습니다.

**기존 규칙:** 검색 입력 범위·권한·제거 B 정보 자동 재사용 제외·사용자 최신 결정·최종 UI 저장/검증/보류는 유지합니다. 검색 끄기만으로 프로젝트 저장·후속 검토·Projection 평가 보류를 바꾸지 않습니다. A안의 결과 사용 제외는 외부 도구가 실제로 즉시 취소됐다는 보장과 구분합니다.

**후속 경계:** 정확한 끄기/진행 상태 표시·답변 처리 시점·이미 처리한 자료와 뒤늦은 결과의 식별은 후속 계약입니다. 취소 전파·도착 순서·진행 중 모델/도구 호출·사용량 기록·참조 입력 제외의 구현은 M-05·06·01·08에서 설계합니다. 구체적인 API·상태 코드·취소 성공 보장을 이번 질문으로 만들지 않습니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-071). 검색 끄기 후 도착한 결과는 현재 답변의 새 근거에서 제외하고 사용 가능한 기존 자료로 답변·보류 판단을 안내합니다. 끄기 이후 새 자료가 현재 답변에 추가되지 않도록 하되 실제 외부 검색 취소 성공·전체 답변 취소·과거 이력/기획 삭제와 구분합니다. B안은 채택하지 않았습니다. 끄기 전에 이미 확인한 외부 자료의 후속 재사용은 WEB-06의 별도 미정 질문으로 이어갑니다.

## 13. WEB-06 — 검색 끄기 전에 확인한 외부 자료를 후속 답변에서 다시 참고할 것인가 (A 채택 / D-UF-072)

**상황:** AI가 검색 사용을 끄기 전에 펀딩 사례의 가격·구성을 실제로 확인하고 출처와 함께 답변했습니다. 사용자는 그 뒤 검색을 끄고 특정 자료를 지정하지 않은 채 ‘그럼 A 구성은 어떻게 바꿀까?’라고 묻습니다. 새 외부 검색은 하지 않으며 끄기 후 도착한 결과의 현재 답변 제외는 D-UF-071로 정했습니다. 이번 질문은 끄기 전에 이미 확인한 외부 자료를 이후 답변의 참고 근거로 자동 재사용할 수 있는지입니다. 과거 대화에 남아 있다는 사실과 실제로 확인한 자료라는 사실을 구분합니다.

| 대안 | 기본 사용자 흐름 | 트레이드오프 |
| --- | --- | --- |
| A — 이미 확인한 자료는 출처·확인 시점·한계와 함께 재사용 (채택 / D-UF-072) | 현재 요청과 관련된 기존 확인 자료를 다시 참고할 수 있고 과거 확인 자료임을 표시. 새 조회·최신 확인으로 안내하지 않으며 시점 변화가 중요한 판단은 최신 확인 불가를 알리고 필요한 판단 보류. 새 검색은 사용자가 다시 허용하기 전 시작하지 않음 | 외부 조회를 끈 상태에서도 대화를 이어가기 쉬움. 대신 과거 확인값과 현재 사실을 혼동하지 않도록 출처·시점·한계가 명확해야 함 |
| B — 과거 외부 근거의 자동 재사용도 중단하고 명시적으로 다시 참고 요청한 자료만 사용 (미채택) | 검색을 끄면 과거 확인 외부 자료도 후속 답변의 자동 참고에서 제외. 사용자가 ‘앞서 확인한 그 사례 기준으로’처럼 다시 참고할 자료를 명시하면 새 조회 없이 그 자료로 설명 | 외부 근거의 영향 범위를 사용자가 더 직접 통제함. 대신 관련 대화마다 이전 자료를 다시 지정해야 할 수 있음 |

**요청이 명확한 예와 기본 동작의 차이:** 사용자가 ‘앞서 확인한 그 사례와 비교해 줘’처럼 특정 과거 자료의 재참고를 명확히 요청하면 B에서도 사용할 수 있습니다. 두 안의 차이는 그 자료를 명시하지 않은 후속 요청에도 관련된 기존 확인 자료를 AI가 자동 참고할 수 있는지입니다. 새 검색 허용이나 초안/확정 저장 선택을 다시 묻는 질문이 아닙니다.

**두 안의 공통 경계:** A에 저장했거나 사용자가 명시적으로 채택한 결정은 검색 끄기만으로 삭제·초기화하지 않고 A의 기획 가정과 외부 원본의 현재 사실을 구분합니다. 과거 AI 출력만으로 자료의 실제 확인·사용자의 명시 채택을 추정하지 않습니다. 제외 요청·현재 권한·제거 B 고유 정보 자동 재사용 제외·실제 참조/대상 버전 검증은 유지합니다. 검색 끄기 뒤 새 조회·재검색·최신 확인을 실행하거나 과거 자료로 현재 사실을 확인했다고 표시하지 않습니다. 최신 확인이 필요한 판단은 미확인·보류를 안내합니다.

**범위 경계:** 이번 질문은 끄기 전에 실제로 확인한 외부 자료의 후속 답변 재사용이며 끄기 후 도착한 미사용 결과의 향후 사용까지 허용하지 않습니다. Chip 제거의 자료 참조 해제(D-UF-065·066)와 Chat 검색 실행 허용의 제어(D-UF-062)는 구분하며 검색 끄기를 참조 Chip 제거로 자동 처리하지 않습니다. 과거 기록 표시·현재 A 결정·자료 자동 참고·실제 저장도 구분합니다.

**후속 경계:** 확인 시점·출처/제외 범위의 정확한 표시·재방문 보존과 보존 기간은 후속 사용자·공동 계약입니다. 실제 자료 확인 기록·혼합 이력/요약 구분·선택·최신성 판단·컨텍스트 조립·입력 제외·캐시는 M-01·06·08에서 설계합니다. 정확한 TTL·필드·DB·랭킹 알고리즘을 이번 질문으로 정하지 않습니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-072). 검색 끄기 전에 실제로 확인한 자료는 출처·확인 시점·한계와 함께 다시 참고할 수 있고 최신 확인이 필요한 판단은 보류합니다. 새 외부 조회를 멈추면서 기존 자료로 대화를 이어가되 과거 확인값을 현재 확인 사실로 표시하지 않습니다. 자료 제외·권한·제거 B 정보 제외·현재 A 결정/저장 경계는 유지합니다. B안은 채택하지 않았고 제외 요청의 지속 범위는 WEB-07의 별도 미정 질문으로 이어갑니다.

## 14. WEB-07 — 자료 제외 요청을 해당 Chat에서 얼마나 유지할 것인가 (A 채택 / D-UF-073)

**상황:** AI가 비교에 사용한 특정 펀딩 상세 페이지 하나에 대해 사용자가 ‘이 자료는 비교에서 빼 줘’라고 요청했습니다. 해당 분석에서 제외 자료를 계속 같은 근거로 쓰지 않는 것은 D-UF-068로 정했습니다. 이후 같은 Chat에서 다른 구성 질문을 하거나 허용된 검색에 같은 페이지가 다시 나왔습니다. 제외를 계속 유지할지, 앞선 요청의 분석에만 적용할지 정합니다. 이번 질문의 대상은 명확히 식별한 자료 하나이며 사이트 전체·같은 주장을 담은 모든 독립 자료를 일괄 제외하는 요청으로 확대하지 않습니다.

| 대안 | 기본 사용자 흐름 | 트레이드오프 |
| --- | --- | --- |
| A — 해당 Chat에서 재허용 전까지 제외 유지 (채택 / D-UF-073) | 이후 답변·검색 결과 선택에서도 그 자료를 근거로 자동 재사용하지 않음. 과거 응답·요약에 있거나 검색에 다시 나와도 제외를 유지. 사용자가 제외 상태를 알 수 있고 다시 참고하도록 명시하면 해제할 수 있음 | 같은 자료를 반복해서 제외할 부담과 뜻밖의 재사용을 줄임. 대신 이후에는 유용한 자료가 돼도 제외가 남을 수 있어 상태 확인·해제 경로가 필요함 |
| B — 요청한 분석에만 제외 적용 (미채택) | 현재 요청의 답변/검토에서는 제외하되 이후 요청에서는 기존 자료 사용 규칙에 따라 다시 참고할 수 있음. 현재 분석에만 적용되는 제외임을 안내 | 한 번의 비교에 부적합했던 자료가 이후 다른 목적에서는 활용될 수 있음. 대신 사용자가 계속 제외하려던 경우 같은 요청을 반복해야 할 수 있음 |

**명시한 범위 우선:** 사용자가 ‘이번 비교에서만’ 또는 ‘앞으로 이 Chat에서는’처럼 범위를 명확히 정하면 그 의도를 우선합니다. 두 안의 차이는 지속 범위를 따로 말하지 않은 제외 요청의 기본 효과입니다. 매번 별도 확인 창·저장 승인을 추가하는 질문이 아닙니다.

**두 안의 공통 경계:** 검색에서 자료가 다시 발견되는 사실과 답변 근거로 선택하는 행위를 구분합니다. 제외를 외부 검색 결과에 그 자료가 절대 노출되지 않는다는 보장으로 표시하지 않습니다. A에 저장했거나 명시적으로 채택한 결정·현재 편집안·과거 이력은 자료 제외만으로 삭제·초기화하지 않고 A의 결정과 원본 근거를 구분합니다. 이미 만든 제안의 실제 참조/대상 버전 검증도 축소하지 않습니다.

**기존 검색·참조·저장 규칙:** 자료 제외의 해제나 재참고 요청이 새 검색 허용·제거한 B Chip의 재선택·초안/확정 저장을 대신하지 않습니다. 검색 꺼짐·입력 정보 범위·권한·늦은 결과 제외·과거 자료의 확인 시점/한계·최신 확인 필요 판단 보류는 유지합니다. 최신 사용자 결정·편집안 반영 선택·최종 UI 저장/검증/보류도 자동 변경하지 않습니다.

**후속 경계:** 구체적인 제외 상태/해제 UX·대상 모호 시 확인·다른 Chat 적용·재방문 보존은 후속 사용자·공동 계약입니다. 동일 자료의 식별·다른 URL/요약 연결·근거 선택/입력 필터·이력 구분은 M-01·06·08에서 설계합니다. 자료 ID·URL 정규화·도메인 차단·영속 스키마를 이번 질문으로 정하지 않습니다.

**최종 선택·이유:** 사용자가 A를 채택했습니다(D-UF-073). 자료 제외는 해당 Chat에서 사용자가 다시 허용할 때까지 유지하고 적용 범위를 명시하면 그 의도를 우선합니다. 다음 대화·검색 재발견·과거 요약을 통해 제외 자료가 조용히 근거로 돌아오지 않게 하되 A의 기존 기획·편집안·저장 상태는 자동 변경하지 않습니다. B안은 채택하지 않았습니다. 구체적인 한도/권한·표시/복구·실제 구현은 잔여 계약으로 추적하고 다음 P0는 [저장·재편집 질문지 SAVE-02](save-and-edit-grill.md)입니다.
