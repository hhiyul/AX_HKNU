# 웹 검색·프로젝트 컨텍스트 Chip P0 Grill 질문지

상태: **사용자 기능 P0 검토 대상 / 아래 대안 미채택 / 모듈 구현 미착수** · 기준일: 2026-11-02

연결: [정리·완료 계획](user-feature-closure-plan.md) · [사용자 기능명세](ai-pipeline-user-feature-spec-v0.1.md) · [미정 계약·기존 결정](open-contracts.md) · [모듈 설계 이관 대장](../03-module-feature-spec/deferred-design-contracts.md)

## 1. 이번 검토의 기준

사용자는 대화·내부 평가·저장 흐름 외에도 웹 검색 MCP와 프로젝트 컨텍스트의 Chip 형식 드래그 앤 드롭에 P0 논의가 남았다고 정정했습니다. 기존 U-07의 웹 검색·프로젝트 컨텍스트 부분을 P0 우선 검토 대상으로 다룹니다. 파일 형식·용량 등의 나머지 자료 확장과 세부 구현까지 모두 P0로 올리는 것은 아닙니다.

프로젝트 컨텍스트는 Chip 형식으로 드래그 앤 드롭하는 사용자 경로를 기준으로 논의합니다. 이 입력이 최초 연결·참조 선택·전송·이후 대화에 어떤 의미를 갖는지는 아래 질문에서 정합니다. 드롭만으로 조회 성공·실제 AI 참조·저장 성공을 선언하지 않습니다. 프로토타입 관찰은 UI-21의 카드·첨부와 드래그 코드, UI-22의 모의 수동 검색에 대한 근거이며 실제 MCP 연동·완성된 Chip UX의 증거가 아닙니다.

기존 D-UF-001~061은 유지합니다. 연결된 Chat의 저장 프로젝트 고정, Projection 조회·명시적 재검토, 실제 참조/대상 버전 검증, 최신 결정의 변경 요약·사용자 반영 선택, 명시적 최종 UI 반영과 저장 보류는 새 도구나 Chip으로 우회하지 않습니다. 다른 프로젝트의 읽기 전용 참조 허용 여부는 OPEN-UF-03의 미정으로 남기고 Chip을 보였다는 이유로 허용하지 않습니다.

## 4. WEB-01 — 웹 검색을 언제 실행할 수 있는가 (미정)

**상황:** 사용자가 프로젝트 컨텍스트를 참고하며 ‘이 구성을 2만원에 팔아도 괜찮을까?’라고 묻습니다. 현재 자료만으로 기획 조언을 할 수도 있지만 AI는 유사 상품·펀딩 사례를 검색하면 판단을 보강할 수 있다고 봅니다. 사용자가 이번 메시지에서 웹 검색을 명시적으로 요청하지 않았을 때 어떤 동작을 기본으로 할지 정합니다.

| 대안 | 사용자 흐름 | 장점·트레이드오프 |
| --- | --- | --- |
| A — Chat에서 검색을 허용한 뒤 필요 시 AI 실행 (추천, 미채택) | 검색 사용 여부를 Chat에서 명시적으로 선택. 허용 전에는 필요성을 안내하고, 허용 후에는 요청을 해결하는 데 필요한 검색을 AI가 실행. 현재 허용 상태를 알 수 있고 이후 사용을 끌 수 있게 함 | 한번 허용한 뒤 반복 요청 부담을 줄이며 검색 사용을 제어할 수 있음. 처음 허용하는 조작과 허용 범위를 이해하는 UX가 필요함 |
| B — 매번 명시적인 검색 요청 후 실행 (미채택) | AI는 검색의 필요성을 제안하고 사용자가 자연어 또는 UI로 그 검색을 요청하면 실행 | 검색마다 의도가 분명함. 대신 외부 확인이 자주 필요한 대화에서 요청 단계가 반복될 수 있음 |
| C — 기본 허용 상태에서 필요 시 AI 실행 (미채택) | 별도 사전 허용 없이 요청에 필요한 검색을 AI가 실행하며, 검색 사용 상태와 실제 실행을 알리고 사용자가 이후 검색을 끌 수 있게 함 | 처음부터 자연스럽게 도구를 활용할 수 있음. 사용자는 일반 질문이 외부 검색으로 이어질 수 있음을 미리 이해할 수 있어야 함 |

**추천 이유:** A는 Chat에서 검색 사용을 선택한 뒤 에이전트가 필요한 검색을 판단할 수 있어 사용자 제어와 도구 활용을 함께 제공할 수 있습니다. 매 응답 검색·무제한 반복을 의무화하거나 허용하지 않습니다. 구체적인 횟수·비용·시간 기준은 서비스 계약과 후속 질문에서 정합니다.

**유지할 경계:** 어떤 안이든 실제 검색 여부·사용한 근거·처리 한계를 알 수 있어야 하고 검색·결과 선택만으로 체크리스트를 저장하지 않습니다. 검색을 허용했다고 모든 프로젝트 정보를 검색 입력에 사용할 권한이 생기는 것으로 해석하지 않습니다. 그 정보 범위는 WEB-02에서 정합니다. 프로젝트 연결만으로 기존 제안 재검토를 자동 실행하거나 사용자의 현재 결정을 바꾸는 권한도 추가하지 않습니다.

**현재 질문:** Chat에서 검색 사용을 명시적으로 허용한 뒤 필요한 검색을 AI가 실행하는 A로 할지, 검색마다 요청을 받는 B 또는 기본 허용인 C로 할지 선택합니다. 현재는 추천만 기록하며 어느 안도 채택하지 않았습니다.
