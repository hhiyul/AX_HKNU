# 기획 결과를 전달하는 사용자 흐름 — EXPORT-01 합의

작성일: 2026-11-03 · 상태: **A 채택 / D-UF-090 / 공동 제공 조건 연결 대기** · 연결: U-08 / OPEN-UF-13·14 / C-01 / 프로토타입 UI-17

프로토타입에는 프로젝트 내보내기가 있지만 예전 PLAN 데이터 중심입니다. 현재 Chat과 여섯 체크리스트에 맞게 **사용자가 어떤 기획 결과를 전달할 수 있어야 하는지** 먼저 정합니다. 기존 상위 범위와 AI 작업의 경계는 유지하고 공통 프로젝트 내보내기는 팀원 시스템과 연결합니다.

## 1. 사용자 시나리오

사용자가 AI Chat에서 고객·상품 구성·가격 가설을 정리했습니다. 고객과 구성은 저장했고, 가격은 아직 비교 중인 미저장 제안입니다. 사용자는 팀원에게 현재 기획을 전달해 의견을 받으려 합니다.

사용자 목적은 자료를 다시 모아 작성하지 않고 현재 기획의 내용과 결정 정도를 전달하는 것입니다. 다음 질문은 서비스 안에서 타인에게 메시지를 보내는 기능이나 공개 공유 링크를 만드는 기능을 정하는 것이 아닙니다.

## 2. EXPORT-01 전달 자료의 기본 범위 — A 채택 / D-UF-090

| 대안 | 사용자에게 제공할 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 현재 저장된 여섯 체크리스트의 내용·저장 상태를 기본 내보내기 대상으로 제공. 초안·확정·미작성을 구분하고 미저장 Chat 제안은 기본 포함하지 않음 | 저장한 기획을 기준으로 전달 범위가 명확하지만 비교 중인 제안은 별도로 정리해야 함 |
| B · 미채택 | 저장된 기획과 함께 사용자가 선택한 미저장 제안·근거도 포함 가능. 저장된 내용과 검토 중인 내용을 구분해 전달 | 논의 중인 대안까지 한 자료로 전달하기 편하지만 포함할 내용을 고르는 과정과 상태 구분이 더 필요함 |

**선택 이유·트레이드오프:** A는 현재 저장된 기획을 기준으로 전달 범위가 명확한 흐름을 제공합니다. B는 미저장 제안까지 한 자료로 전달할 수 있지만 포함할 내용을 고르고 상태를 구분하는 과정이 더 필요합니다. 사용자는 A를 채택했습니다.

**결정:** 저장된 여섯 체크리스트의 내용·저장 상태를 기본 내보내기 대상으로 제공합니다. 미작성·초안·확정을 구분하며 확정 항목만으로 제한하지 않습니다. 미저장 Chat 제안·편집안·비교 근거는 기본 전달물에 자동 포함하지 않습니다. 내보내기만으로 기획을 저장·확정하거나 기존 편집안을 변경하지 않습니다.

## 3. 기존 합의와 공동 경계

- 내보내기를 저장·확정 선택으로 취급하지 않습니다. 현재 저장된 기획을 기준으로 제공하며 미저장 Chat 제안을 자동 포함하거나 기존 기획·편집안·저장 상태를 변경하지 않습니다.
- 초안·확정은 저장 상태이며 내부 평가의 구체화 완료·실제 고객/수익/제작 검증과 구분합니다. 확정 표시를 검증 보증으로 전달하지 않습니다.
- 사용자의 최신 결정·선택 범위, 자료 제외·접근 권한과 기존 저장·검증·보류 원칙을 유지합니다.
- 원문 첨부·대화 이력 전체·내부 평가·이전 저장 이력을 어디까지 제공할지는 이번 기본 범위 선택만으로 모두 확정하지 않습니다. 정확한 파일 형식·화면 구성·생성/다운로드 방식도 후속입니다.
- 프로젝트 내보내기의 담당·접근 범위는 C-01과 공동 확인합니다. 데이터 구조·버전 형식·전달 API·생성 도구를 사용자 질문에 섞지 않습니다.

## 4. 사용자 기능 검토 기준

합의한 사용자 결과는 본문 AC-216·217에 연결합니다. 다음은 기능 정합성 검토 기준이며 구현 시험 통과 기록이 아닙니다.

1. 사용자가 현재 어떤 기획과 결정 정도를 전달하는지 이해하는가?
2. 수신자가 미작성·초안·확정을 구분하고 기획 확정을 실제 검증 보증으로 오해하지 않는가?
3. 현재 저장된 기획을 전달하기 위해 추가 확정이나 비교 중인 제안의 저장을 먼저 요구하지 않는가?

기존 부분 가져오기 전제 불일치의 두 보류안·P0 공동 계약은 그대로 남깁니다. EXPORT-01은 기존 U-08의 사용자 목적별 검토이며 이를 새 P0 필수 기능으로 올리거나 파일 분석의 기술 예외로 다루지 않습니다.

다른 사용자 목적별 미정은 [사용자 기능 정리·완료 계획](user-feature-closure-plan.md)에서 추적합니다.
