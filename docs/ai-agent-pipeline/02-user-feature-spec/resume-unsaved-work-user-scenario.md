# 작업을 잠시 멈췄다가 이어가는 사용자 흐름 — RESUME-01 합의

작성일: 2026-11-03 · 상태: **A 채택 + 브라우저 인메모리 제약 / D-UF-091** · 연결: U-08 / OPEN-UF-12·14 / C-03 / R-03·05

## 1. 사용자 시나리오

사용자가 Chat 질문을 입력하고 AI 제안의 상품 구성 문구도 수정하던 중 앱 실행을 유지한 채 다른 화면을 확인했습니다. 아직 질문은 전송하지 않았고 수정한 기획도 저장·확정하지 않았습니다. 원래 프로젝트의 Chat으로 돌아오면 인메모리에 남은 입력·편집안을 이어서 작성합니다.

사용자 목적은 잠깐 작업을 멈춰도 작성한 내용을 다시 만들지 않고 이어가는 것입니다. 여기서 다룰 내용은 **미전송 텍스트와 사용자가 수정한 미저장 편집안**입니다.

## 2. RESUME-01 실행이 유지되는 동안 미저장 작업 이어가기 — A 채택 / D-UF-091

| 대안 | 사용자에게 제공할 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 + 인메모리 제약 | 작성 중 입력·편집안을 브라우저 인메모리에 자동 임시 보관하고 앱 실행이 유지되는 동안 복귀하면 이어서 작성. 아직 전송/기획 저장·확정되지 않았음을 표시 | 다시 작성하는 부담이 줄지만 메모리 수명을 넘는 복원은 제공하지 않으며 기획 저장과 구분해야 함 |
| B · 미채택 | 미전송 입력·편집안의 자동 보관은 제공하지 않고 이탈 전 남길지 결정할 수 있게 안내. 남기려면 사용자가 전송 또는 기획 저장을 선택 | 자동으로 남기는 작업 자료가 줄지만 보관을 위한 행동과 재작성 부담이 생김 |

사용자는 A를 채택하고 브라우저 인메모리에 보관하도록 명시했습니다. 이 제약에 맞춰 최종 보장 범위는 해당 브라우저 앱 실행이 유지되는 동안의 화면 이동·복귀입니다. 보관 대상은 해당 프로젝트 Chat의 미전송 텍스트와 사용자 미저장 편집안입니다.

**결정과 범위 조정:** 최초 검토안에는 새로고침도 예시로 포함했지만 브라우저 인메모리는 새로고침·탭 종료·앱 재시작 후에 남지 않습니다. 사용자가 추가한 인메모리 제약을 우선해 그 경우의 입력·편집안 복원은 보장하지 않는 것으로 정리합니다. 영속 보관을 임의로 추가하지 않으며 메모리 소실을 기획 저장 성공이나 저장된 기획의 삭제로 표시하지 않습니다.

## 3. 기존 합의와의 관계

- 임시 보관은 현재 기획의 초안 저장·확정이 아닙니다. 어느 안도 기존 프로젝트의 내용·UNSET/DRAFT/DECIDED를 자동 변경하거나 미전송 질문을 자동 전송하지 않습니다.
- D-UF-046의 새 제안 도착 시 편집안 보호를 유지합니다. 이번 합의는 앱 실행이 유지되는 화면 이동·복귀에서도 입력·편집을 이어갈 수 있도록 하며 새로고침 후 영속 복원을 포함하지 않습니다.
- 저장된 기획·전송된 대화는 기존 서비스가 보존·제공하는 범위와 구분합니다. 이 질문만으로 모든 과거 이력·미전송 첨부 원문·다른 기기에서의 복원·영구 복구까지 보장하지 않습니다.
- 복귀만으로 새 AI 실행·명시적 재검토·기획 저장을 시작하지 않으며 기존 최신 사용자 결정·편집 선택·서버 검증·저장 보류를 유지합니다.
- 사용자 명시 제약인 브라우저 인메모리를 따릅니다. 서버 기획 저장·영속 보관·다른 기기 동기화를 자동 추가하지 않습니다. 구체적인 메모리 관리·화면 연결 방식은 모듈 설계로 연결하고 다른 자료의 보존 정책은 C-03의 공동 범위를 유지합니다.

## 4. 사용자 기능 검토 기준

합의한 사용자 결과는 본문 AC-218·219에 연결합니다. 다음은 기능 정합성 검토 기준이며 구현 시험 통과 기록이 아닙니다.

1. 사용자가 돌아왔을 때 무엇을 이어갈 수 있고 무엇이 남지 않았는지 이해하는가?
2. 임시 보관된 작업을 전송되거나 프로젝트에 저장·확정된 기획으로 오해하지 않는가?
3. 미저장 내용을 남기려다가 의도하지 않은 기획 확정을 하게 만들지 않는가?

기존 P0 보류안·공동 계약은 유지합니다. RESUME-01은 A와 인메모리 제약으로 합의한 사용자 작업 연속성이며 기술적 실패 예외를 새 질문으로 분해하지 않습니다. 다른 사용자 목적별 기능의 합의·현재 쟁점은 [정리·완료 계획](user-feature-closure-plan.md)에서 추적합니다.
