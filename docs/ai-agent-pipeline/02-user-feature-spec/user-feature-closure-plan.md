## 1. 이번 정리의 범위와 해석

2026-10-30 재정리에서는 기존 합의를 바꾸지 않고 남은 일을 사용자 기능·공통 시스템 연계·모듈 설계로 구분했습니다. 당시 우선순위·대표 사례는 새 기능·필수 입력·완료 규칙의 채택이 아니었습니다. 2026-11-02 사용자 요청으로 P0 사용자 기능 Grill을 재개했으며, 후속 합의만 8절과 결정 기록에 추가합니다. D-UF-001~030은 그대로 유지하고 D-UF-031~061을 추가했습니다. D-UF-041의 최종 채택은 B안인 저장·확정의 명시적 UI 선택 필수이며, D-UF-042의 직접 재확정과 D-UF-043·044의 항목별 저장 종류 선택·함께 반영·부분 반영도 이를 유지합니다. D-UF-045는 실제 영향이 확인된 다른 항목의 짧은 안내와 저장 내용·상태 유지를 정했습니다. D-UF-046은 미저장 편집안 유지·새 후보 비교·선택 부분 가져오기를 정했습니다. D-UF-047은 CK-05의 판매 단위에 적용할 기획용 가격·범위를 필수로 두고 최종 판매가 확정은 요구하지 않는 결정을 추가했습니다. D-UF-048은 중요한 비용 미정 시 CK-05 전체 구체화 완료 보류와 설명 가능한 추정·범위 허용·실제 견적/실측 비강제를 정했습니다. D-UF-049는 기획 선택에 미치는 영향으로 비용 중요성을 판단하고 AI가 구체적인 영향·이유를 설명하도록 정했습니다. D-UF-050은 CK-06 핵심 구성품의 제작·조달 방식 가설을 필수로 두되 업체 확정·계약·실제 제작 검증은 요구하지 않도록 정했습니다. D-UF-051은 CK-06의 명백한 방식·규모·일정 충돌 시 전체 구체화 완료 보류와 이유·조정 대안 제시를 정했습니다. 실제 제작 검증은 강제하지 않습니다. D-UF-052는 CK-01 상품 선정 이유의 조건부 확인과 CK-03 고객 참여·구매 이유 필수 유지를 정했습니다. D-UF-053은 CK-01의 전체 구체화 완료 판정 기준을 합의했으며 다른 항목·U-02·전체 사용자 기능의 완료를 뜻하지 않습니다. D-UF-054는 CK-02 전체 구체화 완료 판정 기준을 합의하고 첫 접근·판매 실험 계획을 추가 필수로 두지 않도록 정했습니다. CK-01·02 기준 합의와 U-02·전체 사용자 기능 완료는 구분합니다. D-UF-055는 CK-03~06의 실제 진행안만 전체 완료 평가에 포함하는 범위를 정했습니다. 사용자 요청에 따른 P0 진척 점검은 9절에 기록합니다. D-UF-056은 가져오기 적용 대상이 모호할 때 반영을 보류하고 먼저 확인하는 동작을 정했습니다. D-UF-057은 실제 영향은 즉시 안내하되 연관된 저장 기획의 후속 검토는 명시적 사용자 요청 후 시작하고 일반 대화·기존 내부 평가 갱신·부분 제안과 실제 저장 경계는 유지하는 결정입니다. D-UF-058은 현재 초안의 선택한 변경 범위만 갱신하고 서버 확인 후 DRAFT를 유지하며 기존 UI 선택·검증·저장 보류 규칙을 유지하는 결정입니다. D-UF-059은 변경 영향 중심의 기본 후속 검토 범위를 필수 영향 안내 UX 강화 조건과 함께 채택하고, 요청 시 항목 전체 검토·검토 범위/남은 사항의 명시·저장 경계 유지를 정한 결정입니다. D-UF-060은 Q-LATEST-01 B안인 최신 결정의 변경 요약·사용자 편집안 반영 선택, D-UF-061은 Q-LATEST-02 A안인 저장 종류 유지·갱신된 내용에 대한 사용자 최종 반영 단추를 정했습니다. 실제 저장 흐름에서 별도 중간 적용·종류 재선택을 필수로 요구하지 않습니다. 이후 사용자는 웹 검색 MCP·프로젝트 컨텍스트 Chip의 사용자 계약에도 P0 논의가 남았다고 정정해 이를 우선 검토하도록 지시했습니다. 재저장·제안 가져오기·연관 검토를 CK-03~06 완료 기준보다 먼저 다루는 상대 순서는 유지합니다. 프로젝트 섹션별 컨텍스트 관리는 모듈 기능명세 M-01 상세 후속 항목으로 추가 기록합니다. 모듈 설계·구현은 진행하지 않습니다.

재정리 전 본문 전체의 공통 기준 1~38, UF-AI-01~15, AC-01~69와 화면 대응은 [합의 세부 참조본](agreement-details-v0.1.md)에 보존했습니다. 결정 기록의 기존 절·공통 기준·AC 번호는 그 참조본을 가리킵니다. 본문 요약에서 생략된 세부 합의도 폐기된 것이 아닙니다.

계층 구분은 다음 원칙을 따릅니다.

| 구분 | 이 단계에서 정할 것 | 예시 |
| --- | --- | --- |
| 사용자 기능에서 먼저 결정 | 사용자의 목적·선택·입력 범위·받을 결과·저장 의미·실패 시 다음 행동 | 어떤 가격 정보가 없으면 어떤 결과를 받을 수 있는지, 확정 내용을 수정하면 사용자에게 무엇을 보여줄지 |
| 공통 시스템과 공동 확인 | 사용자 결과에 영향을 주지만 팀원 담당 시스템과 함께 정해야 하는 경계 | 프로젝트·브랜드 권한, 삭제 후 참조, 금액의 포함 기준, 모델 이용 가능 여부·사용량 안내 |

모듈로 이관한다는 것은 기존 결정을 자유롭게 바꿔도 된다는 뜻이 아닙니다. 사용자 보장·기존 구현 제약은 설계 입력으로 가져갑니다. 금액에 영향을 주는 계산 기준, 사용자가 허용할 참조 범위, 보존·삭제의 사용자 보장처럼 결과가 달라지는 사항은 기술 용어가 포함돼도 사용자 기능·공통 계약에서 먼저 정해야 합니다.

## 2. 사용자 기능의 완료를 판단할 기준

사용자 기능명세의 완료는 모든 OPEN-UF 항목과 기술 미정이 사라지는 것으로 판단하지 않습니다. 대표 흐름에서 다음을 설명할 수 있어야 합니다.

1. 누가 어떤 목적으로 시작하며 이미 가진 자료와 새로 제공할 정보가 무엇인지.
2. AI가 설명·질문·제안·평가 중 무엇을 제공하고 사용자가 무엇을 수정·선택하는지.
3. 저장하지 않고 대화를 이어가는 경우, 초안 저장, 확정의 결과와 차이가 무엇인지.
4. 여섯 항목 각각의 필수 정보·허용 미정·기획상 충족 및 완료 기준이 무엇인지.
5. 재방문·재편집·새 정보·대표 실패에서 기존 저장 결과와 다음 행동이 어떻게 보이는지.
6. 아직 정하지 않은 항목이 사용자 결정인지 공통 시스템 의존인지 후속 구현 계약인지 추적 가능한지.

버튼 위치·문구 길이·내부 상태 코드·DB 필드까지 확정해야 위 의미가 완성되는 것은 아닙니다. 다만 어떤 사용자 동작을 언제 선택할 수 있는지, 어떤 결과를 신뢰할 수 있는지에 영향을 주는 의미는 남겨 두지 않습니다. 시스템 명세는 팀원 작성 대기이며 실제 권한·공통 기능의 연결은 별도 확인이 필요합니다.

상위 시스템 기능명세는 현행 README상 팀원 작성 대기입니다. C-01 권한·공통 데이터·삭제/참조, C-02 금액의 단위·포함 항목·사업 산식, C-03 모델·도구·첨부·보존 범위는 공동 확인으로 추적합니다. 이를 AI 모듈의 기본값으로 대신 확정하지 않습니다.

[모듈 기능명세](../03-module-feature-spec/README.md)는 실제 모듈 명세 작성 전이며, [이관 대장 M-01~08](../03-module-feature-spec/deferred-design-contracts.md)은 후속 계약 목록입니다. 에이전트 역할·컨텍스트 조립·도구·루프·저장·관찰의 실제 계약을 작성하거나 본 명세에 따른 구현·통합·실서비스 검증을 완료했다는 증거가 아닙니다. 이 점검은 기존 백엔드 전체의 개발 진척률을 평가하지 않습니다.

현재 작업 순서는 아래 네 묶음입니다. 사용자는 웹 검색 MCP·프로젝트 컨텍스트 Chip의 사용자 계약을 새 우선 검토 대상으로 지정했습니다. 기존 재저장·제안 가져오기·연관 검토 → CK-03~06 기준의 상대 순서는 유지하고 그 앞에 U-07의 P0 범위를 둡니다. 프로젝트 섹션별 컨텍스트 관리는 M-01에 후속 명세 범위로 기록하며 현재 사용자 Grill에서 내부 설계를 확정하지 않습니다.

1. [웹 검색·프로젝트 컨텍스트 Chip P0 질문지](context-and-web-grill.md)로 검색 시작·정보 사용·근거·실패와 Chip 드래그 앤 드롭·연결/참조·지속/제거·실제 사용 표시를 먼저 정합니다.
2. 초안 재저장·후보 가져오기·연관 검토의 잔여 사용자 동작을 점검합니다. 기존 합의·보류는 보존하고 C-01·02 공동 확인을 연결합니다.
3. 앞선 사용자 동작을 정리한 뒤 CK-03~06의 전체 완료 기준을 한 표에서 대조합니다. 기존 필수 정보·중요한 미정/충돌·D-UF-055의 진행안 범위를 기반으로 영역별 판단을 좁힙니다.
4. R-01~04를 읽으며 웹 검색·컨텍스트 사용을 포함한 남은 P0와 P1·공동·모듈 계약을 구분하고 종료 여부를 판단합니다. 하위 구현 예외를 늘리기보다 사용자에게 보장할 동작·결과·실패/보류 의미가 연결됐는지 확인합니다.
