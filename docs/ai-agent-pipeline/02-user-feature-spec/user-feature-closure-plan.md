## 1. 이번 정리의 범위와 해석

2026-10-30 재정리에서는 기존 합의를 바꾸지 않고 남은 일을 사용자 기능·공통 시스템 연계·모듈 설계로 구분했습니다. 당시 우선순위·대표 사례는 새 기능·필수 입력·완료 규칙의 채택이 아니었습니다. 2026-11-02 사용자 요청으로 P0 사용자 기능 Grill을 재개했으며, 후속 합의만 8절과 결정 기록에 추가합니다. D-UF-001~030은 그대로 유지하고 D-UF-031~035를 추가했습니다. 모듈 설계·구현은 진행하지 않습니다.

재정리 전 본문 전체의 공통 기준 1~38, UF-AI-01~15, AC-01~69와 화면 대응은 [합의 세부 참조본](agreement-details-v0.1.md)에 보존했습니다. 결정 기록의 기존 절·공통 기준·AC 번호는 그 참조본을 가리킵니다. 본문 요약에서 생략된 세부 합의도 폐기된 것이 아닙니다.

계층 구분은 다음 원칙을 따릅니다.

| 구분 | 이 단계에서 정할 것 | 예시 |
| --- | --- | --- |
| 사용자 기능에서 먼저 결정 | 사용자의 목적·선택·입력 범위·받을 결과·저장 의미·실패 시 다음 행동 | 어떤 가격 정보가 없으면 어떤 결과를 받을 수 있는지, 확정 내용을 수정하면 사용자에게 무엇을 보여줄지 |
| 공통 시스템과 공동 확인 | 사용자 결과에 영향을 주지만 팀원 담당 시스템과 함께 정해야 하는 경계 | 프로젝트·브랜드 권한, 삭제 후 참조, 금액의 포함 기준, 모델 이용 가능 여부·사용량 안내 |
| 모듈 설계로 이관 | 위 동작을 동일하게 구현하기 위한 구조·인터페이스·실행 기법 | Projection 응답 스키마, 참조 버전 기록, 요청 식별·중복 방지, 실행 상태·도구 입출력 |
| 이미 확정된 제약 | 사용자 보장과 이미 합의한 구체적인 실행 원칙 모두 유지 | D-UF-006·026의 시작 직전 재조회, D-UF-008·009의 버전 경계, D-UF-027~030의 보류·재개·종료 원칙 |

모듈로 이관한다는 것은 기존 결정을 자유롭게 바꿔도 된다는 뜻이 아닙니다. 사용자 보장·기존 구현 제약은 설계 입력으로 가져갑니다. 금액에 영향을 주는 계산 기준, 사용자가 허용할 참조 범위, 보존·삭제의 사용자 보장처럼 결과가 달라지는 사항은 기술 용어가 포함돼도 사용자 기능·공통 계약에서 먼저 정해야 합니다.

## 2. 사용자 기능의 완료를 판단할 기준

사용자 기능명세의 완료는 모든 OPEN-UF 항목과 기술 미정이 사라지는 것으로 판단하지 않습니다. 대표 흐름에서 다음을 설명할 수 있어야 합니다.

1. 누가 어떤 목적으로 시작하며 이미 가진 자료와 새로 제공할 정보가 무엇인지.
2. AI가 설명·질문·제안·평가 중 무엇을 제공하고 사용자가 무엇을 수정·선택하는지.
3. 저장하지 않고 대화를 이어가는 경우, 초안 저장, 확정의 결과와 차이가 무엇인지.
4. 여섯 항목 각각의 필수 정보·허용 미정·기획상 충족 및 완료 기준이 무엇인지.
5. 재방문·재편집·새 정보·대표 실패에서 기존 저장 결과와 다음 행동이 어떻게 보이는지.
6. 아직 정하지 않은 항목이 사용자 결정인지 공통 시스템 의존인지 후속 구현 계약인지 추적 가능한지.

버튼 위치·문구 길이·내부 상태 코드·DB 필드까지 확정해야 위 의미가 완성되는 것은 아닙니다. 다만 어떤 사용자 동작을 언제 선택할 수 있는지, 어떤 결과를 신뢰할 수 있는지에 영향을 주는 의미는 남겨 두지 않습니다. 시스템 명세는 팀원 작성 대기이며 실제 권한·공통 기능의 연결은 별도 확인이 필요합니다.

D-UF-034에 따라 내부 기획 구체화가 미완료여도 남은 미정·영향을 안내하고 사용자가 명시적으로 확정할 수 있습니다. 확정만으로 내부 평가를 완료로 바꾸지 않습니다. 여섯 항목의 필수 정보·허용 미정·완료 기준은 여전히 평가에서 필요하며, 기존 서버 검증·제안 저장 보류·명시적 재검토는 유지합니다.

대표 흐름은 기존 기능 초안을 함께 읽기 위한 검토 사례입니다. 화면을 추가하거나 서비스 이용 순서를 고정한 것은 아닙니다.

| 흐름 | 상황·시작 | 검토할 사용자 동작·결과 | 이미 정한 경계 | 남은 쟁점·연결 |

| R-01 상품은 있으나 판매 방법이 막힘 | 프로젝트 연결 Chat에서 보유 상품·현재 고민을 설명 | 현재 자료로 우선 문제·이유·가정과 작은 도움 → 관련 항목의 평가·대안 → 구체안이 생기면 필요한 부분을 편집·저장 검토용 제안으로 제공 → 사용자 수정·항목 선택 → 초안 저장 또는 확정 → 저장 결과 확인 | D-UF-031·032: 사용자 방향 변경 가능, 별도 정리 요청은 필수 아님, 매 응답 제안 의무 없음. 기존 상품 재선정·고정 순서 강제 없음, 추천·제안만으로 진행 대상 지정·저장하지 않음 | 첫 도움·제안 제공 계기는 부분 결정. 항목별 결과·완료, 제안 비교·선택·저장 의미는 잔여 OPEN / U-01~05 / UF-AI-01·02·05~12 |

정상 종료는 매번 저장하는 것이 아닙니다. 설명이나 미저장 제안을 얻고 대화를 이어가는 결과도 포함합니다. 저장을 선택했다면 서버가 확인한 DRAFT·DECIDED 결과가 별도로 보여야 합니다.
