## 1. 이번 정리의 범위와 해석

2026-10-30 재정리에서는 기존 합의를 바꾸지 않고 남은 일을 사용자 기능·공통 시스템 연계·모듈 설계로 구분했습니다. 당시 우선순위·대표 사례는 새 기능·필수 입력·완료 규칙의 채택이 아니었습니다. 2026-11-02 사용자 요청으로 P0 사용자 기능 Grill을 재개했으며, 후속 합의만 8절과 결정 기록에 추가합니다. D-UF-001~030은 그대로 유지하고 D-UF-031~080을 추가했습니다. D-UF-041의 최종 채택은 B안인 저장·확정의 명시적 UI 선택 필수이며, D-UF-042의 직접 재확정과 D-UF-043·044의 항목별 저장 종류 선택·함께 반영·부분 반영도 이를 유지합니다. D-UF-045는 실제 영향이 확인된 다른 항목의 짧은 안내와 저장 내용·상태 유지를 정했습니다. D-UF-046은 미저장 편집안 유지·새 후보 비교·선택 부분 가져오기를 정했습니다. D-UF-047은 CK-05의 판매 단위에 적용할 기획용 가격·범위를 필수로 두고 최종 판매가 확정은 요구하지 않는 결정을 추가했습니다. D-UF-048은 중요한 비용 미정 시 CK-05 전체 구체화 완료 보류와 설명 가능한 추정·범위 허용·실제 견적/실측 비강제를 정했습니다. D-UF-049는 기획 선택에 미치는 영향으로 비용 중요성을 판단하고 AI가 구체적인 영향·이유를 설명하도록 정했습니다. D-UF-050은 CK-06 핵심 구성품의 제작·조달 방식 가설을 필수로 두되 업체 확정·계약·실제 제작 검증은 요구하지 않도록 정했습니다. D-UF-051은 CK-06의 명백한 방식·규모·일정 충돌 시 전체 구체화 완료 보류와 이유·조정 대안 제시를 정했습니다. 실제 제작 검증은 강제하지 않습니다. D-UF-052는 CK-01 상품 선정 이유의 조건부 확인과 CK-03 고객 참여·구매 이유 필수 유지를 정했습니다. D-UF-053은 CK-01의 전체 구체화 완료 판정 기준을 합의했으며 다른 항목·U-02·전체 사용자 기능의 완료를 뜻하지 않습니다. D-UF-054는 CK-02 전체 구체화 완료 판정 기준을 합의하고 첫 접근·판매 실험 계획을 추가 필수로 두지 않도록 정했습니다. CK-01·02 기준 합의와 U-02·전체 사용자 기능 완료는 구분합니다. D-UF-055는 CK-03~06의 실제 진행안만 전체 완료 평가에 포함하는 범위를 정했습니다. 사용자 요청에 따른 P0 진척 점검은 9절에 기록합니다. D-UF-056은 가져오기 적용 대상이 모호할 때 반영을 보류하고 먼저 확인하는 동작을 정했습니다. D-UF-057은 실제 영향은 즉시 안내하되 연관된 저장 기획의 후속 검토는 명시적 사용자 요청 후 시작하고 일반 대화·기존 내부 평가 갱신·부분 제안과 실제 저장 경계는 유지하는 결정입니다. D-UF-058은 현재 초안의 선택한 변경 범위만 갱신하고 서버 확인 후 DRAFT를 유지하며 기존 UI 선택·검증·저장 보류 규칙을 유지하는 결정입니다. D-UF-059은 변경 영향 중심의 기본 후속 검토 범위를 필수 영향 안내 UX 강화 조건과 함께 채택하고, 요청 시 항목 전체 검토·검토 범위/남은 사항의 명시·저장 경계 유지를 정한 결정입니다. D-UF-060은 Q-LATEST-01 B안인 최신 결정의 변경 요약·사용자 편집안 반영 선택, D-UF-061은 Q-LATEST-02 A안인 저장 종류 유지·갱신된 내용에 대한 사용자 최종 반영 단추를 정했습니다. 실제 저장 흐름에서 별도 중간 적용·종류 재선택을 필수로 요구하지 않습니다. D-UF-062는 WEB-01 A안인 Chat의 명시적 검색 허용 후 필요한 검색의 AI 실행·사용자 이후 끄기·검색 상태 표시를 정했습니다. 검색 입력·결과·제한과 Chip의 연결/참조 의미는 이후 결정과 잔여 미정으로 구분합니다. 이후 사용자는 웹 검색 MCP·프로젝트 컨텍스트 Chip의 사용자 계약에도 P0 논의가 남았다고 정정해 이를 우선 검토하도록 지시했습니다. 재저장·제안 가져오기·연관 검토를 CK-03~06 완료 기준보다 먼저 다루는 상대 순서는 유지합니다. 프로젝트 섹션별 컨텍스트 관리는 모듈 기능명세 M-01 상세 후속 항목으로 추가 기록합니다. D-UF-063은 CHIP-01 A안인 프로젝트 Chip의 참조 첨부·저장 연결 분리와 다른 프로젝트 참조를, D-UF-064는 프로젝트 생성 선행·프로젝트와 AI Chat 1:1을 정했습니다. 독립 Chat 사후 연결과 Chat에서 생성 후 복귀 경로는 D-UF-064로 대체하며 기존 원문은 보존합니다. D-UF-065는 CHIP-02 A안인 제거 전까지 Chat의 활성 참조 유지·제거 후 이후 활성 참조 제외를 정했습니다. 과거 B 정보 재사용은 후속 D-UF-066을 따르며 기존 A 결정·저장 내용과 실제 참조 버전 검증은 유지합니다. D-UF-066은 과거 이력을 유지하면서 제거한 B 고유 정보의 자동 재사용은 제외하고 A에 저장했거나 명시적으로 채택한 결정은 유지하도록 정했습니다. D-UF-067은 WEB-02 A안인 일반화된 특성과 사용자가 검색 사용을 명시한 내용만 기본 검색 입력에 포함하는 결정을 정했습니다. 내부 참고·A 저장/채택을 외부 전송 허용으로 간주하지 않습니다. D-UF-068은 WEB-03 A안인 필요한 검색 결과의 AI 선택과 핵심 주장별 출처·확인 범위·한계 표시, 사용자 자료 제외·추가 검토 요청을 정했습니다. 검색 근거와 기획 가설·현재 사용자 결정·실제 저장은 구분합니다. D-UF-069는 CHIP-03 A안인 실제 참고 범위·누락 영향 안내와 가능한 부분 제안 지속, 읽지 못한 자료가 필요한 판단 보류를 정했습니다. 기존 Projection 조회 실패·명시적 재시도 규칙은 유지합니다. D-UF-070은 WEB-04 A안인 허용 범위 내 AI 보완 검색과 진전 없음/한도 도달 시 중단, 확인 내용·남은 한계·보류 판단 안내를 정했습니다. 기존 검색 허용/끄기·입력 범위·Projection 명시적 재시도·저장 경계는 유지합니다. D-UF-071은 WEB-05 A안인 검색 끄기 후 도착한 결과의 현재 답변 새 근거 제외와 기존 자료 기반 답변·보류 판단 안내, 실제 검색 취소와의 구분을 정했습니다. D-UF-072는 WEB-06 A안인 검색 끄기 전 확인 자료의 출처·확인 시점·한계와 함께 재사용, 최신 확인이 필요한 판단 보류를 정했습니다. 새 검색 금지·늦은 결과 제외·자료 제외/권한·기획/저장 경계는 유지합니다. D-UF-073은 WEB-07 A안인 해당 Chat에서 재허용 전까지 자료 제외 유지·사용자 명시 적용 범위 우선·기존 기획/저장 상태 자동 변경 금지를 정했습니다. 웹 검색·Chip 기본 동작의 합의와 잔여 공동/후속 계약을 구분하고 D-UF-074는 SAVE-01 A안인 한 항목 전체 비우기 후 내용 없음/UNSET 복귀·최종 선택 전 확정 해제 영향 안내·다른 항목 자동 변경 금지를 정했습니다. 기존 권한/대상/버전 검증·저장 보류·서버 확인은 유지합니다. D-UF-075는 SAVE-02 A안인 저장 결과 미확인 안내·자동 결과 확인·확인된 결과 또는 미확인 안내를 정했습니다. 같은 변경의 자동 재전송과 기존 기획/편집/저장 상태의 임의 변경은 하지 않습니다. 2026-11-03 사용자 지시로 이후 검토는 대표 사용자 흐름의 목적·요청·보이는 결과·선택에 한정하고 실행 세부는 모듈 설계로 미룹니다. 이후 대표 흐름 질문 세트를 제시했고, 사용자는 다섯 A안을 모두 채택했습니다. D-UF-076은 연결된 기획 대안, D-UF-077~080은 CK-03~06 전체 완료 기준입니다. 남은 P0는 12절의 기존 보류·공동 사용자 계약·대표 흐름 연결 점검으로 정리하며 실행 세부 질문은 늘리지 않습니다. 모듈 설계·구현은 진행하지 않습니다.

재정리 전 본문 전체의 공통 기준 1~38, UF-AI-01~15, AC-01~69와 화면 대응은 [합의 세부 참조본](agreement-details-v0.1.md)에 보존했습니다. 결정 기록의 기존 절·공통 기준·AC 번호는 그 참조본을 가리킵니다. 본문 요약에서 생략된 세부 합의도 폐기된 것이 아닙니다.

계층 구분은 다음 원칙을 따릅니다.

| 구분 | 이 단계에서 정할 것 | 예시 |
| --- | --- | --- |
| 사용자 기능에서 먼저 결정 | 사용자의 목적·선택·입력 범위·받을 결과·저장 의미·실패 시 다음 행동 | 어떤 가격 정보가 없으면 어떤 결과를 받을 수 있는지, 확정 내용을 수정하면 사용자에게 무엇을 보여줄지 |
| 공통 시스템과 공동 확인 | 사용자 결과에 영향을 주지만 팀원 담당 시스템과 함께 정해야 하는 경계 | 프로젝트·브랜드 권한, 삭제 후 참조, 금액의 포함 기준, 모델 이용 가능 여부·사용량 안내 |

모듈로 이관한다는 것은 기존 결정을 자유롭게 바꿔도 된다는 뜻이 아닙니다. 사용자 보장·기존 구현 제약은 설계 입력으로 가져갑니다. 금액에 영향을 주는 계산 기준, 사용자가 허용할 참조 범위, 보존·삭제의 사용자 보장처럼 결과가 달라지는 사항은 기술 용어가 포함돼도 사용자 기능·공통 계약에서 먼저 정해야 합니다.

## 2. 사용자 기능의 완료를 판단할 기준

사용자 기능명세의 완료는 모든 OPEN-UF 항목과 기술 미정이 사라지는 것으로 판단하지 않습니다. 대표 흐름에서 다음을 설명할 수 있어야 합니다.

1. 누가 어떤 목적으로 시작하며 이미 가진 자료와 새로 제공할 정보가 무엇인지.
2. AI가 설명·질문·제안·평가 중 무엇을 제공하고 사용자가 무엇을 수정·선택하는지.
3. 저장하지 않고 대화를 이어가는 경우, 초안 저장, 확정의 결과와 차이가 무엇인지.
4. 여섯 항목 각각의 필수 정보·허용 미정·기획상 충족 및 완료 기준이 무엇인지.
5. 재방문·재편집·새 정보·대표 실패에서 기존 저장 결과와 다음 행동이 어떻게 보이는지.
6. 아직 정하지 않은 항목이 사용자 결정인지 공통 시스템 의존인지 후속 구현 계약인지 추적 가능한지.

버튼 위치·문구 길이·내부 상태 코드·DB 필드까지 확정해야 위 의미가 완성되는 것은 아닙니다. 다만 어떤 사용자 동작을 언제 선택할 수 있는지, 어떤 결과를 신뢰할 수 있는지에 영향을 주는 의미는 남겨 두지 않습니다. 시스템 명세는 팀원 작성 대기이며 실제 권한·공통 기능의 연결은 별도 확인이 필요합니다.

현재 작업 순서는 아래 네 묶음입니다. 사용자는 웹 검색 MCP·프로젝트 컨텍스트 Chip의 사용자 계약을 새 우선 검토 대상으로 지정했습니다. 기존 재저장·제안 가져오기·연관 검토 → CK-03~06 기준의 상대 순서는 유지하고 그 앞에 U-07의 P0 범위를 둡니다. 프로젝트 섹션별 컨텍스트 관리는 M-01에 후속 명세 범위로 기록하며 현재 사용자 Grill에서 내부 설계를 확정하지 않습니다.

2. [대표 흐름 기반 P0 질문 세트](p0-user-flow-grill-sets.md)의 세트 1부터 사용자에게 제공할 결과의 범위를 검토합니다. SAVE-01·02와 편집·저장·명시적 후속 검토의 기존 합의 및 이전 보류를 유지합니다. 이후 세트 2·3의 CK-03~06 전체 충분조건으로 넘어갑니다.
3. CK-01~06의 전체 구체화 완료 기준은 합의했습니다. 대표 사례에서 중요한 미정·충돌과 기획상 완료/실제 검증/저장 상태의 구분을 대조하고, 필요한 C-02 공동 기준을 확인합니다.
4. R-01~04를 읽으며 웹 검색·컨텍스트 사용을 포함한 남은 P0와 P1·공동·모듈 계약을 구분하고 종료 여부를 판단합니다. 하위 구현 예외를 늘리기보다 사용자에게 보장할 동작·결과·실패/보류 의미가 연결됐는지 확인합니다.

## 17. 저장 기획 이력을 문서로 여는 경량 합의 — 2026-11-03
