# 파일 첨부·이미지 분석: 다음 사용자 시나리오 검토

작성일: 2026-11-03 · 상태: **FS-01~03 A 채택 / FS-04 A는 기존 원칙 적용 확인 / D-UF-086~089 / 공동 계약 연결 대기** · 연결: UF-AI-03·05·08·13·14 / R-04·05 / OPEN-UF-04·10·12·14

[파일·이미지 사용자 기능명세](file-and-image-user-feature-spec-v0.1.md)의 D-UF-081~089를 기준으로 사용자 흐름을 정리합니다. FS-01~03은 A로 채택했고 FS-04도 A를 채택했으나, 사용자는 이미 정한 원칙을 기술적 예외로 다시 질문했다고 지적했습니다. FS-04는 기존 확인 자료 재사용·부분 검토 원칙을 파일 재방문에 적용한 확인으로 분류하며 새로운 독립 사용자 기능으로 취급하지 않습니다. 당시 대안·채택 이력은 보존합니다.

## 1. 검토 순서와 기존 합의

| 순서 | 사용자 시나리오 | 현재 상태·결정할 결과 |
| --- | --- | --- |
| 합의 / FS-01 A | 파일만 전송해 대화를 시작 | D-UF-086: 실제 확인한 내용의 짧은 요약·다음 행동 제안, 사용자 방향 선택/변경 |
| 합의 / FS-02 A | 함께 검토할 자료 중 일부를 읽지 못함 | D-UF-087: 가능한 부분 검토·누락 영향·보류 판단·다음 자료 보완 선택 안내 |
| 합의 / FS-03 A | 분석 근거로 사용한 첨부 원문 확인 | D-UF-088: Chat에서 실제 분석에 사용한 원문을 열기/다운로드할 경로 제공. 실제 접근·제공 범위는 공동 계약과 연결 |
| 적용 확인 / FS-04 A | 재방문 시 원문을 일시적으로 불러오지 못함 | D-UF-089: 과거 실제 확인 내용을 출처·당시 확인 시점·현재 한계와 함께 재사용. 최신/원문 확인이 필요한 판단은 보류. 기존 원칙의 적용으로 분류 |
| 정합성 확인 / FS-CHECK-01 | 새 견적으로 저장한 기획 재검토 | 기존 합의로 설명 가능. 자동 저장·최신 사용자 결정의 덮어쓰기를 허용하는 새 질문은 하지 않음 |

허용 여섯 확장자, 요청에 맞는 이미지 기획 제안, 제거 전 활성 참조·목록, 제거 파일 정보의 자동 재사용 제외·사용자 채택/저장 결정 유지, Word 본문·표·삽입 이미지의 통합 분석 대상 지원은 이미 합의했습니다. 이 세트는 그 결정을 다시 묻지 않습니다.

## 2. FS-01 파일만 전송한 사용자의 첫 도움 — A 채택 / D-UF-086

**상황:** 사용자가 제품 사진이나 펀딩 기획서를 첨부한 뒤 별도의 질문 없이 전송합니다. 원하는 도움을 어떻게 표현할지 아직 모를 수 있습니다. 단순히 파일을 선택한 순간과, 파일을 Chat 메시지로 보낸 행동은 구분합니다.

**사용자 목적:** 자료를 바탕으로 대화를 시작하고 다음에 무엇을 해 볼지 알기.

| 대안 | 첫 응답에서 받는 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 실제 확인한 내용의 짧은 요약과 현재 프로젝트에 맞는 소수의 다음 행동을 제안하고 사용자가 방향을 선택·변경 | 막연한 사용자도 도움을 얻고 시작하기 쉽지만 목적이 정해지기 전 내용 파악·방향 제안이 발생 |
| B · 미채택 | “어떤 도움을 원하시나요?”처럼 목적을 먼저 확인하고, 답을 받은 뒤 본격적인 내용 분석·제안 | 원하지 않는 작업을 줄일 수 있지만 파일을 보낸 뒤에도 사용자가 요청을 한 차례 더 구성해야 함 |

**권장 이유:** A는 기존의 막연한 고민에 작은 도움을 먼저 주는 원칙(D-UF-031)을 파일로 시작하는 상황에 연결합니다. 다만 파일 전송을 여섯 체크리스트 전체 평가·명시적 재검토·저장 요청으로 확대하지 않습니다.

어느 안이든 실제 읽지 못한 내용을 요약하지 않고, 읽힌 범위·한계를 구분합니다. 기존 기획·미저장 편집안·저장 상태를 자동 변경하지 않습니다. 첫 응답의 정형 문구·버튼 배치·자동 처리 기법은 이번 질문에서 정하지 않습니다.

**결정:** 사용자 A 채택. 질문 없이 파일만 Chat 메시지로 전송하면 실제 확인한 내용의 짧은 요약과 다음 행동을 제안합니다. 단순 파일 선택을 전송과 동일하게 취급하지 않으며, 읽지 못한 내용의 요약·전체 체크리스트 평가·명시적 재검토·저장으로 확대하지 않습니다.

## 3. FS-02 함께 검토할 자료 중 일부를 읽지 못함 — A 채택 / D-UF-087

**상황:** 사용자가 기획서와 견적서를 보내 “이 구성으로 가격을 검토해 줘”라고 요청했습니다. 기획서는 읽었지만 견적서는 잠금·손상·불명확한 내용 등으로 필요한 금액·조건을 확인하지 못했습니다.

**사용자 목적:** 무엇까지 검토됐는지 이해하고, 현재 가능한 도움과 자료 보완 중 다음 행동을 선택하기.

| 대안 | 받는 결과·다음 선택 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | 실제 읽힌 자료로 가능한 부분 검토·제안을 제공. 읽지 못한 자료와 누락 영향을 알리고 그 자료가 필요한 가격/전체 비교 판단은 보류. 재제공하거나 범위를 좁혀 이어갈 수 있음 | 작업을 이어갈 수 있지만 부분 결과를 전체 검토 완료로 오해하지 않도록 결과·보류를 명확히 구분해야 함 |
| B · 미채택 | 해당 전체 비교의 본격적인 검토는 보류하고 누락·보완 방법을 먼저 안내. 필요한 자료가 갖춰진 후 함께 검토 | 하나의 완결된 비교를 받기 쉽지만 이미 읽힌 자료로 가능한 도움도 뒤로 밀림 |

**기존 보장:** 읽지 못한 자료를 읽었다고 하거나 누락 금액을 임의 값·0으로 채우거나 확인되지 않은 전체 손익·기획 완료를 단정하지 않습니다. B도 일반 Chat 전체를 막는 선택은 아닙니다. 어느 안이든 기존 기획·편집안·저장 상태는 자동 변경하지 않습니다.

**권장 이유:** A는 자료가 일부 부족해도 가능한 작업을 이어가려는 사용자에게 유용합니다. B는 모든 자료를 갖춘 하나의 비교 결과를 우선하는 선택입니다. 실패 원인별 기술 복구·자동 재시도 여부·횟수는 이 질문에서 정하지 않습니다. 기존 Projection 조회 실패·명시적 재시도 규칙도 유지합니다.

**결정:** 사용자 A 채택. 실제 읽힌 자료로 가능한 부분 검토를 제공하고 실제 참고 범위·누락 영향·보류 판단을 구분합니다. 사용자는 필요한 자료를 다시 제공하거나 범위를 좁혀 이어갈 수 있습니다. 중요한 금액을 임의 값·0으로 채우지 않으며 부분 결과를 전체 비교·기획 완료로 표시하지 않습니다.

## 4. FS-03 분석 근거로 사용한 첨부 원문 확인 — A 채택 / D-UF-088

**상황:** AI가 견적서의 수량을 100개로 읽고 가격 제안을 했습니다. 사용자는 문서에 적힌 조건과 맞는지 직접 확인하고 싶습니다. 현재 접근 가능한 활성 첨부를 근거로 삼은 답변에서 어떤 확인 경로를 제공할 것인가?

| 대안 | 사용자 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 | Chat의 첨부/근거 표시에서 실제 분석에 사용한 원문을 열거나 다운로드할 수 있는 경로 제공. 파일 형식·지원 범위에 따라 확인 방식 안내 | 자료를 다시 찾지 않고 결과와 원문을 대조하기 편하지만 원문 접근·제공 범위를 공통 파일 관리와 함께 정해야 함 |
| B · 미채택 | Chat에서는 파일 식별·관련 발췌·실제 확인 범위를 제공하고 원문 열기/다운로드는 별도 지원하지 않음. 원문은 사용자가 보유한 파일 등으로 대조 | 초기 Chat 제공 범위는 줄지만 원문을 직접 찾고 대조하는 부담이 사용자에게 남음 |

**권장 이유:** A는 이미지 문자·견적 조건처럼 확인이 중요한 판단을 사용자가 검토하는 경로를 제공합니다. 새 파일이나 다른 문서를 과거 분석에 사용한 원문인 것처럼 보여주면 안 됩니다. B에서도 확인 범위·한계를 과장하지 않는 기존 보장은 유지합니다.

**공동 경계:** 어느 안도 원문 영구 보존·권한 밖 접근을 보장하지 않습니다. 보존·접근·구체적 제공 범위는 C-01·03과 연결합니다. 원문 확인은 AI의 추가 분석·검색 허용·기획 저장 선택을 대신하지 않으며 제거 파일 정보의 자동 재사용 제외 원칙도 유지합니다. 파일 뷰어·저장 URL·버전 필드·전달 API는 이번 질문에서 정하지 않습니다.

**결정:** 사용자 A 채택. Chat의 첨부·근거 표시에서 실제 분석에 사용한 원문을 열거나 다운로드할 경로를 제공합니다. 파일 형식·실제 제공 범위에 맞춰 확인 방식을 안내하며 다른 파일·새 수정본을 과거 분석 원문인 것처럼 제공하지 않습니다. 원문을 이용할 수 없으면 이용 불가를 알리고 확인 성공으로 표시하지 않습니다. 원문 접근·제공·보존·권한은 공동 계약으로 연결하며 확인만으로 AI 재분석·기획 저장을 실행하지 않습니다.

## 5. FS-04 재방문 시 원문을 일시적으로 불러오지 못함 — A 적용 확인 / D-UF-089

**상황:** 며칠 뒤 같은 Chat에서 기존 견적서로 가격 기획을 이어가려 합니다. 파일은 활성 목록에 있고 이전에 정상적으로 읽은 단가·수량의 설명도 남아 있지만, 지금은 원문을 일시적으로 불러오지 못합니다. 그 과거 내용을 자동으로 다시 참고할 수 있는가?

**적용 범위:** 사용자가 참조를 제거하거나 원문을 삭제한 경우, 권한을 상실한 경우는 이 시나리오에 포함하지 않습니다. 제거 파일의 자동 재사용 제외(D-UF-084)와 별도 삭제·권한 정책을 우회하는 대안이 아닙니다. 원문이 없는 파일을 새로 읽었다고 표시하지 않는 기준은 공통으로 유지합니다.

| 대안 | 사용자 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 / 적용 확인 | 과거에 실제 확인한 내용은 출처·당시 확인 시점·현재 원문 대조 불가의 한계와 함께 재사용. 지금 원문을 읽어야 하거나 최신 확인이 필요한 판단은 보류 | 대화·기획을 이어가기 쉽지만 과거 근거와 현재 확인 사실을 명확히 구분해야 함 |
| B · 미채택 | 원문을 다시 읽거나 사용자가 자료를 재제공하기 전까지 해당 파일 유래 정보의 자동 사용을 보류. 사용자 채택/저장 결정과 다른 유효 자료로 가능한 대화는 지속 | 확인 가능한 원문 중심으로 판단하지만 이전에 읽은 내용이 있어도 자료 보완 부담이 생김 |

**권장 이유:** A는 일시적인 원문 이용 불가 때문에 이미 확인한 자료를 이용한 대화가 모두 끊기는 부담을 줄입니다. 과거 AI 추론·미확인 문자를 실제 확인한 원문 내용으로 바꾸거나, 과거 단가를 현재 견적으로 확인했다고 표시하면 안 됩니다.

**기존 경계:** 두 안 모두 기존 기획·미저장 편집안·저장 상태를 자동 변경하지 않습니다. Projection 조회 실패의 평가 보류·명시적 재시도, 중요한 비용 미정·총원가/최종 이익 판단 보류도 유지합니다. A로 원문 재조회·평가/저장 보류가 해소됐다고 표시하지 않습니다.

**적용 확인:** 사용자 A 채택. 과거 실제 확인 내용은 출처·당시 확인 시점·현재 원문 대조 불가의 한계와 함께 재사용하고 최신/원문 확인이 필요한 판단은 보류합니다. 사용자는 이 사안을 이미 정한 원칙의 반복으로 지적했습니다. D-UF-072의 확인 자료 재사용 기조와 D-UF-087의 부분 검토·보류 원칙을 파일 재방문에 적용한 확인으로 기록하며 동일 원칙을 실패 원인별로 다시 질문하지 않습니다. 제거·삭제·권한 상실과 기존 Projection 재조회·저장 보류는 별도 경계를 유지합니다.

## 6. FS-CHECK-01 새 견적으로 저장한 기획을 발전 — 기존 합의 적용

**상황:** 단가 3,500원 가정으로 저장한 기획이 있고, 새 견적에는 5,000원이 적혀 있습니다. 사용자가 “새 견적 기준으로 가격을 검토해 줘”라고 요청합니다.

1. 실제 읽힌 새 견적의 금액·조건과 현재 기획의 가정을 구분하고 차이·영향·미정을 설명합니다. 현재 기획의 채택값과 파일의 진술을 같은 사실로 합치지 않습니다.
2. 사용자 요청에 맞춰 필요한 가격 검토·편집용 대안을 제공합니다. 중요한 비용·사업 계산 기준이 미정이면 기존 부분 계산·판단 보류를 유지합니다.
3. 새 파일의 도착·분석만으로 저장된 기획을 덮어쓰지 않습니다. 기존 미저장 편집안은 유지하며 필요한 변경을 사용자가 선택합니다.
4. 실제 반영은 기존 UI의 저장 종류·최종 반영 선택, 서버 검증·저장 보류·결과 확인을 따릅니다. 참조 파일을 나중에 제거해도 사용자가 채택·저장한 결정은 자동 삭제하지 않습니다.

연결: D-UF-038·041·044·046·057·060·061·082·084·085. 위 흐름은 기존 합의로 설명되므로 새 A·B 질문을 만들지 않습니다. 대표 사례를 읽으며 설명되지 않는 사용자 결과가 발견될 때만 추가 결정으로 올립니다.

## 7. 세트 이후 남는 공동 계약

정확한 파일 개수·용량·문서 길이·처리 품질의 제공 한도, 원문 보존·재방문 이용 가능 범위·삭제·권한은 C-01·03과 함께 정해야 합니다. 이 질문 세트의 A 채택만으로 수치를 정하거나 모든 파일 처리·원문 영구 보존을 보장하지 않습니다.

Word의 본문·표·삽입 이미지를 분석 대상으로 지원한다는 D-UF-085와 모든 내용을 빠짐없이 읽었다는 표시는 구분합니다. 기본 분석 범위의 합의를 구현·운영 품질의 검증 완료로 보고하지 않습니다.

## 8. 이후 사용자 기능 검토

이후 검토는 새로운 사용자 목적·선택·결과가 달라지는 항목으로 진행합니다. 재조회·복구·수치 한도·캐시·컨텍스트 구성은 기존 보장과 공동 계약·모듈 설계에 연결하고 동일 원칙을 새 Grill로 분해하지 않습니다. 현재 파일·이미지에서 남은 제공 조건·보존·권한은 공동 확인으로 추적합니다.

파일 이외의 사용자 목적별 기능은 [정리·완료 계획](user-feature-closure-plan.md)에서 추적하고, 기획 결과 전달의 합의는 [EXPORT-01](project-export-user-scenario.md)에서 읽습니다. 현재 보류·공동 P0는 유지하며 기술적 예외 질문으로 확장하지 않습니다.
