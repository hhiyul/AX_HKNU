# 저장된 기획 이력을 불러와 편집하는 사용자 흐름 — HISTORY-01 합의

작성일: 2026-11-03 · 상태: **A 채택·경량화 정정 / D-UF-092** · 연결: U-08 / OPEN-UF-12·13·14 / C-01·03 / R-03

## 1. 사용자 시나리오

사용자가 단품 구성·가격으로 기획을 저장했다가 이후 선물 세트 구성으로 바꿔 저장했습니다. 이전에 저장했던 단품 기획을 다시 열어 문서에서 직접 수정하고 싶어 합니다.

사용자 목적은 저장된 이력을 불러와 바로 편집하는 것입니다. 사용자가 말한 Google Docs와 같은 경험은 이력 내용을 편집 가능한 문서로 연다는 의미로 반영합니다. 현재 작성 중인 입력·편집안을 인메모리로 보관하는 RESUME-01과는 구분합니다.

## 2. HISTORY-01 이력 불러오기·문서 편집 — A 경량화 채택 / D-UF-092

| 대안 | 사용자에게 제공할 결과 | 트레이드오프 |
| --- | --- | --- |
| A · 채택 / 경량화 | 제공하는 보존 범위에서 저장된 이력을 선택해 편집 가능한 문서로 열고 직접 수정. 별도 전후 비교 UI를 제공 범위에 넣지 않음 | 과거 안을 다시 작성하는 부담을 줄이고 흐름이 단순하지만 변경 차이를 별도 비교 화면으로 보여주지는 않음 |
| B · 미채택 | 현재 저장 기획을 관리하고 과거 대화·제안은 남아 있는 범위에서 참고. 이전 저장 기획을 정확히 다시 여는 기능은 제공하지 않음 | 기능 범위는 단순해지지만 과거 기획은 사용자가 자료를 찾아 다시 구성해야 할 수 있음 |

**최종 범위 정정:** 최초 A 제안에는 현재 기획과의 비교·필요 부분을 편집 후보로 가져오는 흐름이 있었습니다. 사용자는 A를 채택하면서 가볍게 저장된 이력을 불러와 문서를 편집하는 경험으로 범위를 줄였습니다. HISTORY-01의 제공 범위에서 별도 전후 비교·차이 강조 UI를 제외하고 문서를 직접 수정할 수 있게 합니다.

**사용자 흐름:** 저장된 이력 선택 → 편집 가능한 문서로 열기 → 사용자가 직접 수정 → 기존 UI의 저장·확정 선택 및 검증·반영.

문서를 열기 전에 별도 비교나 부분 가져오기 단계를 필수로 거치지 않습니다. 이력을 열거나 편집하는 것만으로 현재 기획·저장 상태·원본 이력을 자동 변경하지 않으며 실제 저장은 기존 사용자 선택을 따릅니다.

## 3. 기존 합의와의 관계

- D-UF-058의 현재 초안 재저장 흐름은 유지합니다. OPEN-UF-12에 남겨 둔 저장 이력을 다시 여는 범위를 D-UF-092의 문서 불러오기·직접 편집으로 구체화합니다.
- 대화 중 이전 가설을 비교 후보로 남기는 기존 합의는 유지합니다. 이를 과거 저장 기획의 정확한 내용·상태를 모두 다시 열 수 있다는 보장으로 확장하지 않습니다.
- 과거 이력은 편집 가능한 문서로 열고 직접 수정합니다. 별도의 전후 비교·부분 가져오기 단계를 선행 요구하지 않습니다. 실제 반영은 사용자의 선택·UI 최종 반영·기존 서버 검증·저장 보류를 따르고 기존 미저장 편집안 보호 원칙은 유지합니다.
- 과거 안을 현재 진행 대상으로 다시 선택하면 기존 재선택 평가·자료 조회·보류 원칙을 유지합니다. 단순 열람을 그 선택으로 간주하지 않습니다.
- 과거의 사실·기획 가정·현재 사용자 결정을 구분하고 현재 권한·자료 제외 원칙을 유지합니다.
- 어느 시점·범위까지 제공할지의 보존 조건은 C-01·03과 함께 정합니다. 모든 이력의 영구 보존이나 원문 첨부 전체의 복원을 이 질문만으로 보장하지 않습니다. 이력 단위·저장 구조·버전 형식·복구 API는 후속 설계입니다.

## 4. 사용자 기능 검토 기준

합의한 사용자 결과는 본문 AC-220·221에 연결합니다. 다음은 기능 정합성 검토 기준이며 구현 시험 통과 기록이 아닙니다.

1. 원하는 저장 이력을 선택해 편집 가능한 문서로 열고 바로 수정할 수 있는가?
2. 별도 전후 비교·부분 가져오기 단계를 필수로 요구하지 않는가?
3. 열람·편집과 현재 기획에 저장·확정하는 선택을 구분하는가?

기존 부분 가져오기 전제 불일치의 두 보류안·공동 P0·기획 저장 원칙은 유지합니다. 이번 경량화로 그 보류안 중 어느 안도 채택하지 않습니다. HISTORY-01은 저장 이력을 문서로 불러와 편집하는 범위의 합의이며 보존 기간·이력 단위·문서 편집기의 실제 구성은 공동/후속 설계로 연결합니다.
