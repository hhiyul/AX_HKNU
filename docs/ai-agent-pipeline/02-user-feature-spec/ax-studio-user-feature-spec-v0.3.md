# AX Studio 사용자 기능명세 v0.3

작성일: 2026-11-23. **개정: v0.3-R2 / 2026-11-25 / GD-046~070 및 최신 Figma 반영 / 명세 개정 / 신규 실행 인수 NOT_RUN.** 기존 D-MVP-006~011 중 이번 결정이 구체화한 범위는 결정표에서 구분한다. 나머지 작성 기본안을 개별 사용자 확정으로 소급하지 않는다.

이 문서는 문서 작성 중심 MVP의 현재 읽기 시작점이다. [결정·변경 기록](ax-studio-mvp-decisions-v0.3.md)과 [요구사항–인수 추적표](ax-studio-mvp-acceptance-v0.3.md)를 한 세트로 읽는다. 기존 [v0.2](ai-pipeline-user-feature-spec-v0.2.md)의 CK 평가·자유 Chat·추가 기록 등은 이 문서가 바꾼 범위를 제외하고 유지한다. 관찰된 코드가 명세에 우선하지 않는다.

최신 Figma의 확인 위치·확정/설계/제안 구분, 대체 계약, 남은 설계·공동 계약은 [AI Pipeline 개정 계약](../03-module-feature-spec/ai-pipeline-contract-revision-2026-11-25.md)에 연결한다. Figma의 제안 문구를 모두 채택하거나 전체 제품을 첫 출시로 확대하지 않는다. GD-046~070의 결정 원문과 HandOff는 보존한다.

## 1. 목적과 범위

제작 역량은 있지만 문서 작성과 운영 업무를 혼자 감당하는 창작자가 프로젝트의 정보를 활용해 펀딩 상세페이지와 사업계획서를 항목별로 작성하고, 필요한 확인 업무를 등록하며, 다음 방문에 원래 작업을 이어가게 한다.

**대표 완료 흐름:** 프로젝트 선택 → 등록 완료 제품·옵션 확인/선택 → 펀딩 문서 생성 → F06 직접 작성 → 항목 맥락·선택 참고로 실제 AI 도움 → 후보 비교·적용·수정·저장 → 규칙 검사와 항목별 직접 확인 → 문서 완료 요청 → 선택한 할 일의 날짜·내용·목적 확인/등록 → Word/PDF 다운로드 및 홈/달력에서 원래 항목 복귀. 프로젝트 사업계획서에서도 검증한다. 작성 중에는 현재 저장본을 ‘검토 전’으로 다운로드할 수 있고, 할 일 등록 실패는 문서 완료와 별도로 처리한다.

### 2.1 반드시 유지할 경계

1. AI 설명·후보 생성·적용·본문 저장·검토 완료·할 일 완료는 각각 다르다. 말로 한 승인과 실제 저장 결과도 구분한다.
2. AI가 CK·판매가·브랜드·원가·업무를 자동 변경하지 않는다. 가격·날짜·통계·실적·효능·정책을 사실로 만들어 채우지 않는다.
3. 원본 변경은 문서 자동 갱신이 아니다. 문서 편집도 원본 변경이 아니다. 참조 불가와 변경 없음은 다르다.
4. 현재 사용자/프로젝트 권한을 조회와 쓰기에서 확인한다. 로그인 계정 변경, 대상 삭제·보관, 오래된 요청으로 다른 위치를 수정하지 않는다.
5. 읽기·생성·저장 실패와 결과 미확인을 구분한다. 성공을 확인하기 전 완료 표시·중복 저장·자동 재호출을 하지 않는다.
6. 미저장 편집과 기존 후보를 보존하며 사용자가 선택하지 않은 영역을 덮어쓰지 않는다. 입력량 초과는 설명하고 조정을 요청하며 조용히 원문을 잘라 성공으로 표시하지 않는다.
7. 기존 CK 평가의 가설·미정·검증 사실 구분, 중요한 선택에 한정한 질문, 이미 아는 정보 재사용을 유지한다. 문서 작성률은 사업성·제작 가능성·제출 승인 지표가 아니다.

### 2.2 템플릿 문서 항목의 작성·검토 상태

| 상태 | 판정 | 상태를 바꾸지 않는 행동 |
| --- | --- | --- |
| 미작성 | 해당 틀이 요구하는 저장 내용이 비어 있음 | 화면 열기, AI 요청·후보, 임시 작성·임시 저장 |
| 작성 중 | 비어 있지 않은 저장 본문이 있고 현재 저장 내용의 검토가 없음 | 단순 조회·미리보기·업무 완료 |
| 검토 완료 | 비어 있지 않은 현재 저장 본문과 참조 구성을 사용자가 확인 | 출력·조회·할 일 등록/완료 |
| 미저장 변경 있음 | 화면 편집안과 저장 본문/참조가 다름. 위 저장 상태와 함께 별도 표시 | 성공하지 않은 저장을 저장 상태에 합산하지 않음 |
| 임시 저장됨 | 서버가 편집안 보관을 확인. 본문·검토 상태와 별도 | 본문 저장으로 승격하지 않음 |

이 문서의 ‘저장 본문/내용’은 양식이 관리하는 글·구조화된 표/제품 사실·문서 이미지/설명도 포함하는 논리적 내용이다. 이미지 항목을 글자 수만으로 판정하거나 제품 원본 전체를 문서에 복제하라는 뜻이 아니다. 물리 저장 표현·항목별 필수 검증은 D-03/J-04에서 정한다.

저장 본문 또는 연결된 참고 자료의 구성을 실제로 변경해 저장하면 해당 항목의 검토는 해제된다. 필요한 저장 내용을 모두 비우면 미작성이다. 동일 내용 재저장은 불필요하게 검토를 해제하지 않는다. 미저장 변경이 있는 동안에는 과거 저장본의 검토 상태가 현재 편집안까지 확인됐다는 인상을 주지 않는다.

문서가 **현재 사실**로 사용하는 원본 값의 변경이 확인되면 영향받는 항목만 재검토로 돌리고 기존 본문은 보존한다(GD-063). 사용자가 의도한 계획값 또는 기준일을 명시한 과거 값으로 확인한 경우에는 그 원본 변경만으로 재검토하지 않는다(GD-052). 원본 삭제·권한 변경·조회 실패는 확인된 값 변경과 다르다. 원본을 다시 열 수 없다는 이유만으로 기존 완료 상태/당시 검토를 취소하지 않고 확인 불가를 표시한다. 이후 다시 완료할 때는 필요한 근거를 재확인한다(GD-066).

신규 두 양식의 직접 확인 진행도 = 현재 저장본에서 확인한 항목 수 / 8. 모든 항목의 작성·직접 확인과 차단 사항 해소 후 사용자가 문서 완료를 요청한다. 항목 확인 수와 문서 완료 상태를 구분한다. 과거 틀의 분모는 당시 버전을 유지하며 최신 8개 기준으로 소급 변환하지 않는다. 휴지통 문서는 활성 집계에서 제외한다.

### 2.2.1 문서 검토·완료와 비용 근거

- 기본 ‘문서 검토’는 저장된 문서 버전에 대해 필수값·합계 등 정해진 규칙을 검사한다. AI 점검은 사용자가 별도로 명시 요청했을 때만 호출한다. 규칙 결과와 AI 의견은 검사한 버전·실제 처리 상태를 각각 갖는다(GD-069).
- 필수 누락·검증 가능한 불일치·사용자가 확인한 미결 사항 및 직접 확인 미완료는 완료를 막는다. AI의 의심·의견·실패 자체는 완료 차단 근거가 아니다. 오류가 없다는 결과도 사용자 확인을 대신하지 않는다(GD-053).
- 원가의 핵심 여부는 판매가·리워드 구성·제작 규모·진행 여부에 미치는 영향으로 사용자가 확인한다. AI는 이유를 제안할 수 있지만 항목명·단가만으로 분류하거나 차단하지 않는다(GD-062).
- GD-058의 핵심 원가 완료 기준은 현재 견적 또는 실제 비용 기록이다. 실제 받은 견적은 파일 없이 직접 기록해도 근거로 사용할 수 있다. 견적 기록은 권장 사항이며 미기록 자체로 작성·AI 도움·저장·검토 전 다운로드를 막지 않는다(GD-065). 추정·확인·미확인을 구분한다.
- **문서 제품 정책 정합 잔여:** 핵심 원가의 실제 근거 자체가 전혀 없는 경우 GD-058의 최종 완료 제한과 GD-065의 완화 의도를 어떻게 적용할지는 아직 정합 확인이 필요하다. GD-058을 임의 폐기하거나 ‘견적 첨부 필수’로 강화하지 않는다. AI Pipeline은 문서 owner의 근거 상태·차단 사유를 소비하며 이 정책을 모델에게 맡기지 않는다. 해당 문서 완료 사례의 확정만 제한하며 독립된 AI 설계·작성 경로를 막지 않는다.

### 2.3 CK·작업 기록의 상태와 보존

- **CK:** 저장 내용이 없으면 미작성, 있으면 작성됨이다. 미정/가정/최종 판단의 의미는 본문·출처에서 구분하며 작성됨을 사용자 확정이나 사실 검증으로 승격하지 않는다. 조회 실패/권한 없음은 미작성으로 추정하지 않는다. UI·AI 입력·내보내기가 같은 의미를 사용한다. 읽지 못한 값을 빈 내용으로 저장하지 않는다.
- CK 내용 비우기는 대상·영향을 확인한 사용자 저장이다. CK-05 전체 비우기는 해당 가격 본문과 금액을 미정으로 돌리는 영향을 함께 안내하며, 다른 CK·기록·원가 값을 자동 변경하지 않는다. 경제성 화면에서 사용자가 판매가를 선택·적용하는 기존 행동은 별도 유지하며 AI 작성이나 문서 검토가 이를 대신하지 않는다. 같은 가격을 표시하는 화면의 연결·갱신은 G-S에서 이 사용자 의미에 맞게 설계한다.
- **작업 기록:** 기록 없음/미저장 편집/저장됨/실패·미확인을 구분한다. 초안·확정·문서 검토·업무 완료 상태를 추가하지 않는다. 기존 여러 기록을 그대로 보존하며 한 기록의 수정이 다른 기록을 덮어쓰지 않는다. 과거 단일 기록장이 실제 데이터로 존재한다면 임의로 분할하지 않고 하나의 기존 기록으로 보존한다.
- 기존 DRAFT/DECIDED가 들어 있는 외부 자료가 있더라도 표시/이전 과정에서 확정 사실을 새로 만들거나 원문·출처를 버리지 않는다. 그 형식의 신규 가져오기 지원은 P1이며, 실제 현행 서버 데이터를 파괴적으로 변환할 근거로 삼지 않는다.
- 문서 휴지통의 대상은 일반/템플릿 산출물(document)이다. 작업 기록(record)에 같은 휴지통·복구를 새로 추가하는 결정은 아니다. 기존 사용자 직접 수정/삭제 범위는 유지하되 삭제 대상·복구 가능 여부를 분명히 안내한다. 원래 대화는 기록 삭제만으로 삭제하지 않는다.

### 2.4 교차 기능에서의 해석

- 문서에 저장된 참조 구성과 **이번 AI 요청에 사용할 선택 자료**를 구분한다. 연결돼 있다는 이유만으로 외부 원본을 전부 AI에게 보내지 않는다. 요청 전에 기본 맥락과 선택 범위를 보여주며 선택/조회/생성만으로 저장된 참조·본문을 바꾸지 않는다. 현재 사실 원본의 확인된 변경에 따른 재검토는 별도로 적용한다. 채택한 문서 작성 후보의 출처는 편집안과 함께 추적하고 저장 때 해당 본문의 근거로 연결한다. 할 일 등록은 원래 항목/메시지와 업무를 연결하며 문서 본문·참조를 변경하지 않는다.
- 문서의 초안·다듬기와 **그 항목에서 요청하는 할 일 제안** 모두 AX-UF-05의 기본 맥락과 선택 입력 경계를 따른다. 같은 문서의 관련 저장 항목·같은 항목 이력은 기본 맥락이지만 다른 항목 임시 작성·AI 이력이나 전체 Chat·웹 검색을 우회 연결하지 않는다.
- 생성 당시 참고 원문의 별도 영속 사본을 금지하는 것은 원래 저장 자료의 운영 백업을 금지하는 뜻이 아니다. 요청의 참고 원문을 Chat 메시지·실행 로그에 통째로 복제해 그 금지를 우회하지 않는다. 사용자가 직접 작성한 발췌, 원래 대화, 생성 결과, 실제 원본 자료는 서로 구분한다.
- **대상 권한**과 **출처 권한**을 구분한다. 계정/소유 프로젝트/대상 문서에 쓰기 권한이 없으면 적용·저장·업무 등록을 차단한다. 원본 자료에 대한 후속 읽기는 현재 접근 권한을 확인한다. 이미 적법하게 읽은 자료를 실행 중 사용할 수 있는 범위는 기존 GD-015·016을 유지하고, 읽은 시점·현재 비교 불가를 표시하며 새 요청에서 재조회/자동 재사용하지 않는다.
- 같은 프로젝트의 생성 실행 한 개라는 규칙은 Chat·항목 도움·할 일 제안·명시 AI 점검에 공통이다. 기본 규칙 검사는 모델 생성이 아니다. 작업 중 화면을 이동해도 요청 대상은 바뀌지 않는다. 프로젝트가 보관/휴지통 상태이면 새 업무 쓰기는 차단하며, 상태 확인·중지 같은 기존 허용 경로와 구분한다.
- 파일 등록/목록 조회와 원문 읽기는 다르다. 파일명·설명·접근 가능한 등록 기록은 허용 참고 범위에서 사용하되 원문은 사용자가 그 파일을 지정한 뒤 권한과 지원 범위를 확인하여 읽는다(GD-048). TXT/MD는 기존 P5 지원 기준이며 다른 형식·이미지 지원은 실제 파서/Provider 계약과 검증을 거쳐 명시한다. 코드에 분석 경로가 있다는 이유로 전 형식 지원을 약속하지 않는다.

## 3. 두 작성 틀

일반적인 작성 가이드이며 외부 플랫폼·지원기관의 공식 제출 양식이 아니다. 최신 Figma DOC-06·10·11·22의 항목 이름·순서로 신규 틀을 정합한다. 항목은 순서와 무관하게 작성할 수 있고 작성·확인 의무는 완료 조건에 사용하며 이동·저장을 막지 않는다. 이전 틀의 같은 항목 번호를 새 의미로 덮어쓰지 않으며 실제 틀 버전/이전 방식은 설계에서 확정한다.

## 4. 기능별 사용자 계약

각 기능은 [기존 작성 템플릿](user-feature-spec-template.md)의 목적·배경·시나리오·입력·출력·예외·논리 데이터·상태 전이를 포함한다. AX-UF/AX-RQ는 이번 서비스 범위의 새 식별자이며 기존 UF-AI·D-UF·AC 번호를 재사용하지 않는다. 인수 시나리오는 별도 추적표에 있다.

### AX-UF-01 프로젝트 진입과 홈 범위

1. **목적:** 사용자가 자신에게 속한 프로젝트를 찾고 이어갈 작업의 범위를 이해한다.
2. **배경:** HTML 홈·선택 브랜드 구조와 D-MVP-006. 브랜드가 문서 작성의 필수 선행 단계가 되지 않게 한다.
3. **시나리오:** 로그인 → 브랜드 없이 프로젝트 생성/선택 → 홈에서 계정 전체와 브랜드 필터 전환 → 프로젝트 이름이 붙은 문서/업무로 이동.
4. **입력:** 현재 계정(필수), 프로젝트(작업 시 필수), 이름(새 프로젝트 시 필수), 브랜드(선택). 소속이 없거나 권한 없는 대상은 진입 불가.
5. **출력·요구:** **AX-RQ-001** 홈은 접근 가능한 활성 프로젝트만 집계하고 계정/브랜드 범위를 표시한다. **AX-RQ-002** 브랜드·CK 완성 없이 프로젝트와 문서를 시작한다. **AX-RQ-003** 문서 검토·업무 완료·추천·미저장 여부를 다른 정보로 표시한다.
6. **예외:** 빈 목록은 생성 진입, 일부 조회 실패는 해당 부분의 조회 실패로 표시한다. 실패를 0개/완료로 바꾸지 않는다.
7. **논리 데이터:** 계정·브랜드·프로젝트 식별, 활성/보관/휴지통, 대상별 표시 이름과 조회 범위. 물리 테이블은 설계 후속.
8. **상태:** 범위 선택은 조회 범위만 바꾼다. 홈 진입으로 생성·검토·업무 상태를 변경하지 않는다.

### AX-UF-02 문서 생성과 작성 틀 선택

1. **목적:** 프로젝트에 독립 문서를 만들고 올바른 편집기로 진입한다.
2. **배경:** 기존 동일 유형 다중 문서 유지, HTML 두 틀과 D-MVP-006·007.
3. **시나리오:** 문서 작성 → 이름·펀딩/프로젝트 사업계획 선택 → 등록 완료 제품·옵션 선택/확인 → 생성 → 가져온 제품 사실과 작성할 설명을 구분한 편집기. 기존 자유형 문서는 기존 편집기로 연다. 채팅 답변에서 시작하면 GD-068의 첫 참고와 원 대화 연결을 함께 전달한다.
4. **입력:** 소유 프로젝트, 공백이 아닌 이름, 지원 유형, 사용자가 확인한 제품·옵션과 원본 기준. 생성된 문서의 틀 버전은 시스템이 고정한다. 작성 중 제품은 문서 선택에 사용하지 않으며 예상 가격은 예상값 표시가 있어야 한다. 최소 선택 개수·필수 제품 필드의 정확 규칙은 제품 owner와 확정한다.
5. **출력·요구:** **AX-RQ-004** 한 생성 요청의 연속 클릭·재확인으로 문서가 중복 생성되지 않는다. **AX-RQ-005** F01~F08/B01~B08과 필수 기준을 생성 시 고정하며 틀 개정이 과거 문서를 몰래 바꾸지 않는다. **AX-RQ-006** 동일 유형 여러 문서와 기존 자유형 문서를 구분하고 강제 변환·자동 사본 생성을 하지 않는다.
6. **예외:** 결과 미확인은 같은 생성의 결과를 먼저 조회한다. 프로젝트가 없거나 보관/휴지통이면 생성하지 않는다. 미지원 틀은 편집/진행도 계산 불가를 설명하고 데이터를 보존한다.
7. **논리 데이터:** 문서 식별·제목·유형·틀 식별/버전·소유 프로젝트·항목 목록. 아직 없는 API를 확정하지 않는다.
8. **상태:** 유형/제품 선택 → 생성 중 → 서버 확인된 문서 또는 실패/미확인. 가져온 사실이 있어도 설명 글 작성·사용자 검토가 자동 완료되지 않는다. 메뉴를 열거나 닫는 것만으로 문서를 만들지 않는다.

### AX-UF-03 항목 편집·임시 저장·본문 저장

1. **목적:** 순서와 무관하게 내용을 작성하고 저장 위치를 이해하며 작업을 이어간다.
2. **배경:** 비선형 작성 유지, 서버 임시 저장의 복귀 범위를 구체화(D-MVP-010).

4. **입력:** 문서·항목, 현재 본문/참조, 편집안, 편집 기준 버전. 빈 본문도 저장 가능하며 비우기의 영향을 표시한다.
5. **출력·요구:** **AX-RQ-007** 필수·선행 항목 미작성으로 이동·작성·저장을 막지 않는다. **AX-RQ-008** 임시 저장 성공분과 마지막 문서/항목은 재방문에 복원하고 실패·미저장 입력은 구분한다. **AX-RQ-009** 항목 저장은 같은 문서의 선택한 항목만 갱신하며 충돌 시 현재 편집안을 보존하고 자동 덮어쓰기/병합하지 않는다.
6. **예외:** 임시/본문 저장 실패는 성공 이동·완료 표시를 하지 않고 입력을 유지한다. 다른 탭이 변경했다면 최신본 확인·편집 유지·명시 재시도 선택을 제공한다. 재접속·새로고침은 서버 보관 성공분만 복원한다.

### AX-UF-04 사용자 검토와 문서 진행도

1. **목적:** 사용자가 확인한 현재 내용을 정확히 표시한다.
2. **배경:** 내부 기획 평가·사용자 확인·사업 성과를 분리한 기존 원칙 및 HTML 진행 기준.
3. **시나리오:** 항목 작성 → 검토 완료 선택 → 현재 변경 저장 성공 → 그 저장 내용의 확인 기록 → 수정·저장 → 재확인.
4. **입력:** 비어 있지 않은 현재 내용, 참조 구성, 사용자의 검토 행동. 빈 항목은 검토 완료할 수 없다.
5. **출력·요구:** **AX-RQ-010** 2.2절 상태와 생성 시 틀의 직접 확인 분모를 표시한다. 신규 두 틀은 각각 8개이며 문서 완료에는 모든 항목의 작성·직접 확인과 차단 사항 해소 및 사용자 완료 요청이 필요하다. **AX-RQ-011** 검토 완료는 현재 변경 저장이 확인되고 같은 내용임이 확인된 경우에만 기록한다. **AX-RQ-012** 저장 본문/참조 구성 변경 또는 현재 사실로 사용한 원본 값의 확인된 변경은 영향받는 항목만 재검토로 돌린다. 계획값·기준일 있는 과거 값과 원본 접근 불가는 2.2절에 따라 구분한다. **AX-RQ-046** 기본 규칙 검사는 모델 호출 없이 저장 버전을 검사하며, 명시 요청한 AI 점검은 별도 버전·처리 상태의 참고 의견으로 제공한다. AI 의견/실패만으로 완료를 막거나 승인하지 않는다. **AX-RQ-047** 가격의 의미·핵심 원가 영향·실제/예상/미확인 근거를 구분해 문서 owner의 완료 규칙을 적용한다. 견적 미기록 자체는 작성·AI·저장·검토 전 출력을 막지 않으며 2.2.1절의 완료 정책 정합 잔여를 보존한다.
6. **예외:** 저장·검토 사이 충돌/실패에는 검토 완료를 표시하지 않는다. 기존 확인 상태와 새 미저장 변경을 함께 보여 혼동을 막는다.
7. **논리 데이터:** 현재 저장 내용의 식별, 사용자가 확인한 내용의 식별, 필수 여부. 검토 이력의 상세 UI·보존 기간은 후속 설계다.
8. **상태:** 미작성 → 작성 중 → 검토 완료 → 내용/참조 변경 저장 또는 현재 사실의 확인된 원본 변경 시 재검토. 문서 완료는 별도 사용자 요청이다. 할 일 등록/완료·AI 평가가 확인 상태를 대신하지 않는다.

### AX-UF-05 참고 정보 선택과 출처 확인

1. **목적:** 사용자가 AI가 읽을 범위와 문서의 근거를 이해한다.
2. **배경:** D-MVP-007·008, GD-039, 선택 입력과 원본 독립성.
3. **시나리오:** 현재 항목·같은 문서의 관련 저장 항목·같은 항목의 이용 가능한 AI 이력을 기본으로 확인 → 추가 조회할 제품 원본·CK·브랜드·다른 문서/기록/대화/파일 선택 → 요청 → 실제 사용 출처 확인.
4. **입력:** 현재 항목의 편집안과 요청, 같은 문서의 관련 저장 항목, 같은 항목의 이전 요청과 후속 수정 대상 답변, 명시 선택한 문서 밖 자료, 현재 접근·버전·제외 범위. 다른 항목의 임시 입력·AI 이력은 자동 포함하지 않는다.
5. **출력·요구:** **AX-RQ-013** 항목 AI와 그 항목의 할 일 제안은 위 기본 맥락을 사용하고, 문서 밖 원본의 추가 조회는 명시 선택 범위로 제한한다. 참고 선택은 같은 항목에서 유지하고 다른 항목에서는 새로 선택한다. 채팅에서 이어진 작업에는 원 대화의 제외를 이어받는다. **AX-RQ-014** 실제 사용 출처·버전·확인 범위·원문/메시지 연결과 파생 의존성을 추적하되 별도 영속 원문 사본은 만들지 않는다. 제외 자료에서만 유래한 정보는 이전 요청/답변·요약을 통한 우회 사용도 금지하며 분리/검증 불가인 부분은 입력에서 제외한다. **AX-RQ-015** 관련 원본의 변경·삭제·권한 상실·비교 불가를 구분하고 GD-063·066에 맞춰 검토 상태를 처리한다. 본문 자동 수정·없는 원문 복원은 금지한다. **AX-RQ-048** 등록 파일의 원문은 사용자가 해당 파일을 지정한 뒤 접근 권한·지원 형식·읽기 범위를 확인해 읽는다. 목록 메타데이터·읽은 원문·부분 누락·실패를 구분하며 지정되지 않은 파일을 자동 분석하지 않는다.
6. **예외:** 선택 자료를 읽지 못하면 누락 범위를 알리고 가능한 결과에 한계를 표시한다. 필수 입력이 없으면 보완 요청/중단한다. 이력 열람 권한을 현재 AI 입력 동의로 간주하지 않는다. 같은 브랜드 소개용 라인업의 명시 선택을 다른 프로젝트 전체 자료 조회로 확대하지 않는다. 일반적인 교차 프로젝트 신규 탐색은 P1이다.
7. **논리 데이터:** 자료 식별·유형·상태·버전·소유·실제 사용 여부·출처 메시지. 생성 중 일관된 입력 고정은 필요하나 영속 원문 복제와 다르다.
8. **상태:** 참고 후보 → 사용자 선택 → 실제 사용/누락 확인. 선택만으로 읽기 성공·본문 반영·원본 수정이 되지 않는다.

### AX-UF-06 항목별 AI 초안·다듬기

1. **목적:** 작성 위치에서 필요한 문구 후보를 얻고 사용자가 채택한다.
2. **배경:** D-MVP-001의 명시 A. 새 템플릿 항목에 한정해 기존 P5 제외 범위를 확장한다.
3. **시나리오:** 초안 만들기 또는 현재 글 다듬기 → 참고 확인 → 요청 → 별도 후보 확인 → 적용/닫기 → 직접 수정 → AX-UF-03 저장.

5. **출력·요구:** **AX-RQ-016** 후보 1개를 현재 본문과 분리해 표시하고 사실·추정·미정을 구분한다. **AX-RQ-017** 적용은 해당 항목 편집안만 바꾸고 저장·검토·CK·업무를 자동 변경하지 않는다. 닫기는 기존 본문/편집안을 유지한다. **AX-RQ-018** 요청 대상과 저장/편집 기준을 고정하여 연속 클릭·늦은 응답·이동·동시 편집으로 잘못된 위치나 최신 편집안을 덮어쓰지 않는다.
6. **예외:** 실행 중 편집되면 오래된 후보임을 안내하고 현재 글과 함께 확인한 후 사용자가 명시적으로 가져오게 한다. 오류·빈 응답은 기존 후보·입력을 유지한다. 새 유효 후보가 도착하기 전 이전 후보를 지우지 않는다.
7. **논리 데이터:** 요청 식별, 소유/대상, 작업 종류, 기준 내용 식별, 후보 본문·출처·메시지 연결·실제 상태. 원문 snapshot을 영속 저장할 권한으로 확대하지 않는다.
8. **상태:** 요청 전 → 생성 중 → 후보 있음/실패/중단/미확인 → 편집안 적용 또는 닫기. 복구된 삭제 문서에 삭제 전 후보를 자동 적용하지 않는다.

### AX-UF-07 자유 대화 탐색과 문서·항목 도움 기록

1. **목적:** 한 프로젝트의 자유 대화와 문서 작업을 잃지 않고 찾아간다.
2. **배경:** GD-046~050·068이 D-MVP-003/GD-041의 단일 대화·같은 타임라인 규칙을 대체한다. GD-043~045의 사용량·진행·미확인은 유지한다.
3. **시나리오:** 새 자유 대화 → 현재 프로젝트의 전체 대화 목록에서 제목/내용 검색 → 선택한 같은 대화 재개. 특정 답변에서 문서 작성 → 제품 선택 → 첫 AI 참고 확인 → 항목 도움 → 해당 문서·항목에서 기록 재열람, 필요하면 연결된 원 대화로 이동.
4. **입력:** 프로젝트·선택 대화·대상 문서/항목·원 대화/메시지 연결·요청 참고 범위. 목록 열람/검색과 AI에게 참고로 지정하는 행위를 구분한다.
5. **출력·요구:** **AX-RQ-019** 프로젝트의 복수 대화 생성·목록·검색·같은 ID 재개를 제공한다. 다른 대화 내용은 사용자가 직접 선택한 접근 가능한 대화만 참고하며 자연어 요청만으로 AI가 다른 대화를 검색하거나 공유 기억을 만들지 않는다. 최근 목록은 최대 5개, 전체 목록은 오른쪽 본문이며 AI-25는 보조 전체 열람이다. 개별 대화 삭제·초기화는 이번에 추가하지 않는다. **AX-RQ-020** 문서 도움 요청·응답은 대상 문서·항목에서 다시 열고, 채팅에서 시작한 작업은 원 대화 연결을 남긴다. 일반 채팅에 도움 기록을 중복 적재하거나 다른 항목의 AI 이력을 자동 승계하지 않는다. **AX-RQ-021** 같은 프로젝트의 자유 대화·항목 도움·할 일 제안·AI 점검 생성은 동시에 하나의 활성 실행만 허용하며 실제 진행·중단·사용량을 구분한다. **AX-RQ-049** 자유 대화의 참고 범위가 0개여도 현재 요청과 이용 가능한 현재 대화 이력으로 계속한다. 제외 출처의 정보 또는 출처 분리/검증 불가 이력·요약은 입력에서 제외하고 조회 불가 사실을 꾸며 채우지 않는다. **AX-RQ-050** ‘이 답변으로 문서 작성’에서 선택한 답변 한 건을 첫 문서 AI 요청의 제거/교체 가능한 참고로 표시한다. 원 대화의 제외를 적용하며 대화 전체 열람이나 본문 자동 반영을 허용하지 않는다.
6. **예외:** 생성 중 다음 질문 작성은 가능하나 자동 큐잉·자동 전송하지 않는다. 사용자 중단 뒤 실제 종료를 확인하고 다음 요청을 보낸다. 다른 프로젝트는 별도 실행 가능. 끊긴 실행은 미확인과 전달된 부분 결과를 구분한다.
7. **논리 데이터:** 프로젝트·자유 대화/문서 항목 도움의 소유 단위, 메시지 순서·역할·요청·대상·원 대화 연결·실행·사용량. 실제 저장 테이블·도움 기록 표현은 설계 사항이며 논리적 분리를 별도 서비스/전역 기억 생성 요구로 해석하지 않는다.
8. **상태:** 목록 검색·열람·재개는 다른 대화의 AI 참고 허용과 별개다. 자유 대화는 브랜드 공통+현재 프로젝트를 기본 참고하되 사용자 제외를 적용하고, 다른 프로젝트·다른 대화·파일 원문을 자동 확대하지 않는다. 항목 도움에는 AX-UF-05를 적용한다.

### AX-UF-08 할 일 후보 검토·등록·수정·완료

1. **목적:** 문서에서 발견한 확인 업무를 사용자 의도로 실행 목록에 남긴다.
2. **배경:** HTML 할 일 연결, D-MVP-006·009. 기존 추가 기록과 다른 자원이다.
3. **시나리오:** F06에서 할 일 제안 받기 → 일부 후보 선택 → 제목·날짜·메모 수정 → 등록 → 등록된 업무 확인 → 직접 수정/완료. AI 없이 수동 등록도 가능하다.
4. **입력:** 프로젝트, 공백 아닌 제목과 사용자가 확인한 유효한 달력 날짜는 등록 필수, 메모·목적은 선택. 문서 목적을 선택 후보로 보여주되 일괄 선택하지 않는다. 목적 없이도 등록할 수 있고 목적별 집계에서는 제외한다. 문서에서 제안된 후보는 원래 문서·항목·메시지와 연결한다. 미정 날짜를 임의로 채우지 않는다.
5. **출력·요구:** **AX-RQ-022** AI 후보와 실제 할 일을 구분하고 날짜·내용을 확인한 후보만 등록한다. **AX-RQ-023** 같은 제안의 반복 등록·응답 유실·재방문은 같은 할 일 결과를 확인하며 중복 생성하지 않는다. **AX-RQ-024** 사용자가 제목·날짜·메모와 완료를 직접 변경하며 문서 검토/외부 수행 성공을 자동 추정하지 않는다.
6. **예외:** 저장 실패는 등록되지 않음, 결과 미확인은 결과 조회 후 재시도. 문서가 휴지통으로 이동하면 그 문서의 미등록 후보 등록은 보류하고 복원 경로를 안내한다. 이미 등록된 업무는 유지한다. 생성 때의 항목 내용/참조와 현재 값이 다르면 그 차이를 알리고 현재 제목·날짜·메모와 원래 대상을 사용자가 다시 확인한 뒤 등록한다. 상위 프로젝트 접근 불가·보관·휴지통이면 등록하지 않는다.
7. **논리 데이터:** 제안 식별·원래 메시지/항목, 선택 여부, 업무 식별·제목·날짜·메모·완료, 등록 결과 연결. 후보에 업무 완료 상태를 따로 중복 저장하지 않는다.
8. **상태:** 후보 → 확인/수정 → 건별 등록 확인 또는 실패/미확인. 성공한 건은 유지하고 확인된 실패 건만 재시도한다. 미확인은 원 등록 결과부터 확인한다. 문서가 완료 조건을 충족하고 사용자가 완료를 요청했다면 일부 할 일 등록 실패와 무관하게 문서를 완료할 수 있다. 작성 중 등록은 문서를 완료시키지 않는다. 업무는 미완료↔완료를 사용자 행동으로 전환한다.

**AX-RQ-051** 날짜 확인·선택 목적·원래 제안 연결과 건별 등록 결과를 보존한다. 여러 목적에서 같은 할 일 ID를 참조하고 목적 미선택은 등록 장애가 아니다. 문서 완료와 일부 등록 실패·업무 실행 상태를 각각 표시한다(GD-055·060·064·067).

### AX-UF-09 캘린더·최근 작업·원래 항목 복귀

1. **목적:** 오늘 할 일과 멈춘 작업을 찾아 원래 작성 맥락으로 돌아간다.
2. **배경:** 계정 홈·프로젝트 일정·전체 일정의 연결과 규칙 기반 추천.
3. **시나리오:** 프로젝트 달력/전체 일정/홈에서 업무 선택 → 프로젝트·문서·항목 확인 → 해당 항목 열기 → 수정·저장 → 업무 직접 완료.
4. **입력:** 계정/브랜드/프로젝트 범위, 날짜, 업무·최근 작업의 대상 식별. 날짜는 시간 없는 달력 날짜로 취급하며 오늘 판정의 기준 시간대를 화면에 알린다. 초기 검토안은 Asia/Seoul, 상세 지역화는 후속이다.
5. **출력·요구:** **AX-RQ-025** 날짜·범위에 맞는 등록 업무만 오늘/예정/기한 지남으로 보여주고 완료 여부를 구분한다. **AX-RQ-026** 업무와 최근 작업은 원래 프로젝트·문서·항목으로 정확히 복귀한다. **AX-RQ-027** 미작성 필수 항목·최근 중단·기한 지남에 근거한 추천을 업무와 구분하고 홈 진입만으로 AI 호출·업무 등록을 하지 않는다.
6. **예외:** 문서 휴지통은 복원 경로, 원본 부재는 찾을 수 없음, 권한 상실은 접근 불가를 표시한다. 이름이 비슷한 다른 항목으로 대신 연결하지 않는다.
7. **논리 데이터:** 업무의 원래 대상, 마지막 접근 위치, 표시 범위, 기준 날짜, 추천 이유. 추천은 업무의 별도 사본이 아니다.
8. **상태:** 조회/복귀는 업무 완료나 문서 검토를 바꾸지 않는다. 삭제 문서는 활성 최근/진행 집계에서 제외하되 업무 연결은 유지한다.

**AX-RQ-052** 각 목적에 연결된 문서 작성 완료와 할 일 실행 완료를 따로 집계한다. 연결 할 일이 0개면 ‘연결된 할 일 없음’이며 ‘준비 전체 완료’로 판정하지 않는다. 복수 목적은 같은 문서/할 일의 상태를 읽으며 서비스 차원의 목적별 필수 조건을 새로 만들지 않는다(GD-056).

### AX-UF-10 문서 휴지통과 복구

1. **목적:** 문서를 잘못 지워도 기존 작업 연결을 보존하며 되돌린다.
2. **배경:** D-MVP-004로 GD-038 대체. 기존 일반 문서와 새 템플릿 문서 모두 적용한다.
3. **시나리오:** 문서와 영향을 확인 → 휴지통 이동 → 관련 할 일은 남아 삭제 문서 표시 → 휴지통에서 복구 → 같은 문서·항목과 업무 연결 확인.
4. **입력:** 소유 문서, 현재 기준 버전, 사용자의 삭제/복구 선택. 상위 프로젝트 접근·활성 여부를 확인한다.
5. **출력·요구:** **AX-RQ-028** 문서 삭제는 복구 가능한 휴지통 이동이며 활성 목록·진행도·AI 참고에서 제외한다. **AX-RQ-029** 복구는 같은 문서/항목 식별·본문·서버 저장된 임시 작성·검토 근거·메시지/업무 연결을 보존하고 새 사본을 만들지 않는다. **AX-RQ-030** 관련 할 일·대화·원본 자료는 연쇄 삭제하지 않으며 접근 불가인 프로젝트를 문서 복구로 부활시키지 않는다.
6. **예외:** 삭제/복구 실패·미확인은 성공으로 표시하지 않는다. 삭제 중 도착한 AI 결과는 적용하지 않는다. 삭제 전 후보는 복구 후에도 자동으로 유효해지지 않는다. 복구 때 출처 이용 상태를 현재 기준으로 다시 구분한다.
7. **논리 데이터:** 문서의 활성/휴지통 상태, 동일성, 삭제 전 저장 상태, 상위 프로젝트 수명. 물리 삭제·보관 기간·정리 정책은 후속 계약이며 무기한 보관을 약속하지 않는다.
8. **상태:** 활성↔휴지통은 사용자 명시 동작과 서버 성공으로만 전환한다. P0 문서 UI에는 영구 삭제/휴지통 비우기를 새로 추가하지 않는다. 프로젝트 전체 삭제의 기존 경계와 구분한다.

### AX-UF-11 미리보기·복사·파일 출력

1. **목적:** 사용자가 저장한 문서를 외부에서 활용할 수 있는 텍스트/파일로 얻는다.
2. **배경:** Q19·GD-036·037 유지, 항목형 문서의 저장 본문 단일 원본 원칙.
3. **시나리오:** 항목형 전체 미리보기/복사/출력 선택 → 문서 안의 미저장/임시 작성 변경 항목을 모두 확인 → 저장 후 진행 또는 취소 → 같은 저장 기준의 항목들을 순서대로 합성 → 결과 확인. 기존 자유형은 저장본 출력 및 미저장 내용 포함 시 먼저 저장 안내라는 기존 계약을 유지한다.
4. **입력:** 접근 가능한 활성 문서의 현재 저장본, 선택 출력 형식. 항목형은 틀의 제목·순서와 각 저장 본문을 사용한다. 비어 있는 항목에는 내용을 만들어 넣지 않는다.
5. **출력·요구:** **AX-RQ-031** 합성 전체 본문은 별도 편집 원본·새 문서가 아니며 AI 재작성 없이 현재의 일관된 저장본으로 출력한다. 작성 중/재검토 중에는 ‘검토 전’으로 식별한다. 직전 완료본을 따로 고르는 기능은 포함하지 않는다. **AX-RQ-032** 항목형 문서의 현재 화면뿐 아니라 다른 항목의 미저장/임시 작성 변경도 알리고 저장 또는 취소를 선택하게 한다. 확인한 저장이 모두 성공하기 전 출력하지 않으며 실패 시 입력과 이미 성공한 저장을 보존하고 전체 출력은 보류한다. **AX-RQ-033** 신규 양식의 Word/PDF는 같은 저장 버전의 제목·항목 순서·표·등록 이미지·페이지 구분을 보존한다. 기존 자유형 04의 TXT/MD/DOCX/PDF 및 03 CK·전체 작업 기록 MD/TXT는 유지한다. 목록 페이지 크기나 AI 자동 참고 개수 제한으로 저장 기록을 출력에서 누락하지 않는다.
6. **예외:** 읽기·변환·전달 실패를 성공 파일로 표시하지 않는다. 한글·목록 등 변환 충실도는 형식별 검증한다. 필수 자료 조회 실패 시 기존 기획 원본 출력은 전체 보류한다. 이미지 레이아웃·플랫폼 게시 기능으로 안내하지 않는다.
7. **논리 데이터:** 문서/항목의 저장본 식별, 틀 순서, 출력 형식·결과. 출력으로 원본·검토 상태·문서 수를 바꾸지 않는다.
8. **상태:** 출력 요청 → 필요 시 저장 확인 → 생성/전달 성공 또는 실패. 검토 완료하지 않은 저장본도 출력할 수 있으며 성공이 제출 승인을 뜻하지 않는다.

### AX-UF-12 실패·미확인·접근 변경 후 계속하기

1. **목적:** 끊김·충돌·권한 변경에서도 무엇이 반영됐는지 알고 안전하게 이어간다.
2. **배경:** 기존 실패/미확인 구분, GD-045, HTML 경합 시나리오.
3. **시나리오:** 저장/등록 응답 유실 → 결과 확인 → 이미 반영됐으면 결과만 표시 → 미반영 종료가 확인됐을 때 사용자 재시도. 생성 중 새로고침은 확인 가능한 실행 상태를 다시 조회한다.
4. **입력:** 원래 요청·대상, 현재 계정/접근, 확인 가능한 서버 상태, 유지한 편집안.
5. **출력·요구:** **AX-RQ-034** 실패·중단·미확인을 구분하고 미확인 쓰기를 자동 재전송하지 않는다. **AX-RQ-035** 새로고침 뒤 저장 성공한 입력/초안과 확인 가능한 기록만 복원하며 유령 생성 중·자동 재호출을 만들지 않는다. **AX-RQ-036** 계정 전환·대상 삭제/복구·권한 상실·버전 충돌이 있는 늦은 응답은 잘못된 계정/문서에 적용되지 않는다. 비밀키는 사용자 브라우저·출력에 노출하지 않는다.
6. **예외:** 상태 조회도 불가하면 미확인을 유지하고 다음 행동을 안내한다. 원격 생성 결과 미확인과 로컬 실행 종료를 구분하며 안전하게 종료한 뒤 새 요청을 허용하되 원래 결과 복구를 보장하지 않는다.
7. **논리 데이터:** 요청 식별·대상·실제 반영 결과·실행/전달 상태·접근과 수명 변화. 반복 요청·다중 탭·다중 서버의 구체 보장은 설계/시험에서 확인한다.
8. **상태:** 진행 → 확인된 성공/실패/중단/미확인. 미확인을 0·실패·성공으로 임의 전환하지 않으며 계정 전환 뒤 이전 계정 편집안을 새 계정에 노출하지 않는다.

**AX-RQ-053** 사용자가 ‘이어서 생성’을 선택하면 원래 질문과 중단된 부분 답변의 이용 가능한 내용을 입력으로 삼아 남은 내용만 새 실행으로 생성한다. 원 부분 답변·중단 기록과 원 요청 연결을 보존한다. 현재 접근·참고·출처 제외를 다시 적용하며 기존 실행 종료와 늦은 출력 차단이 확인된 뒤 접수한다. 원격 결과 미확인을 자동 재시도로 바꾸지 않는다(GD-024·045·070).

### AX-UF-13 기존 기획·일반 문서·추가 기록·Chat 보존

1. **목적:** 새 MVP를 도입해도 이미 작성한 기획과 기록을 잃거나 다른 의미로 바꾸지 않는다.
2. **배경:** D-MVP-007·011·012·013, GD-042, 기존 UF-AI-01~16과 자유형 04 계약. CK 확정 단계와 프로젝트 기록장 하나는 이번 명시 결정으로 대체한다.
3. **시나리오:** 기존 CK를 직접 저장/비우기 → AI·출력에서 같은 상태 확인. 작업 기록 목록에서 개별 기록을 열거나 직접 작성/AI 검토안으로 새 기록 저장 → 기존 기록 명시 수정 → 전체 기록 내보내기. 일반 문서·첨부·Chat도 기존 내용·연결을 유지하며 새 문서에 선택 참고한다.
4. **입력:** 소유 프로젝트·기존 데이터·접근 권한·사용자 저장 의도·편집 기준. 새 작업 기록은 공백 아닌 제목·본문이 필요하며 원래 대화/메시지는 있을 때 연결한다. 원문 그대로 저장 요청은 의미를 바꾸지 않는다. 내용의 사실·가설·미정과 단순 저장 여부를 구분한다.
5. **출력·요구:** **AX-RQ-037** CK는 직접 편집만 허용하고 새 문서 AI/저장/복구가 CK·판매가·원가를 자동 변경하지 않는다. **AX-RQ-038** 기존 자유형 문서·작업 기록의 본문과 연결을 보존하고 새 템플릿/할 일로 강제 변환하지 않는다. **AX-RQ-039** 자유 Chat의 CK 판단 기준·검색 허용/제외·출처·진행·토큰 표시와 지원 첨부의 사용자 계약을 유지하며 항목 AI의 선택 입력 규칙을 별도로 적용한다. **AX-RQ-043** CK는 미작성/작성됨 두 상태만 제공하고 별도 초안/확정 없이 저장·조회·AI·내보내기의 의미를 일치시킨다. **AX-RQ-044** 여러 독립 작업 기록을 목록·제목·수정 시각·원래 대화 연결로 찾고 개별 저장/편집한다. 같은 저장 요청/원래 답변의 반복 저장은 기존 연결 기록을 확인하며 다른 기록이나 사용자의 후속 편집을 조용히 덮어쓰지 않는다.
6. **예외:** 기록 저장 실패/미확인은 완료로 표시하지 않고 결과를 먼저 확인한다. 이미 저장한 AI 답변은 기존 연결 기록으로 안내하며, 수정하려면 대상·변경 내용·기준을 명시적으로 확인한다. 기록이 그 뒤 편집됐다면 기존 편집안을 보존하고 충돌/비교를 거쳐 사용자 선택을 받는다. 태그·폴더·초안/확정·검토 완료는 추가하지 않는다.
7. **논리 데이터:** 기존 소유·본문·저장 상태·버전·출처·유형·연결. 작업 기록마다 독립 식별·제목·본문·수정 기준을 갖는다. 현재 코드의 200개·5,000자·AI 최근 20개는 구현 관찰이며 제품의 확정 한도는 G-S에서 정한다.
8. **상태:** CK는 명시 저장 성공 시 작성됨, 내용 비우기 성공 시 미작성이다. 조회/AI 응답/문서 저장으로 CK 상태가 변하지 않는다. 작업 기록은 단일 저장 승인으로 반영하고 완료/확정 단계는 없다. 일반 문서 직접 편집은 같은 문서, 전체 AI 재생성의 저장은 새 독립 문서라는 기존 경로를 유지한다.

**AX-RQ-054** CK-05/경제성의 가격은 프로젝트 기획 가격이다. 제품·옵션의 현재 판매가, 문서 리워드 가격, 거래 당시 실제 금액을 각 owner·기준일·실제/예상 의미와 함께 구분한다. 기획 가격을 제품 등록에 가져오려면 사용자가 확인한다. 문서 값으로 제품 가격·판매 기록·재고를 자동 변경하지 않는다(GD-051).

**AX-RQ-055** 첫 출시는 제품 등록 완료→옵션/가격/초기 수량 확인→제품 선택→펀딩·프로젝트 사업계획 작성/검토/Word·PDF→연결 할 일까지 검증한다. 브랜드 전체 사업계획서·SNS 전용 글·판매/재고/정산 운영 흐름은 후속이며 이미 있는 데이터·기능은 파괴하지 않는다(GD-057·061).

## 7. 워터폴/V 진행 경계

이번 산출물은 사용자 요구와 인수 기준을 연결하는 단계다. 다음 시스템/모듈 설계에서 실제 API·DB·동시성·한도·접근·마이그레이션과 검증을 대응시킨다. G-U~G-A의 종료 조건과 요구별 검증은 [인수 추적표](ax-studio-mvp-acceptance-v0.3.md)를 따른다.

OPEN-MVP-01~03은 D-MVP-012~014로 종결된 이력을 유지한다. v0.3-R2는 GD-046~070을 반영한 현재 설계 입력이다. [11월 23일 정합 점검](ax-studio-mvp-consistency-review-2026-11-23.md)은 당시 기록으로 보존하고, 현재의 대체 관계·Figma 근거·남은 계약은 [AI Pipeline 개정 계약](../03-module-feature-spec/ai-pipeline-contract-revision-2026-11-25.md)을 따른다. 추가 AI 기둥 제품 결정은 없지만 2.2.1절의 문서 완료 정책 정합과 구체 설계·공동 제공 계약은 완료로 표시하지 않는다. 구현·인수 통과나 모든 작성 기본안의 별도 사용자 승인을 주장하지 않는다. 애플리케이션 코드·데이터·HandOff는 이번 개정 범위가 아니다.
