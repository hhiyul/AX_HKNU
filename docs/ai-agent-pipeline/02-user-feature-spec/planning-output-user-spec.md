# 04 기획 산출물 사용자 기능명세

기준: 2026-11-12 사용자 채택 Q1~Q20. [03 사용자 기능 정본](ai-pipeline-user-feature-spec-v0.2.md) · [결정 추적](../03-module-feature-spec/grill-feature-decisions.md#2026-11-12-q1q20-결정-추적) · [04 모듈 계약](../03-module-feature-spec/planning-output-module-spec.md). 이 문서는 04 사용자 기능 정본이며 구현·실서비스 검증을 뜻하지 않습니다. Q 식별자는 기존 GD 및 기존 문서의 Q와 별개입니다.

## 1. 목적과 자원

사용자는 프로젝트와 기획 내용을 토대로 사업계획서·상품기획서·상세페이지 등의 글을 생성하고 검토·편집·저장·내보냅니다. 02 직접 편집과 03의 Field별 승인으로 갱신하는 CK-01~06은 동일한 02 정본입니다. 04 문서는 별도 결과물이며 프로젝트 아래 같은 종류를 포함해 여러 개를 둘 수 있습니다(Q11). 03의 프로젝트당 하나인 UF-AI-16 추가 기록은 별개입니다. Document 본문은 자유형 문자열 중심이며, 제목·문서 식별·편집 revision과 입력 출처·기준 revision·상태·결손은 논리적으로 분리해 보존합니다(Q2·Q9·Q12). 물리 형식은 미정입니다.

## 2. 생성과 검토

**입력:** 04 직접 요청 또는 03 Chat의 문서 작성 의도, 소유 프로젝트, 요청 내용, 접근 가능한 브랜드·프로젝트·기획 자료, 사용자 선택 초안과 명시 포함 자료. 확정 CK는 기본으로 사용하고 선택한 DRAFT는 상태·revision·출처를 함께 전달합니다. 사용자 요청에 따라 현재 세션의 대화·미반영 Artifact를 그 세션의 비정본 출처로 포함할 수 있습니다(Q16). 다른 세션의 미등록 내용을 자동 공유하지 않습니다. 선택한 기존 문서의 편집 본문을 재생성 참조로 포함할 수 있습니다(Q14). 권한이 없거나 읽지 못한 자료는 실제 입력으로 주장하지 않습니다.

**처리와 출력:** 03은 의도를 04에 자동 라우팅하며 04가 생성 실행과 결과를 책임집니다(Q5). 생성 시작 시 선택된 자료의 일관된 스냅샷을 고정하고 실제 입력 manifest를 만듭니다(Q7). LLM은 요청에 맞춰 목차·순서·표현을 자율적으로 정합니다(Q3). 상세페이지도 기본적으로 글과 구성이지 완성 HTML이나 이미지가 아닙니다. 제공되지 않은 사실과 수치를 확정 사실로 만들지 않습니다(Q8). 가능한 부분은 작성하고 결손·불확실성을 메타데이터로 남기며 근본적으로 생성할 수 없을 때 필요한 질문을 합니다(Q17). DRAFT를 확정으로 승격하거나 고정 경고문을 본문에 강제하지 않습니다. 생성 결과를 검토할 수 있게 제공하고 사용자의 저장 선택 전에는 Document로 영속 저장하거나 CK를 수정하지 않습니다.

**예외:** 자료 일부 읽기 실패는 이용한 범위와 누락을 구분합니다. 권한 상실 또는 프로젝트 삭제 시 해당 자료를 사용하거나 늦은 결과로 프로젝트를 부활시키지 않습니다. 생성 실패·중단은 완료로 표시하지 않습니다. 새로고침·재진입 시 확인 가능한 상태만 보여 주며 별도 자동 복구는 확정하지 않습니다.

**논리 상태:** 요청 → 자료 확인 및 고정 → 생성 중 → 검토 가능한 후보 / 실패·중단 → 사용자 저장 선택 → 저장 확인 / 결과 미확인. 이는 UX/API enum을 정한 것이 아닙니다. 저장 미확인은 성공이나 실패로 추정하지 않고 결과 확인을 시도하며 동일한 쓰기를 자동 반복하지 않습니다.

## 3. 편집·변경 감지·재생성

**입력:** 사용자가 선택한 저장 Document와 그 편집 기준 revision, 에디터 수정 내용 또는 재생성 요청, 필요한 경우 기존 본문의 명시적 참고 선택. **출력:** 직접 수정 저장은 같은 Document의 편집 revision을 갱신하며 CK는 변경하지 않습니다(Q18). 동시 수정·삭제·권한 변경은 확인해 충돌 또는 미확인을 구분하고 사용자의 편집안을 자동 덮어쓰지 않습니다. 정확한 충돌 UX와 버전 표현은 후속입니다.

04는 각 문서의 실제 입력/참조 manifest와 현재 자료 revision을 비교해 해당 근거의 변경을 감지합니다(Q15). 무관한 프로젝트 변경만으로 일괄 변경 표시하지 않고, 원본 변경으로 문서 본문을 자동 수정하지 않습니다(Q4). 원본이 삭제되거나 접근 불가하면 현재 비교 불가를 구별하며 없는 내용을 복원하지 않습니다.

사용자의 최신화 요청은 **전체 문서 재생성**입니다(Q10 B). 사용자가 원하면 기존 에디터 본문을 참조할 수 있지만 문장 보존·부분 패치·자동 병합은 보장하지 않습니다(Q14 B). 새 결과를 검토 후 저장하면 기존 문서의 편집 revision이 아닌 **새 독립 Document**가 됩니다(Q13 B). 기존 문서와 미저장 편집안은 보존하고 새 문서는 새 입력의 출처를 기록합니다.

## 4. 삭제·내보내기·수명

04가 문서 생성·수정·삭제 도구 작업을 소유합니다(Q20). 대상·권한·사용자 의도와 결과를 확인해야 하며 Q20 자체는 무승인 자율 삭제·덮어쓰기 승인이 아닙니다. 정확한 확인 UX·위임 범위는 PRODUCT_OPEN입니다. Chat 삭제는 이미 프로젝트에 저장된 문서를 일괄 삭제하지 않습니다. 삭제된 출처 Chat은 접근 불가로 구분하고 복원하지 않습니다. 프로젝트 삭제 뒤 늦은 생성 결과는 저장하지 않습니다. 삭제 및 실행 경합의 실제 보장은 공동 확인입니다.

저장된 문서의 선택 revision을 .txt, .md, .docx, .pdf로 출력합니다(Q19). 내보내기는 문서나 CK를 수정하지 않으며 실패 시 성공한 파일로 표시하지 않습니다. 미저장 편집 내용의 출력 여부와 서식·메타데이터 포함 방식은 미정입니다. 기존 03 원본 기획 내보내기는 별개의 .md/.txt 계약으로, GD-009의 추가 기록 기본 포함과 GD-011의 필수 자료 불완전 시 전체 보류를 유지하며 AI 재작성하지 않습니다.

## 5. 인수 조건과 미결

- 직접 수정한 CK-03과 AI가 승인받은 CK-03은 같은 정본이며 미선택 CK와 편집안은 그대로입니다. 기준 revision 7의 후보에 현재 8이 있으면 적용을 보류합니다.
- 선택한 DRAFT와 명시한 세션 자료의 상태·출처를 보존하고 정본 확정이나 타 세션 공유를 하지 않습니다. 생성 중 원본이 바뀌어도 시작 스냅샷을 혼합하지 않습니다. 근거 없는 수치는 만들지 않고 결손을 남깁니다.
- 같은 종류 문서 세 개는 독립 문서입니다. 참조한 CK만 바뀌면 변경을 감지하며 무관한 변경은 해당하지 않습니다. 기존 문서 선택 참조 후 전체 재생성·저장 시 새 문서가 생기고 원본은 유지됩니다.
- 네 형식은 저장 문서를 출력하며 03 원본 내보내기의 두 형식을 바꾸지 않습니다. Chat 삭제 후 저장 문서는 남고 프로젝트 삭제 후 늦은 결과는 반영되지 않습니다. 권한 상실·쓰기 미확인은 성공으로 꾸미거나 무승인 재시도하지 않습니다.

PRODUCT_OPEN: 삭제/AI 수정 확인과 권한 위임 UX, 세션·기존 문서 선택 UX, 미저장 편집 내보내기 및 문서 복구 제공 여부. EXACT_OPEN: CK 내부 revision 해상도, 본문 형식·문서 편집 충돌 처리·이력 보존, manifest/스냅샷 저장·원자성, 참조 변경 판정 세부, 변환 품질·메타데이터 표현. UPSTREAM_BLOCKED: C-01~03의 권한·자료/버전 조회·조건부 쓰기·삭제/결과 확인·제공 조건. 기능 선택은 FIXED, 구현과 실행 검증은 NOT_IMPLEMENTED/NOT_TESTED입니다.
