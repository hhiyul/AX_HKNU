# 04 기획 산출물 사용자 기능명세

**2026-11-25 현행 적용:** [v0.3-R2 사용자 정본](ax-studio-user-feature-spec-v0.3.md)과 [개정 계약](../03-module-feature-spec/ai-pipeline-contract-revision-2026-11-25.md)을 우선합니다. 아래 단일 대화/같은 타임라인 전제는 GD-046·049로 대체합니다. 새 항목 AI 입력은 같은 문서 저장 맥락·같은 항목 이력·선택 외부 자료이고, 지정 파일 원문을 지원/권한 확인 뒤 읽습니다. 현재 사실 원본 변경의 영향 항목 재검토, 접근 불가의 기존 완료 보존, 기본 규칙 검사/명시 AI 점검, 현재 저장본의 검토 전 Word/PDF를 적용합니다. 기존 자유형 생성/전체 재생성·사용자 저장·출처와 원문 사본 금지·휴지통은 대체되지 않은 범위에서 유지합니다. 아래 과거 ‘최신’ 문구는 당시 기록입니다.

**2026-11-23 v0.3-R1 적용 범위:** [사용자 명세 v0.3](ax-studio-user-feature-spec-v0.3.md), [결정 기록](ax-studio-mvp-decisions-v0.3.md), [인수 추적표](ax-studio-mvp-acceptance-v0.3.md)를 우선합니다. 이 문서는 기존 자유형 04의 보조 명세입니다. CK는 미작성/작성됨이고 별도 확정 단계가 없으며(D-MVP-012), 작업 기록은 프로젝트당 여러 독립 기록입니다(D-MVP-013). 사용자용 전체 백업/가져오기는 P1, 운영 DB+첨부 복구 검증은 P0입니다(D-MVP-014). 새 항목 AI는 후보 → 편집안 적용 → 사용자 저장, 문서 삭제는 휴지통·복구이며 단일 대화의 삭제/새 대화는 없습니다. 세 제품 정합 사항은 종결됐으며 신규 구현·인수는 아직 수행하지 않았습니다.

**최신 제품 정정 GD-041·042:** 프로젝트별 지속 Chat은 하나이고 삭제/새 대화 기능은 제공하지 않습니다. CK-01~06은 사용자 직접 편집만 가능하며 AI의 Field별 CK 반영 경로는 제외합니다. 아래 해당 이전 Q1·Q6 문구는 이 범위에서 대체된 이력입니다. 04 독립 문서 생성·다중 문서·변경 감지·4형식 내보내기는 유지하고 04 문서 저장이 CK를 변경하지 않습니다.


**2026-11-12 P5 저장소 연결:** Q-P5-07에 따라 03 Chat 첨부 원문과 04 산출물은 같은 프로젝트 파일 저장소를 활용합니다. 04의 문서 소유·프로젝트 1:N·revision·UI 승인·출처에 원본 사본 없음은 유지하며, 공통 저장소만으로 다른 Chat 첨부를 자동 참조하거나 CK에 반영하지 않습니다(GD-033·039). 실제 물리 경로·접근·삭제/보존은 공통 owner와 후속 확인합니다.

## 1. 목적과 자원

사용자는 프로젝트와 기획 내용을 토대로 사업계획서·상품기획서·상세페이지 등의 글을 생성하고 검토·편집·저장·내보냅니다. CK-01~06은 02의 정본이며 사용자가 직접 편집·저장합니다. AI의 CK 변경용 Artifact·도구·승인 경로는 제공하지 않습니다(GD-042). 04 문서는 별도 결과물이며 프로젝트 아래 같은 종류를 포함해 여러 개를 둘 수 있습니다(Q11). 03의 작업 기록(record)은 프로젝트당 여러 독립 제목·본문 기록이며, D-MVP-013이 UF-AI-16의 한 문서 규칙을 대체합니다. 문서와 작업 기록은 별개 자원입니다. Document 본문은 자유형 Markdown 문자열이며 제목·목록·링크를 표현합니다(GD-036). 제목·문서 식별·편집 revision과 입력 출처·기준 revision·상태·결손은 본문과 논리적으로 분리해 보존합니다(Q2·Q9·Q12). 지원 문법 세부와 저장 스키마는 후속입니다.

## 2. 생성과 검토

**입력:** 04 직접 요청 또는 03 Chat의 문서 작성 의도, 소유 프로젝트, 요청 내용, 접근 가능한 브랜드·프로젝트·기획 자료와 명시 포함 자료를 받습니다. 저장 CK는 미작성/작성됨으로 구분하고 내용·revision·출처를 전달합니다. 작성됨을 사실 검증이나 최종 확정으로 간주하지 않으며 확정 CK만 사용하는 필터·DRAFT 추가 선택은 없습니다(D-MVP-012). 기존 자유형 생성은 허용된 프로젝트 맥락을 사용하고, 새 항목 AI/할 일 제안은 AX-UF-05의 이번 요청 선택 범위를 따릅니다. 사용자가 명시한 대화·미저장 문서 편집안·생성 후보는 해당 출처의 비정본 내용으로 구분합니다(Q14·16). 미선택 이력을 새 항목에 자동 주입하지 않으며 읽지 못한 자료를 실제 입력으로 주장하지 않습니다.

**처리와 출력:** 03은 의도를 04에 자동 라우팅하며 04가 생성 실행과 결과를 책임집니다(Q5). 생성 시작 시 선택된 자료의 일관된 스냅샷을 고정하고 실제 입력 manifest를 만듭니다(Q7). LLM은 요청에 맞춰 목차·순서·표현을 자율적으로 정합니다(Q3). 상세페이지도 기본적으로 글과 구성이지 완성 HTML이나 이미지가 아닙니다. 제공되지 않은 사실과 수치를 확정 사실로 만들지 않습니다(Q8). 가능한 부분은 작성하고 결손·불확실성을 메타데이터로 남기며 근본적으로 생성할 수 없을 때 필요한 질문을 합니다(Q17). 저장된 가설을 확정 사실로 승격하거나 고정 경고문을 본문에 강제하지 않습니다. 생성 결과를 검토할 수 있게 제공하고 사용자의 저장 선택 전에는 Document로 영속 저장하거나 CK를 수정하지 않습니다.

04 문서 생성의 초기 모델은 OpenAI `gpt-6-luna`입니다(GD-040). 실제 계정 지원·인증·호출 및 품질 검증은 별개이며 모델 지정만으로 제공을 보장하지 않습니다.

**예외:** 자료 일부 읽기 실패는 이용한 범위와 누락을 구분합니다. 권한 상실 시 새 조회·후속 재사용은 기존 GD-015·016에 따라 판단하며, 프로젝트 삭제 뒤 늦은 결과로 프로젝트를 부활시키지 않습니다. 생성 실패·중단은 완료로 표시하지 않습니다. 새로고침·재진입 시 확인 가능한 상태만 보여 주며 별도 자동 복구는 확정하지 않습니다.

**논리 상태:** 요청 → 자료 확인 및 고정 → 생성 중 → 검토 가능한 후보 / 실패·중단 → 사용자 저장 선택 → 저장 확인 / 결과 미확인. 이는 UX/API enum을 정한 것이 아닙니다. 저장 미확인은 성공이나 실패로 추정하지 않고 결과 확인을 시도하며 동일한 쓰기를 자동 반복하지 않습니다.

## 3. 편집·변경 감지·재생성

**입력:** 사용자가 선택한 저장 Document와 그 편집 기준 revision, 에디터 수정 내용 또는 재생성 요청, 필요한 경우 기존 본문의 명시적 참고 선택. **출력:** 직접 수정 저장은 같은 Document의 편집 revision을 갱신하며 CK는 변경하지 않습니다(Q18). 동시 수정·삭제·권한 변경은 확인해 충돌 또는 미확인을 구분하고 사용자의 편집안을 자동 덮어쓰지 않습니다. 정확한 충돌 UX와 버전 표현은 후속입니다.

04는 각 문서의 실제 입력/참조 manifest와 현재 자료 revision을 비교해 해당 근거의 변경을 감지합니다(Q15). 무관한 프로젝트 변경만으로 일괄 변경 표시하지 않고, 원본 변경으로 문서 본문을 자동 수정하지 않습니다(Q4). 원본이 삭제되거나 접근 불가하면 현재 비교 불가를 구별하며 없는 내용을 복원하지 않습니다.

저장 문서의 출처 정보는 실제 입력 자료의 식별·상태·revision·세션 귀속 등 메타데이터를 유지하고 원본 사본은 보관하지 않습니다(GD-039). 원본이 없어지거나 첨부가 삭제된 뒤 해당 원본을 다시 조회·복원하지 않으며, 이미 작성된 문서 본문과 원본 사본은 구분합니다. 생성 중 선택 입력의 일관된 고정은 계속 필요합니다. 단일 지속 Chat의 삭제 기능을 추가하는 뜻은 아닙니다. 생성 입력 원문을 메시지·로그에 통째로 복제하지 않으며, 실제 원본 자료의 운영 백업과는 구분합니다.

기존 자유형 문서의 전체 최신화 요청은 **전체 문서 재생성**입니다(Q10 B). 사용자가 원하면 기존 에디터 본문을 참조할 수 있지만 문장 보존·부분 패치·자동 병합은 보장하지 않습니다(Q14 B). 새 결과를 검토 후 저장하면 **새 독립 Document**가 됩니다(Q13 B). 기존 문서와 미저장 편집안은 보존합니다. 새 템플릿의 항목 초안·다듬기는 이 전체 재생성과 다른 경로로, 같은 문서·항목의 후보를 사용자 편집안에 적용하고 별도로 저장합니다(AX-UF-06). 기존 자유형 문서를 항목형으로 강제 변환하지 않습니다.

## 4. 삭제·내보내기·수명

04가 문서 생성·편집·출력의 책임을 갖습니다(Q20). GD-035는 AI 수정·삭제 도구의 승인 조건에 관한 과거 결정이며 후속 P5에서는 해당 경로를 구현 범위에서 제외했습니다. D-MVP-001은 새 템플릿 항목의 **AI 후보 → 사용자 적용 → 편집 → 별도 저장**만 확장합니다. AI 직접 저장·삭제나 CK 변경 도구를 허용하지 않습니다. 문서 삭제는 사용자가 대상·내용을 확인해 휴지통으로 이동하며 복구할 수 있습니다(D-MVP-004가 GD-038 대체). 같은 문서·항목·저장 상태와 메시지/할 일 연결을 보존하고 관련 할 일·대화·원본 자료를 연쇄 삭제하지 않습니다. 삭제·복구 실패/미확인은 성공으로 표시하지 않으며 삭제 전 AI 후보는 복구 후 자동으로 유효해지지 않습니다. 단일 지속 Chat의 삭제·초기화는 제공하지 않고 프로젝트 삭제 뒤 늦은 생성 결과도 저장하지 않습니다. 영구 삭제 UI는 신규 P0에 추가하지 않으며 물리 보존 기간·삭제 경합 보장은 후속 설계/검증에서 확정합니다.

선택한 기존 자유형 문서의 현재 저장 revision에 있는 Markdown 본문을 .txt, .md, .docx, .pdf로 출력합니다(Q19·GD-036). 미저장 수정이 있으면 파일에는 저장본만 포함됨을 알리고 수정 내용까지 출력하려면 먼저 저장하도록 안내합니다(GD-037). 과거 revision 선택·복원 기능을 추가하는 결정은 아닙니다. 각 형식의 세부 변환과 미지원 문법 처리는 후속이며, 사용자의 문서 내용을 바꾸기 위한 AI 재작성은 아닙니다. 내보내기는 문서나 CK를 수정하지 않으며 실패 시 성공한 파일로 표시하지 않습니다. 파일에 메타데이터를 포함할지는 미정입니다. 기존 03 원본 기획 내보내기는 별개의 .md/.txt 계약으로, GD-009의 추가 기록 기본 포함(모든 저장 기록, D-MVP-013)과 GD-011의 필수 자료 불완전 시 전체 보류를 유지하며 AI 재작성하지 않습니다. 새 템플릿 문서는 AX-UF-11에 따라 모든 항목의 미저장 변경을 확인하고 사용자 저장이 전부 성공한 뒤 일관된 저장본을 출력합니다. 일부 저장 실패 시 출력은 보류하며 성공한 저장과 남은 편집안은 보존합니다.

## 5. 인수 조건과 미결

- CK-03은 사용자 직접 수정만 가능하며 AI의 CK 반영 후보·승인 경로는 없습니다(GD-042). 새 문서 항목의 AI 후보는 요청 당시 저장/편집 기준과 현재 값이 다르면 자동 적용하지 않고 기존 편집안을 보존합니다.
- 저장 CK의 가설·미정 및 명시한 대화/편집안의 상태·출처를 보존하고 저장을 사실 확정으로 취급하지 않습니다. 조회 실패를 미작성 CK로 추정하지 않습니다. 생성 중 원본이 바뀌어도 시작 시 입력을 혼합하지 않으며 근거 없는 수치는 만들지 않습니다.
- 같은 종류 문서 세 개는 독립 문서입니다. 참조한 CK만 바뀌면 변경을 감지하며 무관한 변경은 해당하지 않습니다. 기존 문서 선택 참조 후 전체 재생성·저장 시 새 문서가 생기고 원본은 유지됩니다.
- 네 형식은 저장 문서를 출력하며 03 원본 내보내기의 두 형식을 바꾸지 않습니다. 단일 Chat 삭제 기능은 없고 문서 휴지통 이동은 대화·할 일을 삭제하지 않습니다. 프로젝트 삭제 후 늦은 결과는 반영되지 않습니다. 권한 상실·쓰기 미확인은 성공으로 꾸미거나 무승인 재시도하지 않습니다.

OPEN-MVP-01~03은 [D-MVP-012~014](ax-studio-mvp-decisions-v0.3.md)로 종결했습니다. 대화 개수·항목 AI·문서 휴지통·CK 상태·작업 기록 개수·사용자 백업 P1은 다시 질문하지 않습니다. EXACT_OPEN: 지원 문법·충돌·이력 보존, manifest 표현·실행 중 입력 고정 수명·원자성, 참조 변경 판정·변환 품질·삭제/복구 경합·운영 DB+첨부 백업/복구. 기존 C-01~03은 통합 코드의 실제 제공 범위와 대조해 G-S/G-D에서 갱신합니다. 설계 미정은 별도로 남기며 코드 존재만으로 계약·인수 완료를 주장하지 않습니다.

## 6. 2026-11-12 UX 관찰과 정합 사항

아래는 당시 관찰 기록입니다. Q1의 CK 승인 반영은 GD-042로 대체됐으며 이 관찰을 현행 제품 요구나 실제 통합 완료로 사용하지 않습니다.

[Figma IA v0.2](https://www.figma.com/design/QESgySmqjIcX38YAI1eSf2/D%EA%B9%80%EB%8F%84%EA%B2%BD_UX-Document?node-id=24-4392)는 상품기획을 기준본, 산출물을 활용 문서로 구분하며 AI 제안의 기존 정보 비교·부분 선택·사용자 적용을 표현합니다. 이 IA의 초안 저장 → 사용자 확정 도식은 기존 D-UF-042의 직접 재확정 허용을 취소하지 않으며, 자유형 생성·새 문서 재생성 등 Q1~Q20의 세부 결정을 대체하지 않습니다.

[디자인팀 웹 프로토타입](https://duing.shop/AX/)을 브라우저에서 관찰했습니다. 브랜드 없이 여섯 항목을 건너뛰어 작업실에 진입하고 CK-03을 직접 수정·저장할 수 있었습니다. 모의 AI 답변 검수·확정은 여섯 기존 기획 항목과 별도인 ‘AI와 함께 정리한 내용’에 저장되고 기존 CK-03은 바뀌지 않았습니다. 이는 Q1의 Field별 선택 승인으로 동일 CK를 갱신하는 채택 방향과 정합이 필요합니다.

산출물에서 AI 채팅으로 이동해 문서 요청 시 여섯 항목을 나열한 모의 문서가 생성됐고 ‘산출물로 저장하기’는 별도 검수 화면 없이 저장된 문서 목록으로 이동했습니다. 저장된 본문을 직접 편집·저장하고 다시 열어 유지됨을 확인했습니다. 이후 문서에 사용된 CK-03을 변경했을 때 확인한 산출물 목록·편집 화면에는 변경 감지 안내가 보이지 않았습니다. 편집 화면에는 PDF 다운로드 버튼이 있었으나 파일 출력은 시험하지 않았습니다. Q3의 LLM 자유 구성, Q10·13의 전체 재생성과 새 문서, Q15의 참조 revision 변경 감지, Q19의 네 형식 제공을 이 시연으로 검증할 수 없습니다. 화면은 실제 LLM 미연결·로컬 시뮬레이션이라고 명시하며 제품 구현이나 영속 API의 증거가 아닙니다. 실제 서버 동작·권한·revision 추적은 NOT_TESTED입니다.
