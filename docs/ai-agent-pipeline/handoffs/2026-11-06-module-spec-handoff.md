### 맥락·지시문·압축의 수치 계약

- 현재 프로젝트 상태·활성 접근 가능 파일/Chip은 비압축 prefix. 사용자 발화·도구 자료도 압축하지 않습니다. 압축은 **오래된 AI 출력만**입니다. 추가 기록의 기본 자동 참고 범위는 아직 미정입니다.
- 입력 예산은 실제 모델 한도 − 출력 8k − 여유 8k입니다. k=1,000토큰. AI 이력 100k 초과 또는 전체 입력 예산 초과 예상 시 압축, 캡슐 4k+최근 AI 응답 16k 목표입니다. 전체 입력에는 지시문/도구 정의·이미지 등 실제 전달량을 반영해야 합니다.
- 최초 실패/부족 시 현재 요청에서 **OpenAI 추가 압축 1회** 후 검증·전체 재계산. 수용 가능하면 원래 요청 계속, 재실패/여전한 초과는 종료·원인/다음 행동. 무한 재귀/비AI 압축/무단 자료 절삭 없음. 일반 대화 Provider까지 OpenAI로 확정된 것은 아닙니다.
- D-UF-100의 여섯 행동 계약: 목적/범위·작은 다음 행동, 사실/가정/미정, 관련 CK 기준, 최소 변경/UI 반영, 허용 자료/도구·자료의 비지시성, 간결한 실제 결과/완료 안내. 실제 프롬프트는 다음 모듈 설계 대상입니다.
- 사용자가 지정한 [CLAUDE.md](https://github.com/multica-ai/andrej-karpathy-skills/blob/main/CLAUDE.md)는 이 행동 방향의 참고였으며 설치된 스킬·저장소 AGENTS·특정 LLM 선정은 아닙니다. 정본에 이미 통합된 여섯 계약을 우선합니다.

## 5. 아직 닫지 않은 제품·공동 계약

모든 사용자 흐름이 닫혔다는 뜻은 아닙니다. 아래 범위에 영향을 주지 않는 모듈 명세는 진행할 수 있습니다.

| 우선·분류 | 상황·남은 선택 | 다음에 다룰 때의 경계 |
| --- | --- | --- |
| 제품 P-01 | 현재 편집 “카드 3장/비용 1,500원”에 후보 “5장/2,500원”의 비용만 가져오기. 적용 후 불일치 안내 vs 전제 정리까지 가져오기 보류 **둘 다 미채택** | M-02·04·08의 해당 경로 전에 사용자 결정. 최신 결정 존중/최종 UI 승인·이력 경량화로 해소된 것 아님 |
| 제품 OPEN-UF-16 | 추가 기록의 기본 내보내기 포함 및 후속 Chat 자동 참고/Projection 필드 범위 | 기본 export 여섯 CK만 유지. 문서 자체 열람/수정 요구를 모든 요청 자동 주입으로 확대하지 않음 |
| 제품·디자인 계산 | 자동 계산 최초 범위와 요청/결과 UI, 기초 계산 vs 목표 역산 **둘 다 미채택** | 디자인팀과 먼저 논의. 기존 부분 계산·누락 비용 보류는 유지 |
| 자료 사용자 결과 | 일반 Chip 실패 후 재시도/재선택 최신성, 원본 삭제/권한 변화 결과 | 기존 명시 Projection 재시도·제거 다음-run 합의와 구분. 접근 불가 우회 금지 |
| 실행 사용자 결과 | 일반 중단 후 제공할 결과·재요청 안내 | 자동 작업 복구·큐 도입으로 대신 해결하지 않음 |
| 공동 C-01 | 권한·공통 자원/1:1 소유·Projection·쓰기/삭제·원문/내보내기·추가 기록·원 요청 결과 조회 | 팀원 API/데이터 소유 확인 전 실제 지원 선언 불가 |
| 공동 C-02 | 통화/판매 단위·수수료/세금/배송·배부·반올림/근거 | 실제 기준 없으면 부분 설명만. 임의 산식/미정값 대입 금지 |
| 공동 C-03 | 모델/인증/도구·파일 지원과 한도·기본 저장 기간/접근·제공 이력 | 데모 상수와 현재 의존성 목록으로 제공 보장하지 않음 |

모듈 문서의 **MC-01~12**는 이 제품·공동 결정을 정확한 Python/Provider/저장/UI 계약으로 내릴 때의 질문 목록입니다. 새 제품 결정의 번호를 대신하지 않으며 아직 답이 정해졌다는 뜻도 아닙니다.

## 6. 현재 백엔드의 실제 범위와 환경 주의점

- `backend/main.py`에는 `GET /`, `GET /hello/{name}`만 있습니다. 현재 소스에서 Chat·Agent·도구·MongoDB 클라이언트·저장 API·인증·요청 결과 조회는 확인되지 않습니다. 옛 `__pycache__`나 과거 세션의 부트스트랩 설명을 현재 구현으로 인정하지 않습니다.
- 직접 의존성 원본은 `backend/requirements.in`, 고정 목록은 `backend/requirements.txt`입니다. 후자의 헤더는 Python **3.11** 생성이고 Docker도 **3.11-slim-bookworm**입니다. 과거 사용자의 3.10 정렬 의도와 다르므로 **MC-01에서 백엔드 팀과 대상 버전 확인**이 우선입니다. 이번에 Python/lock을 변경하거나 설치하지 않았습니다.
- Compose는 React → Spring Gateway → FastAPI 연결을 정의합니다. `MONGO_DETAILS` 전달은 있으나 DB 연결 코드/준비 완료 증거가 아닙니다. healthcheck는 `/openapi.json` 접근이며 DB나 Provider ping이 아닙니다.
- 저장소에서 확인한 `backend/test_main.http`는 수동 HTTP 예시입니다. 현재 모듈 단위시험·Provider SDK·문서 파서·토큰 계산기 계약은 없습니다. 실행해 보지 않았으므로 설치/호환/테스트 PASS를 말할 수 없습니다.
- MongoDB Atlas 설정은 사용자가 팀원 상의를 위해 중단한 상태입니다. 새 인프라 생성이나 연결 설정 재개는 이번 작업의 범위가 아닙니다. 연결 문자열/비밀값을 채팅·문서·로그로 요구하거나 출력하지 않습니다.
- 시스템 기능명세는 팀원 작성 대기입니다. 전체 백엔드/프로젝트·브랜드 생성은 팀원 담당, AI Chat 파이프라인/하네스는 사용자 담당이라는 협업 경계를 지킵니다.

## 7. 다음 세션의 권장 진행 순서

1. **기준 확인:** AGENTS·Git 상태·작업 트리 v0.2·모듈 초안을 읽고 변경된 상위 계약/소스가 있는지 확인합니다. 자동 pull/merge, 전역 `git add`, 기존 dirty 작업 수정은 하지 않습니다.
2. **진행할 책임 선택:** MC-01의 Python 기준과 MC-02·03의 서비스/백엔드 제공 가능 범위를 확인합니다. 당장 팀 답이 없더라도 논리 포트/미정을 분리해 명세는 전진할 수 있습니다.

## 8. 이후 단위검증 목표와 증거 구분

모듈 초안의 UT-01~32는 **시험 계획**입니다. 아직 테스트 파일이나 통과 결과가 아닙니다.

| 단계 | 필요한 증거 | 이 증거만으로 말할 수 없는 것 |
| --- | --- | --- |
| 명세 정합 | UF·결정·정상/예외·입출력·OPEN·수용 사례가 연결됨 | Python 구현 완료 |
| 모듈 단위시험 | 가짜 Provider/저장소/시계/토큰 계산기와 작은 fixture로 정책·실제 어댑터 payload/파싱·오류 검증 | 실제 LLM·MongoDB·Gateway 연결 또는 자연어 품질 |
| 루프/파이프라인 단위시험 | 가짜 포트 조합으로 도구 순서·중단·근거·승인/쓰기 경계·실패 전파 확인 | 실서비스 통합/E2E |
| LLM 실호출 | 별도 허용된 모델/키/호출 범위로 실제 연결/응답 확인 | 단위시험을 대신한 전 경로 보장 |
| DB/통합·브라우저 | 나중에 별도 범위·환경으로 확인 | 이번 목표에 자동 포함되지 않음 |

특히 실제 자료 획득과 최종 Provider payload를 잇는 경로, UI 승인 없는 쓰기 0회, 삭제/제외 자료 우회 재사용, 검색 끄기와 파일/Chip 제거의 서로 다른 시점, 압축 추가 1회, 충돌 대기·미확인 재전송 차단을 반례로 검증해야 합니다. 단위시험을 위해 live 키·Atlas를 기본 요구하지 않습니다. 테스트 도구/명령은 MC-12를 닫은 뒤 정합니다.
