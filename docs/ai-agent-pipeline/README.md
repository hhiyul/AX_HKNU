# AI 에이전트 파이프라인 명세

AI 채팅 파이프라인·평가와 제안·도구 호출·에이전트 루프·하네스를 상위 요구사항부터 정리하는 문서 디렉터리입니다. 현재는 **사용자 기능 초안의 범위·흐름·완료 기준을 먼저 맞추는 단계**이며 모듈 설계·구현은 시작하지 않았습니다.

## 현재 상태와 읽기 순서

| 순서 | 문서·계층 | 역할·현재 상태 |

상위 시스템보다 먼저 작성한 사용자 초안은 사용자의 명시적 요청과 확인된 제품 기준에 근거합니다. 시스템 명세가 준비되면 범위·권한·데이터·기능 ID를 대조합니다. 분석 자료나 사용자 초안이 상위 명세를 대신하지 않습니다.

## 유지하는 제품 기준

- 전체 백엔드·프로젝트 구성·브랜드 생성은 팀원 담당입니다. 이 세션의 파일 변경 범위는 `docs/ai-agent-pipeline/`입니다.
- PLAN-01·PLAN-02는 폐기됐습니다. Chat이 주 흐름이며 여섯 체크리스트를 정해진 순서로 작성하게 하지 않습니다.
- AI는 내부 평가·설명·질문·편집 가능한 제안을 제공합니다. 저장된 내용·상태는 사용자 저장·확정 선택과 서버 검증 후 갱신합니다.
- 프로젝트 연결 Chat의 저장 대상은 하나로 고정합니다. 독립 Chat의 최초 연결, 연결 전 제안의 명시적 재검토, 재조회·변경 판정은 기존 합의를 유지합니다.
- 고객 선정은 대상·목적·접점·근거가 연결된 가설을 다룹니다. 가설 구체화와 실제 검증을 분리하며, 기존 필수·조건부 정보·평가·진행 대상·재선택 합의를 유지합니다.
- 막연한 판매 고민에는 AI가 현재 자료로 우선 문제·이유·가정을 설명하고 작은 대안이나 다음 행동을 제안하며, 사용자가 방향을 바꿀 수 있습니다. 방향 추천은 가설의 진행 대상 지정·저장·확정을 대신하지 않습니다(D-UF-031, 2026-11-02).
- 대화 중 구체안이 생기면 필요한 부분을 편집·저장 검토용 제안으로 제공합니다. 별도 정리 요청을 필수로 기다리거나 매 응답 제안을 의무화하지 않으며, 제안만으로 저장·확정하지 않습니다(D-UF-032, 2026-11-02).
- 독립 Chat에서 저장하려는데 프로젝트가 없으면 공통 생성 흐름으로 안내하고 완료 후 같은 Chat에서 최초 연결합니다. 프로젝트 생성 결과와 체크리스트 저장은 별개이며 연결만으로 재검토·저장하지 않습니다(D-UF-033, 2026-11-02).
- 기획 구체화가 미완료여도 남은 미정·영향을 안내하고 사용자가 명시적으로 확정할 수 있습니다. 내부 평가의 미완료·남은 사유와 기존 서버 검증·제안 저장 보류 규칙은 유지합니다(D-UF-034, 2026-11-02).
- 상품 선정의 구체화 완료에는 이번 펀딩의 판매 대상·범위 식별이 필수이며 최종 규격·옵션·가격은 요구하지 않습니다. 이 요건만으로 전체 완료나 저장·확정을 선언하지 않습니다(D-UF-035, 2026-11-02).
- 구매 가치의 구체화 완료에는 고객의 참여·구매 목적과 연결된 선택 이유가 필수입니다. 가설 설명을 허용하며 실제 구매 반응이나 고객 선정의 선행 완료·저장은 요구하지 않습니다(D-UF-036, 2026-11-02).
- 상품 구성의 구체화 완료에는 한 판매 단위의 핵심 구성·수량이 필수입니다. 기획 가설을 허용하며 최종 가격·제작 확정은 선행 요구하지 않습니다(D-UF-037, 2026-11-02).
- 가격·원가의 일부 비용이 미정이면 계산 가능한 부분·명시 가정·누락 비용과 영향을 안내하고 총원가·최종 이익 판단은 보류합니다. 미정 비용은 0이나 임의 값으로 채우지 않습니다(D-UF-038, 2026-11-02).
- 제작 가능성의 구체화 완료에는 이번 펀딩의 제작 규모·목표 일정 가설이 필수입니다. 추정·범위를 허용하며 실제 제작 검증·보증·전체 완료와 구분합니다(D-UF-039, 2026-11-02).
- 같은 체크리스트 안에서는 선택한 변경 범위만 반영하고 나머지 기존 내용을 유지합니다. 제안에서 생략된 내용을 자동 삭제하거나 일부 선택을 항목 전체 교체로 해석하지 않습니다(D-UF-040, 2026-11-02).
- 초안 저장·확정은 사용자가 별도 UI에서 대상·내용과 저장 종류를 확인하고 명시적으로 선택해야 합니다. 명확한 Chat 요청도 이 선택을 대신하지 않습니다. 서버 검증·저장 보류·명시적 재검토는 유지합니다(D-UF-041, 최종 B안, 2026-11-02).
- 확정 내용의 수정안을 사용자가 UI에서 명시적으로 재확정하면 중간 초안 저장 없이 기존 검증 후 선택한 변경 범위를 반영할 수 있습니다. 서버 확인 후 DECIDED를 유지하며 UI 선택·서버 검증·저장 보류 원칙은 그대로 적용합니다(D-UF-042, 2026-11-02).
- 여러 체크리스트에 대해 UI에서 항목별로 초안·확정을 명시적으로 선택한 뒤 함께 반영할 수 있습니다. 선택한 내용·저장 종류와 기존 검증·저장 보류를 유지합니다(D-UF-043, 2026-11-02).
- 검증을 통과하고 저장 보류가 없는 항목만 부분 반영하며, 반영한 항목의 확인된 결과와 반영하지 못한 항목의 사유를 구분해 안내합니다. 결과 미확인을 성공·미반영으로 단정하지 않습니다(D-UF-044, 2026-11-02).
- 실제 영향이 확인된 다른 항목에 한해 변경 결과와 함께 영향·이유·다음 검토를 짧게 안내합니다. 다른 항목의 저장 내용·상태는 자동 변경하지 않습니다(D-UF-045, 2026-11-02).
- 미저장 편집안을 유지하고 새 AI 제안은 별도 후보로 비교한 뒤 필요한 부분만 명시적으로 선택해 가져올 수 있습니다. 비교·가져오기만으로 저장·확정하지 않으며 기존 검증·저장 보류를 유지합니다(D-UF-046, 2026-11-02).
- 가격·원가의 구체화 완료에는 판매 단위에 적용할 기획용 판매가격의 금액·범위가 필수이며 최종 판매가 확정은 요구하지 않습니다. 기존 비용 미정·총원가 및 최종 이익 판단 보류는 유지하고 이 요건만으로 전체 완료를 선언하지 않습니다(D-UF-047, 2026-11-02).
- 중요한 비용이 미정이면 CK-05 전체 구체화 완료를 보류하되 설명 가능한 기획용 추정·범위는 허용합니다. 실제 견적·실측값을 강제하지 않으며 내부 평가 보류와 계산 판단·저장 보류를 구분합니다(D-UF-048, 2026-11-02).
- 판매가격·구성·제작 규모·진행 여부를 바꿀 수 있는 비용을 중요하게 보고 AI가 구체적인 영향·이유를 설명합니다. 항목명·금액 크기만으로 판단하지 않으며 실제 견적/실측 비강제와 임의 값 대입 금지를 유지합니다(D-UF-049, 2026-11-02).
- 제작 가능성의 구체화 완료에는 핵심 구성품의 제작·조달 방식 가설도 필수입니다. 직접 제작·외주·보유 재고 활용 등으로 설명할 수 있으며 업체 확정·계약·실제 제작 검증은 요구하지 않습니다. 이 요건만으로 전체 완료·제작 보증을 선언하지 않습니다(D-UF-050, 2026-11-02).
- 현재 자료·사용자 설명에서 제작 방식·규모·일정의 명백한 충돌이 확인되면 CK-06 전체 구체화 완료를 보류하고 이유·조정 대안을 제시합니다. 실제 제작 검증은 강제하지 않으며 저장된 계획·상태는 자동 변경하지 않습니다(D-UF-051, 2026-11-02).
- 상품 선정 이유는 상품 비교·추천·범위 조정에 영향을 줄 때만 확인하며 그 외에는 미정 자체로 CK-01 전체 완료를 막지 않습니다. CK-03의 고객 참여·구매 목적과 연결된 선택 이유는 계속 필수입니다(D-UF-052, 2026-11-02).
- 판매 대상·범위가 충분히 식별되고 일관되며 현재 상품 선택에 영향을 주는 중요한 미정·충돌이 없으면 CK-01 전체 구체화 완료로 평가합니다. 최종 규격·옵션·가격 확정은 요구하지 않으며 다른 항목의 완료·저장·확정이나 저장 상태 자동 변경과 구분합니다(D-UF-053, 2026-11-02).
- 실제 진행 고객 가설 모두가 기존 필수·조건부 요건을 충족하고 대상·목적·접점/연결 이유가 일관되게 연결되며 중요한 미정·충돌이 없으면 CK-02 전체 구체화 완료로 평가합니다. 첫 접근·판매 실험 계획과 실제 실적·반응은 추가 필수로 요구하지 않으며 기존 평가 보류·저장 분리를 유지합니다(D-UF-054, 2026-11-02).
- CK-03~06의 전체 완료 평가에는 실제 진행안만 포함하고 여러 개면 모두 평가합니다. 미선택 비교 후보의 자체 미정은 완료를 막지 않지만 진행안에 영향을 주는 공통 정보·중요한 미정·충돌은 계속 포함합니다. 저장·확정과는 구분합니다(D-UF-055, 2026-11-02).
- 가져올 내용의 적용 대상이 명확하면 추가 확인 없이 선택한 부분만 적용하고, 모호하면 해당 가져오기 반영을 보류한 채 대상을 먼저 확인합니다. 기존 편집을 유지하고 모호한 원문을 먼저 덧붙이지 않으며 대상 확인을 실제 저장·확정으로 취급하지 않습니다(D-UF-056, 2026-11-02).
- 실제 영향은 변경 결과와 함께 즉시 안내하고 연관된 저장 기획의 후속 검토는 사용자가 명시적으로 요청할 때 시작합니다. 안내만으로 새 검토 제안을 자동 작성하지 않으며 일반 Chat·기존 내부 평가 갱신·부분 제안과 실제 저장의 UI 선택·검증 경계를 유지합니다(D-UF-057, 2026-11-02).
- 현재 DRAFT를 수정해 UI에서 초안 재저장을 명시적으로 선택하고 기존 검증을 통과·저장 보류 없이 서버 저장을 확인하면 선택한 변경 범위만 현재 초안에 반영하고 DRAFT를 유지합니다. 나머지 내용과 기존 검증·보류 규칙을 유지하며 별도 저장 초안 추가·자동 확정으로 처리하지 않습니다(D-UF-058, 2026-11-02).
- 명시적으로 요청한 연관 기획의 후속 검토는 변경 영향 중심을 기본으로 하고 요청 시 항목 전체를 검토합니다. 채택 조건으로 변경·영향받는 항목·이유·다음 검토를 기본 응답에서 바로 식별되게 안내하고, 검토 후 범위·남은 확인 사항을 드러내도록 UX를 강화합니다. 상세에만 숨기거나 부분 검토를 전체 완료로 표시하지 않습니다(D-UF-059, 2026-11-02).
- 최신 대화 결정은 현재 작업 기준으로 존중하고 변경 요약을 보여준 뒤 사용자가 편집안 반영을 선택합니다(Q-LATEST-01 B / D-UF-060). 미리 선택한 초안·확정 종류는 유지하고 갱신된 내용에 대한 최종 반영 단추를 사용자가 직접 누르게 하며 별도 중간 적용·종류 재선택을 필수로 늘리지 않습니다(Q-LATEST-02 A / D-UF-061). 기존 검증·저장 보류·명시적 재검토는 유지합니다.
- **D-UF-001~061 전체는 계속 유효**합니다. 정확한 의미·대안·트레이드오프는 [결정 기록](02-user-feature-spec/open-contracts.md), 재정리 전 공통 기준·UF 상세·AC는 [세부 참조본](02-user-feature-spec/agreement-details-v0.1.md)에 보존합니다.

## 남은 일을 다루는 순서

1. [웹 검색·프로젝트 컨텍스트 Chip P0 질문지](02-user-feature-spec/context-and-web-grill.md)로 검색 실행·정보 사용·근거와 Chip 드래그 앤 드롭·참조 지속·제거·처리 결과를 먼저 정리합니다.
2. 재저장·제안 가져오기·연관 항목 검토의 잔여 사용자 동작과 결과를 점검합니다. 필요한 공통 권한·저장 경계는 팀원과 병행 확인합니다.
3. 위 동작을 정리한 뒤 CK-03~06의 전체 구체화 완료 기준을 맞춥니다.
4. R-01~04를 처음부터 끝까지 검토해 자료 사용을 포함한 남은 P0와 P1·공동·모듈 계약을 구분하고 P0 종료 여부를 판단합니다.
5. 대표 실패·나머지 자료 확장·이력·공통 화면에서 사용자가 얻을 결과 등 P1과 필요한 공동 계약을 정리합니다.
6. 그 결과와 이미 확정한 제약을 입력으로 실제 모듈·인터페이스·루프를 설계합니다. 프로젝트 섹션별 컨텍스트 관리는 M-01의 상세 후속 항목으로 기록했습니다.

이는 문서 검토 순서이며 새 제품 워크플로가 아닙니다. 2026-11-02 사용자 요청으로 P0 사용자 기능 Grill을 재개했습니다. 결정한 내용과 잔여 쟁점은 [정리·완료 계획 8절](02-user-feature-spec/user-feature-closure-plan.md#8-p0-사용자-기능-검토-진행)에서 추적하며 모듈 설계는 뒤로 미룹니다.

## 디렉터리와 문서 관리

- `00-prototype-analysis/`: 관찰·분석 근거. 모의 동작을 실제 구현 증거로 사용하지 않습니다.
- `01-system-feature-spec/`: 팀원 담당 상위 시스템 명세와 연결합니다.
- `02-user-feature-spec/`: 사용자 본문, 정리·완료 계획, 하위 문제 검토안, 미정·결정 원문과 세부 참조본을 둡니다.
- `03-module-feature-spec/`: 사용자 기능을 구현할 후속 설계와 이관 목록을 둡니다. 현재는 실제 모듈 명세 작성 전입니다.

각 폴더의 README에서 실제 문서를 연결합니다. 하위 문서는 상위 기능 경로·ID와 기존 결정·미정을 추적하고, 없는 상위 계약을 구현 기본값으로 확정하지 않습니다. 후보·미정·합의·관찰을 구분하며 한글 문서는 UTF-8로 저장합니다. 이 경로는 명세를 관리하며 실행 코드의 위치는 별도 설계 사항입니다.
