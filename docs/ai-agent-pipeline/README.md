# AI 에이전트 파이프라인 명세

AI 에이전트 파이프라인의 명세를 상위 요구사항부터 모듈 설계까지 순서대로 정리하는 디렉터리입니다.

현재는 문서 구조를 준비한 단계입니다. 팀원이 작성할 시스템 기능명세는 아직 없으며, 사용자 기능명세와 모듈 기능명세의 실제 내용도 작성 전입니다.

## 디렉터리 구성

```text
docs/ai-agent-pipeline/
├── README.md
├── 01-system-feature-spec/
│   └── README.md
├── 02-user-feature-spec/
│   └── README.md
└── 03-module-feature-spec/
    └── README.md
```

| 순서 | 명세 | 역할 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | [시스템 기능명세](01-system-feature-spec/README.md) | 전체 시스템의 기능과 범위, AI 에이전트 파이프라인의 위치를 정의합니다. | 팀원 작성 대기 |
| 2 | [사용자 기능명세](02-user-feature-spec/README.md) | 시스템 기능을 사용자의 목적, 사용 흐름, 결과와 완료 기준으로 구체화합니다. | 상위 명세 대기 |
| 3 | [모듈 기능명세](03-module-feature-spec/README.md) | 사용자 기능을 구현할 에이전트 역할, 하네스 구성, 에이전트 루프와 모듈 간 계약을 정의합니다. | 상위 명세 대기 |

## 작성 및 읽기 순서

1. 시스템 기능명세를 먼저 확인하여 기능의 목적과 범위를 맞춥니다.
2. 해당 시스템 기능을 근거로 사용자 기능명세를 작성합니다.
3. 사용자 기능을 충족하도록 모듈 기능명세를 작성합니다.

하위 명세에는 근거가 되는 상위 문서의 상대 경로와 해당 기능명 또는 기능 ID를 연결합니다. 상위 요구사항이 없거나 모호한 부분은 미정으로 남겨 두고, 하위 설계만으로 확정하지 않습니다.

## 문서 관리 기준

- 각 폴더의 `README.md`는 해당 계층의 안내와 문서 목록을 제공합니다.
- 실제 명세 문서는 해당 계층의 폴더에 추가하고 안내 문서에서 연결합니다.
- 문서를 분리할 때는 기능이나 모듈 단위로 나누고, 파일명으로 내용을 식별할 수 있게 합니다.
- 작성 예정 항목, 검토 중인 제안, 확정된 내용을 구분합니다. 안내 문서의 항목 목록은 확정된 기능 요구사항을 뜻하지 않습니다.
- 한글 문서는 UTF-8로 저장합니다.
- 이 경로에는 명세를 관리합니다. 실행 코드의 배치 위치는 모듈 설계 시 별도로 정합니다.
