# AI 에이전트 파이프라인 명세

AI 에이전트 파이프라인의 명세를 상위 요구사항부터 모듈 설계까지 순서대로 정리하는 디렉터리입니다.

현재는 [프로토타입·Figma 분석](00-prototype-analysis/README.md)과 [AI 파이프라인 사용자 기능명세 v0.1 초안](02-user-feature-spec/ai-pipeline-user-feature-spec-v0.1.md)을 준비한 단계입니다. 팀원이 작성할 시스템 기능명세는 아직 없으며, 사용자 기능명세의 상위 추적 관계는 연결 대기입니다. 모듈 기능명세는 작성 전입니다. 분석 자료와 사용자 기능 초안은 상위 시스템 기능명세를 대체하지 않습니다.

## 현재 확인된 제품 기준

- 전체 백엔드, 프로젝트 구성, 브랜드 생성은 팀원이 담당합니다. 이 세션에서는 AI 채팅 파이프라인, 에이전트 루프, 도구 호출과 하네스 구성을 분석하고 명세화합니다.
- 이 세션의 파일 변경 범위는 `docs/ai-agent-pipeline/` 안입니다.
- PLAN-01·PLAN-02는 폐기되었습니다. 첨부 HTML에 남은 PLAN 화면·확정본 선택·데이터 구조는 현행 요구사항으로 채택하지 않습니다.
- 주 작업 방식은 Chat입니다. 상품 기획의 6개 항목은 각각 내용과 상태를 가지며, 고정된 작성 순서를 강제하지 않습니다.
- AI는 내부 평가와 편집 가능한 제안을 만듭니다. 저장된 체크리스트의 내용·상태는 사용자의 저장/확정 선택과 서버 검증을 거쳐 갱신합니다.

위 기준은 2026-10-30 사용자 설명·추가 확인 및 공유 Figma를 근거로 합니다. 상세 항목과 아직 결정되지 않은 계약은 분석 문서에서 구분합니다.

`00-prototype-analysis/`는 위 3단계 명세의 참고 자료입니다. 기존 화면의 기능 목록, 코드·브라우저 관찰, 사용자 정정 사항과 후속 합의 지점을 관리합니다.

## 작성 및 읽기 순서

1. 시스템 기능명세를 먼저 확인하여 기능의 목적과 범위를 맞춥니다.
2. 해당 시스템 기능을 근거로 사용자 기능명세를 작성합니다.
3. 사용자 기능을 충족하도록 모듈 기능명세를 작성합니다.

이번 사용자 기능 초안은 사용자의 명시적인 요청으로 상위 시스템 기능명세보다 먼저 작성했습니다. 현재는 확인된 제품 기준과 분석을 근거로 하며, 시스템 기능명세가 준비되면 범위·권한·공통 데이터의 정합성과 추적 관계를 대조합니다. [미정 계약](02-user-feature-spec/open-contracts.md)은 별도로 유지합니다.

하위 명세에는 근거가 되는 상위 문서의 상대 경로와 해당 기능명 또는 기능 ID를 연결합니다. 상위 요구사항이 없거나 모호한 부분은 미정으로 남겨 두고, 하위 설계만으로 확정하지 않습니다.

## 문서 관리 기준

- 각 폴더의 `README.md`는 해당 계층의 안내와 문서 목록을 제공합니다.
- 실제 명세 문서는 해당 계층의 폴더에 추가하고 안내 문서에서 연결합니다.
- 문서를 분리할 때는 기능이나 모듈 단위로 나누고, 파일명으로 내용을 식별할 수 있게 합니다.
- 작성 예정 항목, 검토 중인 제안, 확정된 내용을 구분합니다. 안내 문서의 항목 목록은 확정된 기능 요구사항을 뜻하지 않습니다.
- 한글 문서는 UTF-8로 저장합니다.
- 이 경로에는 명세를 관리합니다. 실행 코드의 배치 위치는 모듈 설계 시 별도로 정합니다.
