# 컴포넌트·기능 목록

기준과 출처: [분석 개요](README.md) · 동작 확인: [브라우저 기록](browser-verification.md)

아래 번호는 화면 누락을 막기 위한 분석용 식별자입니다. 확정된 시스템 기능 ID나 구현 완료 표시가 아닙니다. 같은 기능의 여러 버튼·진입점은 한 행에서 함께 추적합니다.

## Figma와 사용자 설명으로 추가되는 중심 기능

| ID | 기능 | 현재 HTML과의 관계 | 명세에서 다룰 내용 |
| --- | --- | --- | --- |
| NEW-01 | 6개 기획 항목의 내용·상태 | 정식 데이터 모델·표시 흐름이 아직 없음 | 상품 선정, 고객 선정, 구매 가치, 상품 구성, 가격 원가, 제작 가능성 각각의 내용·상태 |
| NEW-02 | Chat 기반 내부 체크리스트 평가 | 현재는 규칙 기반 고정 응답 | 필요한 항목 조회, 부족한 정보 확인, 도구 사용과 관측 결과 평가 |
| NEW-03 | 항목별 편집 가능한 변경안 | 현재는 AI 답변 전체를 한 필드에 적용 | 대상 항목과 제안 내용, 사용자 수정·항목 제외 |
| NEW-04 | 초안 저장과 명시적 확정 | 현재의 단일 프로젝트 반영으로는 구분하지 않음 | 사용자 선택, 서버 검증, 선택한 항목의 내용·상태 갱신 |
| NEW-05 | 실제 모델·도구·반복 실행 | HTML의 작업 타이머는 모의 실행 | 모델 호출, 도구 디스패치, 결과 관찰, 질문·완료·실패·취소·제한 도달 시 종료 |

여기서 NEW는 구현 대상의 분석 분류이며 기능 추가 승인을 새로 의미하지 않습니다. 특히 구체적인 도구, 스키마, 에이전트 수와 프레임워크는 미정입니다.

## 폐기·교체할 흔적

| 항목 | 현재 흔적 | 적용 기준 |
| --- | --- | --- |
| PLAN-01·PLAN-02 작성·확정 | 예전 편집 컴포넌트 `F0`, 샘플 기획 데이터, 상태 필드 | 사용자 지시로 폐기. 순차 PLAN 명세를 작성하지 않음 |
| Chat의 PLAN 확정본 체크박스 | 고객과 상품의 장점 / 상품 구성과 비용 선택, `plan01`·`plan02` 자료 참조 | 6개 항목의 현재 내용·상태를 읽는 구조로 교체할 접점 |
| 데모 안내의 PLAN 진입 버튼 | 샘플 PLAN-01·PLAN-02 버튼과 옛 시연 순서 | 참고용 잔재. 버튼을 눌러도 현재 프로젝트 상세가 나타남 |
| PLAN 단위 내보내기 | `confirmed`에 예전 PLAN 확정본을 포함 | 현행 기획 데이터의 내보내기로 재정의 필요 |
| 옛 경제성 화면 | `P0`, 비용 입력·가정 승인·시나리오·계산 모의 처리 | PLAN 화면을 복원하지 않음. 가격·원가 및 제작 가능성의 계산 도구가 필요한지는 새 항목 기준으로 명세화 |

## 코드에만 있거나 조건부인 기능

아래 기능은 현재 기본 화면에서 실제 사용되는 기능이라고 단정하지 않습니다.

| 항목 | 관찰 | 취급 |
| --- | --- | --- |
| 자동 웹 검색 토글 | `Vc` 정의는 있지만 React 호출 지점이 없음. Chat은 `allowWebSearch` 값을 읽지만 UI에서 설정하는 지점을 찾지 못함 | 자동 검색 방식은 미정. 수동 웹 자료 검색과 구분 |
| 전송 전 컨텍스트 미리보기 | 모의 `context-preview` 경로는 있으나 실제 호출 지점을 찾지 못함 | 미리보기 화면을 구현된 것으로 기록하지 않음 |
| 과거 형식 오류 응답 | `format_issue`일 때 원문 보존·질문 다시 준비 UI가 있음. 기본 샘플에서는 나타나지 않음 | 조건부 복구 기능으로 추적, 실제 시연은 미실행 |
| 과거 삭제 항목 정리·복원 | Chat trash 경로와 프로젝트/대화 복원 UI가 있으나 모의 trash 조회는 빈 배열 | 삭제·복원 정책은 실제 백엔드와 별도 합의 |
| 필드별 AI 도움·기획 수정 비교 | `Kr`, `z0`, `U0` 등 옛 편집 구조가 남아 있음 | PLAN 단계의 복구 근거로 쓰지 않음. 새 제안 편집 요구는 Figma를 기준으로 작성 |

## 숫자·문구를 계약으로 옮길 때의 주의점

- Chat 입력 8,000자, 파일 2개·각 2MB, 선택 웹 자료 최대 3개는 이 데모의 코드·안내 값입니다. 제품 제한값으로 합의된 것은 아닙니다.
- 컨텍스트 안내에는 최근 대화 10개·24,000자가 남아 있고, 모의 미리보기 계산에는 메시지 20개가 사용됩니다. 실제 모델 입력 계약은 새로 정해야 합니다.
- 모의 작업 지연과 조회 주기, 세션 TTL·유료 시도 한도 필드, 샘플 가격·수수료는 운영 기본값의 근거가 아닙니다.
- 모델 목록과 API 키 발급 안내는 화면 분석 대상입니다. 실제 모델의 현행 제공 여부·요금·발급 절차를 검증한 자료가 아닙니다.
